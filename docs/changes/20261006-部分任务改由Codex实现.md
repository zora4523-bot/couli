## 2. 决定内容

| 任务 | 内容 | 选它的理由 |
| --- | --- | --- |
| B3-02 | Agent 模型接入层：主备路由、超时熔断、无模型降级 | 接口标准、边界清楚，可用录制回放测 |

| B3-07 | 素材结构化、黑话词典、未知权益提示 | 纯函数与词表为主 |
| B1-14（含 QA-06） | 外部依赖熔断与降级表、k6 压测脚本 | 脚本与配置为主，不碰业务数据 |
| QA-05 | 故障注入 | 测试工具，独立目录 |
| QA-09 | 发布制品密钥扫描 | 流水线脚本，独立 |

- 这几项的主实现改为 Codex（经 `tools/agent/codex-run.sh impl`），沙箱里只做类型检查与 lint；规则 / 验收测试改由 Claude 子代理在实现前先写、先红；对抗评审由 Claude 新子代理（与写测试的不是同一会话）；测试由编排者在隔离容器或 CI 里跑。
- 这几条线另行并行，不占 规划/11 §3.4「在途不超过 4 个」的名额；`paths` 不相交、契约与迁移串行的规定照旧。

## 3. 不在此列（维持 第 12 项：Opus 实现、Codex 写测试与评审）

- 资金（B2）、归属与订单（B1-08～11 等）：实现方与测试作者须分属两家，已按 Opus 实现、Codex 测试安排，对调要重写测试。
- 三端（APP、HM）：Codex 沙箱没有 Xcode 与鸿蒙工具链，无法构建与运行。
- 迁移与契约（CT）：全局串行，并行不加快。
- H5 与后台页面：按「先设计再开发前端」，等对应高保真稿定稿。
- 依赖尚未合并的任务：前置合并后再按本表的判断方式选。

## 4. 风险与提醒

- 合并前的容器验证与合并队列仍是串行，多开实现线不会按比例加快合并。
- Codex 在沙箱里不执行测试，第一次跑测试在编排者的容器或 CI 里，问题会晚一步暴露；按 11 §2.5 的轮次与熔断处理。
