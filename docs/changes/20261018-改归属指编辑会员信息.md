# 2026-10-18 后台「改归属」指编辑会员信息

**来源**：负责人 2026-10-18 在对话中确认：「管理后台的『改归属』功能指的是管理员可以对会员的信息有编辑权限，不管是手机号码字段还是金额等等信息。不是改给另外一个用户。理论管理员可以修改任何东西，我感觉有些规则显得很多余。」

**起因**：拍板第二批 §8 ADD-05（资金操作一人可完成）原文只列打款、人工调账、补差、坏账核销、间推开关等；规划在写回时把后台「改归属」推成「已归属订单改归属给另一个用户」（08 BR-ATTR-20「已归属订单改归属（前稿 O12）」、BR-FUND-01 R14 改派与 REASSIGN_REV / REASSIGN_CREDIT 红冲重记、BR-FUND-10 负余额例外、BR-FUND-15 等），2026-10-18 记账模板待定项又为它登记了「改派时旧受益人注销中 / 已注销怎么记」（06_FUND §6.3 第 23 项）。负责人确认这不是他的意思。

**类别**：00 §8 第 ② 类（改变已确认决定与订单归属边界）；负责人在对话中明确确认，按 §8 直接回写并注明日期。

## 内容

1. 后台不提供把已归属订单（user_id 非空，不论是否锁定、不论 rebate_status）改给其他用户。BR-ATTR-20 去掉这一支，标题改为「找回通过、未归因订单指派与锁定」。
2. 保留不变：找回通过（客服审核）与未归因订单的管理员指派，二者都只对 user_id 为空的订单；同一把锁、并发复查与 20902、写后锁定、封禁目标拒绝 / 冻结目标可以、VOID 的未归因订单只写归属（R3b）、锁定后找回返回 30204。
3. 后台 `orders/{id}/reassign` 只接受 user_id 为空的订单；重读到 user_id 非空返回 20902（`data.resource=order_attribution`，现有码，不新增）。2026-10-06 定的「已归属的 VOID / CLAWED_BACK 订单不得改派、返回 20902 order」被本条涵盖，统一在复查一步按 order_attribution 拒绝（错误码属代理可自定，00 §9）。
4. BR-FUND-01 R14 标为「不开放」：编号、迁移表行内原文与细则「R14 的凭证键」「R14 的分录类型」保留作记录，不删除、不复用；REASSIGN_REV、REASSIGN_CREDIT、`:REASSIGN:` 没收键、改派入账义务（`beneficiary_credits.kind=reassign_credit`）当前不产生。BR-FUND-04 ⑫、05、08、10、15、19、25 与 BR-CALC-13 提到它们的地方各加一句「当前不产生」，数值与公式不改。
5. 06_FUND §6.3 第 23 项改为已撤销：R14 不开放，问题不再存在。
6. 不动：编辑会员信息（手机号、昵称；01 F-ADM-04、BR-ID-06 细则、权限点 `user.phone_change`）与人工调账（ADMIN_ADJUST；01 F-ADM-08、BR-FUND-24、权限点 `fund.adjust`）的口径；任何金额、分佣比例与其他归属规则。BR-ATTR-20 细则只加一句：后台「改归属」按负责人 2026-10-18 解释为这两项。
