## 1. 提现单「预计到账」与「实际到账」

**内容**：提现记录与详情里的到账金额（net_fen），审核中、打款中（PENDING_REVIEW、APPROVED、PAYING）的单标「预计到账」，已到账（PAID_API、PAID_MANUAL）的单才标「实际到账」。原写法「提现记录中逐单展示「实际到账 {net}」」不分状态，钱还没到时容易被误读为已到账。未通过、打款未成功的单不在本条范围。

**涉及 BR**：BR-TEXT-01（术语表「实际到账」行、钱包汇总口径、细则「取代」）；BR-TEXT-14 表 C 新增 `withdraw_detail.net.expected` / `withdraw_detail.net.actual`；BR-TEXT-12 细则「资金术语键」不用改（两个键落在已列的 `withdraw_detail.` 前缀内）。BR-TEXT-06、BR-WDR-25 不变。08 README §1.2「实际到账」行同步。

**受影响的页面与接口**：`WithdrawRecords`（列表与详情）；`GET /v1/withdrawals`、`GET /v1/withdrawals/{id}` 形状不变（net_fen 照旧）。

**代码仓库待跟进**（本仓库只改规划，不碰 `rebate-platform`）：`contracts/texts.default.json` 新增 `withdraw_detail.net.expected`（预计到账 {net}）与 `withdraw_detail.net.actual`（实际到账 {net}），若已有单一的到账金额键则换成这两个；`specs/fund-term-keys.yaml` 核对这两个键落在「资金术语」段的 `withdraw_detail.` 前缀下（按 BR-TEXT-12 细则，前缀已列则不用改文件）。

**验收**：审核中、打款中的单在列表和详情都显示「预计到账 ¥x」，已到账的单显示「实际到账 ¥x」；这两个键归资金术语，改措辞需要 `content.fund_terms` 权限（BR-TEXT-12 细则）。

**恢复方式**：改回不分状态时，在 BR-TEXT-01 删去这一区分，客户端统一用 `withdraw_detail.net.actual`。

## 2. 申诉与说明页不显示处理时限

**内容**：申诉提交页、申诉进度（含处理中）与封禁 / 冻结说明页不显示申诉的处理时限或截止时刻，只说明会尽快处理、结果通过站内消息（APPEAL_RESULT）通知。内部时限不变：BR-ID-36 的第 3 个工作日结案与 `appeals.deadline_at` 仍用于超时告警。冻结到期时间（frozen_until）不是处理时限，冻结说明页照常显示。

**涉及 BR**：BR-TEXT-23 细则（新增一项，用户侧写法的唯一维护处）；BR-ID-36 细则（加一句指针）。

**受影响的页面与接口**：`Appeal`、`RiskNotice`（01 §4.2 两行已加摘要）；申诉接口形状不变。

**验收**：三个页面上找不到「x 个工作日」「x 日前」一类的处理时限文字；内部超时告警照旧触发。AC-S1-60 不变。

**恢复方式**：要对用户写时限时，另作决定，在 BR-TEXT-23 细则改回并加文案键。

## 3. Apple 登录按钮用官方样式

**内容**：登录页的 Apple 按钮用系统提供的官方按钮（UIKit `ASAuthorizationAppleIDButton` 或 SwiftUI `SignInWithAppleButton`，带 Apple 标志），作为设计稿「界面不出现平台标志」约定的例外，只限这一个按钮。

**涉及 BR**：无（不是业务规则）。「界面不出现平台标志」是设计任务书的约定，规划里没有对应条目；规划里与商标有关的是 01 F-PRIV-08（App 图标、名称、启动页不含平台商标）与 `design/README.md`（素材不含淘宝等电商平台商标），两处都不涉及 Apple，不改。

**落点**：03 §3.5 SDK 清单的 Sign in with Apple 行（实现方案）。

**受影响的页面**：`Login`（iOS）。

**验收**：iOS 登录页的 Apple 按钮是系统按钮，其余位置（微信等）仍不出现平台标志。

**恢复方式**：撤去 03 该行的说明，按钮改回自绘样式（须先确认商店审核允许）。

## 4. 冻结时钱包提示点进 RiskNotice 冻结态

**内容**：账户被风控冻结（risk_state=frozen）时，钱包顶部的「提现已暂停」提示可以点击，进入 `RiskNotice` 的冻结态说明页（原因类别、有到期时间时的到期时间、申诉入口）；封禁态与冻结态是同一页的两种状态。统一了 01 §4.2 `RiskNotice` 行、F-RISK-04 与 BR-TEXT-23 细则此前不一致的说法。提现冻结记录（BR-WDR-05）等其他原因的提现暂停提示不在本条范围，按现行写法。

**涉及 BR**：BR-TEXT-23 细则（「冻结只影响提现」一句之后补入口）。

**受影响的页面**：`Wallet`、`RiskNotice`（01 §4.2 `RiskNotice` 行、F-RISK-04 已改）。

**验收**：冻结用户点钱包「提现已暂停」进入冻结态说明页，有返回；页面按 GET /v1/me 的 risk 字段显示原因类别与到期时间（AC-S1-60 ① 的 a 用户）。

**恢复方式**：在 BR-TEXT-23 细则删去该入口，钱包提示改回不可点。

**涉及 BR**：BR-TEXT-14 表 A 10404（不变）。

**落点**：无需改规划，只在本记录写明。

## 7. 注销页余额为负进页即提示

**内容**：进入注销页时按钱包汇总的 negative_fen（BR-FUND-18）判断，余额已为负就直接显示 30416 的同一句提示（「账户有待扣回金额 {amount}，抵扣回正后才能注销」）与【联系客服】，申请按钮置灰；用户点申请时服务端仍返回 30416 兜底（如进页后余额才变负、客户端数据过时）。

**涉及 BR**：BR-ID-27 细则（新增一项）；BR-TEXT-14 表 A 30416 行（加进页显示一句）。BR-ID-27 正文与 30416 的服务端行为不变。

**受影响的页面与接口**：`DeleteAccount`（01 §4.2 已改）；`GET /v1/wallet/summary`（已有字段）、`POST /v1/me/deletion`（不变）。

**验收**：余额为负的用户进注销页即看到提示与【联系客服】、申请按钮置灰；绕过客户端直接调申请接口仍得 30416、不进入冷静期。

**恢复方式**：删去 BR-ID-27 细则这一项，回到只在点申请后提示。

## 8. 分享中间页的按钮主次

**内容**：商品分享中间页（App 外的浏览器内）【复制淘口令】为主按钮、【在 App 中打开】为次按钮。

**涉及 BR**：BR-TEXT-14 表 C `share_page.copy_tpwd`、`share_page.open_in_app` 两行。BR-ATTR-05、BR-ATTR-10 不变。

**受影响的页面**：分享中间页（H5，M-公开）；01 F-SHARE-07 加指针。

**待补（不自拟）**：京东、拼多多在中间页上的购买按钮（按钮名、文案键、与【在 App 中打开】的主次）规划仍未写；12 §2.8 已按短链画了「去购买」，但 08 与 01、03 没有对应规则。按 12 §9 的现有做法登记为 **12 §9.3 L-16**（类别：同步），由负责分享任务的代理补到 BR-TEXT-14 表 C 并经评审；12 §9 合计随之改为 114 条。

**验收**：浏览器里两个按钮同时出现时，【复制淘口令】是主按钮。

**恢复方式**：改表 C 两行的主次说明。

## 10. 内测包不显示注销入口

**内容**：注销属 M-公开（00 §4）。M-内测阶段分发的内测包，设置页「账号与安全」里不显示「注销账号」；公开版显示。

**涉及 BR**：BR-ID-27 细则（新增一项）。BR-ID-27 的注销入口路径与阶段不变；08 §10.3 第 2 项（TestFlight 外部测试是否需要注销）仍未决，本条不关闭它。

**受影响的页面**：`Settings`（01 §4.2 已改）。

**说明**：本条只管设置页的入口。强更页、封禁说明页上的「注销账号」入口（BR-ID-27 细则「强更状态下的入口」、BR-ID-31 白名单）内测期怎么显示，本次没有决定，规划不改。

**验收**：内测包的设置页没有「注销账号」，公开版有。

**恢复方式**：删去 BR-ID-27 细则这一项，内测包同样显示入口（需要注销接口在内测期可用）。
