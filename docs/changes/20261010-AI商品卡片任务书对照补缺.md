## 2. 补进规划的条目

1. **seq 缺号**不再静默丢弃，视为流不完整，本地结束并由历史接口拉回（03 §7.2）。
2. 断线重试只由用户触发、后台不重试、历史接口退避与 5 次上限（03 §7.2）。
3. 帧解码：UTF-8 跨块、一块多帧、单帧 64 KiB 上限、外壳缺字段按协议错误（03 §7.2）。
4. 同一张卡只有一个进行中的购买操作，连点与 H5 同 link 调用互斥，桥码 90409（代理默认）（03 §4.5）。
5. 启动结果三值 `requested / failed / unknown`，unknown 不自动再跳、不等于成交（03 §4.5）。
6. 授权期间离开发起页、切号、超时不恢复外跳；晚到回调不复活操作（03 §4.5）。
7. 外跳前再查一次本地最新开关（03 §4.5）。
8. 桥调用 `request_id` 去重，同参复用、异参 90002 `request_id_conflict`，L2 方法 90003 后不自动重发（03 §5.3）。
9. 页面会话编号：导航后旧回调作废、权限失效，结果只回给发起页面（03 §5.3）。
10. 埋点 `event_id` 落盘、重试不换、服务端去重；被互斥拒绝的点击只记诊断（03 §6.2）。
11. `app_return` 只是观测；看板不得用外跳次数代替成交；无权威订单不产生 paid 类事件（03 §6.2）。
12. 终止帧之后不再有内容帧，晚到的工具 / 模型结果丢弃不计费（02 §9.2）。
13. `stream.` 子域反代关闭缓冲与压缩、每帧 flush、联调抓包核对分批到达（02 §9.2 新行「流的传输」，验收挂 B1-32）。
14. LKG 过期时限与包内保守默认：购买、转链、Agent 入口按关闭处理，只读照常（02 §10）。
15. Agent 流性能基线：最低档真机、200 条历史 / 50 张卡、每秒 20 帧 60 秒、P95 阈值、首帧 / 首文本 / 首卡记录方式（10 AC-S1-179）。
16. 验收用例 AC-S1-174～178 覆盖任务书 V03、V06、V09、V14、V15、V18 中 couli 原来没有的子项（10 §2.7）。

代理默认（负责人可改）：90409 桥码、`config.lkg_max_age_sec` 7 天、64 KiB 单帧上限、性能阈值 P95 100 / 200 毫秒沿用任务书数值。错误码 90409 按 08 §13.11 的流程登记后才可实现。

## 3. 不采纳或后置（写明理由）

| 任务书条目 | 处理 | 理由 |
| --- | --- | --- |
| §4.3–4.4 事件持久化、`afterSeq` 续读、410 `REPLAY_EXPIRED`、原子快照接口、客户端 reducer 状态与游标原子落盘、24 小时重放窗口 | **P1 候选**，MVP 不做 | 02 §9.2 已定「MVP 不做事件续传，断线后用历史接口拉回完整回复」（不建 `agent_events`）；单轮时限短、回复体量小，拉回整条回复代价低。P1 立项时按任务书 §4.4 的规则整体引入，届时再加 `snapshot_seq` 与 `afterSeq` |
| §5.1 块模型：`block.upsert` 全量快照、`revision`、`placeholder` 原位变卡、`position` 交错、每条回复 30 块 / 20000 字上限 | 不采纳 | couli 用 `tool.status` 表示检索中、卡片只追加不改（出卡前已完成核对与 Jev 降级，02 §9.2），没有原位更新的需求；文本上限由单轮时限与 BR-AI-14 控制。若 P1 要做「卡片随报价刷新」再引入 revision |
