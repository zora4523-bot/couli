## 1. 决定内容

1. 新增只读模型工具 `get_my_earnings`：返回可提现余额、预估收益、预计结算月份、最近一笔提现的进度。
2. 数据来源：与 App 钱包页、收益看板、提现记录调同一个查询函数（`GET /v1/wallet/summary`、`GET /v1/earnings/summary`、`GET /v1/withdrawals` 背后的服务函数），Agent 不另算。
3. 模型只看到「已出一张收益卡」（卡片引用与状态），看不到任何金额；用户看到收益卡，金额由服务端填，带「去钱包」按钮（复用页面引导卡的 in_app 打开机制，目标 Wallet / WithdrawRecords，不带参数）。
4. 只限已登录且已绑手机的本人（与订单类工具同一主体过滤）；游客与未绑手机出 `auth_required`。
5. 提现、改收款账号、调账等任何写操作仍是 C 级，不放开。
6. 进 MVP，排在钱包接口做完之后（05 §0.1 第 5 段 B2 主线），之前由页面引导卡顶着。
7. 修改「管得过宽」的规则：BR-AI-02 ③ 只允许 import 上述接口所用的具名只读查询函数（按函数名逐个列入允许清单），这些模块的其他导出与所有写服务仍禁止；denylist 正则不放宽，写清扫描对象。

## 2. 不变的部分

1. BR-AI-01 C 级清单不变：提现、余额或分录写入、收款账号增改、调账仍禁止；卡上没有任何操作按钮。
2. BR-AI-02 ① allowlist 精确比对、② denylist 正则不变；③ 对 growth、commission 的禁令不变，对 ledger、settlement、payout 只放开登记的只读查询函数。
3. BR-AI-03（身份注入、`additionalProperties=false`）、BR-AI-05（模型看不到数字）、BR-AI-06（金额只在卡片里）都不变，新工具照此执行。
4. 钱包、提现、收益看板的口径（BR-FUND-18、BR-FUND-25、BR-TEXT-01、BR-TEXT-06）不变，Agent 只复用。
5. 页面引导卡（D31）的 6 个目标页、`agent_guide` 候选集与「不读数据」的约束不变；收益卡的两个按钮复用它的打开机制。
6. 不新增 BR 编号、错误码与第三方依赖；BR-AI-21 门槛不变。
