# 凑狸接入 TypeSafe Jev 的规划

## 1. 结论

**Jev 是什么**：TypeSafe 提供的一种"判断模型"。它不写字、不聊天、不写代码。你给它一段文字，再给它几个定好选项的问题，它只回答三种结果：从几个选项里选一个、按等级打分、给出"是"的概率。选一个和打分两种结果还会附带一个"把握度"数值。

**能不能高效率地做选择？** 要分两类看：

| 类型 | 例子 | Jev 行不行 |
|---|---|---|
| App 运行时的自动小判断 | 这件商品是不是纯牛奶；这句运营文案有没有变相说"全网最低" | 适合。一次请求可以同时问多个问题，文档称约 0.1–0.15 秒。价格约每百万字 0.042 美元，只按输入计费 |
| 负责人的业务决定 | 返利比例、要不要接某个平台、推广标识怎么写 | 不适合。Jev 不给理由，也不承担责任，仍由你来定 |

**"安装"的含义**：Jev 不能装进 Claude Code 替换编码模型，文档原话是 "not a drop-in replacement"。真正的接入点是将来后端 `rebate-platform/apps/api` 里的一个服务端调用模块。这个仓库现在还没建，所以现阶段只能做本地试验和评测，没有可以"安装"的地方。

**在凑狸里能帮什么**：商品是否符合条件的核对、评测打分、文案语义检查、同款打分。

**不能帮什么**：金额、返利、订单归属、状态变化、日期计算。这些全部由代码负责，Jev 的结果不参与。

## 4. 不建议用的地方

- **金额、价格比较、"再便宜点"、返利、佣金、提现**：文档说明 Jev 的数学和计数不可靠。
- **订单归属、找回审核、状态机、打款结论**：这些是精确规则，涉及资金后果，而 Jev 的判断无法向用户解释。
- **日期换算**（例如"昨天买的"）：日期比较是 Jev 的已知弱项。
- **用户聊天的入口分流、条件抽取、多轮指代、素材解析、剪贴板识别**：会把用户原文发到境外，而且代码词表加千问已经能覆盖。
- **客服自动回复、举报分诊、申诉分诊、恶意维权标签**：数据是用户自由文本；量小；另外，对用户不利的标签无法解释依据。
- **平台状态码映射**：量很小，人工查一次文档即可。
- **法定内容安全审核、禁用词硬拦截、推广标识**：属于法定或需确定可审计的义务，不能交给概率判断。
- **图片识别**：Jev 只接受文字输入。
- **每张卡单独发一次请求**：会很快触发限流。

## 5. 接入方式

- **位置**：`apps/api` 里新建一个独立的"判断适配模块"，和千问一样走外部依赖治理层（02 §原则 4）。通过依赖检查禁止账务、分佣、结算、打款、归因、转链模块引用它。
- **SDK**：`npm install @typesafe-ai/sdk`（要求 Node ≥20，文档链接的版本是 v0.6.0）。离线脚本也可以用 Python：`pip install typesafe-sdk`（要求 Python ≥3.10）。
- **给编码代理的插件（可选）**：`claude plugin marketplace add typesafe-ai/skills` 之后执行 `claude plugin install typesafe@typesafe-ai`。它只是帮代理写集成代码，本身不是模型。
- **超时与降级**：在线调用硬超时 400ms，每轮最多合并成 1 次请求；失败时回到纯规则。
- **开关**：`jev.enabled`、`agent.result_check.provider`（取值 off / rules / qwen / jev），默认都是关闭或 rules。
- **版本**：锁定 `jev-1.13.0`，不用 `jev-latest`；把响应里的 model 字段写进 trace；录下 Jev 的响应，纳入回放测试。
- **与千问的分工**：千问负责理解用户和生成说明文字，Jev 只在出卡前对公开商品数据做核对。两者不替代，Jev 也不进入 `agent.model_route`。

## 8. API Key 保管

- **不要在对话里发 Key**，也不要写进这个公开仓库的任何文件或示例。
- 本机放在环境变量 `TYPESAFE_API_KEY` 里（写在 `~/.zshrc` 或钥匙串中）。以后 CI 用 secret，服务器用 KMS，和千问 Key 的保管方式一样，每 180 天轮换一次。
- 只在服务端调用，不开启 `dangerouslyAllowBrowser`，生产环境关闭 debug 日志（debug 日志不会对请求体脱敏）。
- 在控制台设置用量上限。
- 注意：`.githooks` 目录目前不存在，gitleaks 实际没有在运行，建议在放入任何脚本之前先补上。

## 9. 需要你拍板的问题

1. **是否同意把 TypeSafe 登记为新供应商，只处理不含个人信息的数据？** 建议同意，写一条 docs/changes 记录。
2. **用户的聊天原文是否发给 Jev？** 建议 MVP 阶段不发，这样不用修改 AI 同意书，也不涉及出境评估。
3. **卡片核对的对外措辞**：建议只用"标题显示为 X"和"规格待确认"，不用"符合你的要求"。
4. **W3 决定点的规则**：建议中文达不到验收线就关闭 ③，Agent 按原计划上线。
5. **付款与额度**：建议先设月度上限 20 美元；发票和境外付款请财务确认。
6. **插件什么时候装**：建议等 `rebate-platform` 建库时，在那个仓库里装 SDK 和插件；在当前规划仓库里装没有意义。
