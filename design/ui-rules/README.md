# 凑狸 · 界面与交互规则（总则）

2026-11-07 · 状态：生效 · 依据：规划/00 D37（三端功能一致、界面优先用平台原生组件）、D35（深色跟随系统）、规划/03 §10–§11 · 维护：编排会话

这份文档写给三端（iOS、Android、鸿蒙）的开发代理与评审者：**做任何界面改动前先读本总则，再读本端细则**——[iOS](ios.md)、[Android](android.md)、[鸿蒙](harmony.md)。H5 与管理后台不在本文范围，仍按 03 §8–§9。

每条规则给「要 / 不要」，都能在代码或录屏里验收。平台 API 的确切写法以各平台官方文档为准；细则里标「以官方文档为准」的条目，实现前先查官方文档再写。

---

## 0. 为什么有这份文档

负责人 2026-11-07 定了两件事：

1. 三端**功能一致、界面不求一致**（00 D37）。iOS 底栏用系统 TabBar，iOS 26 起是 Liquid Glass 悬浮样式；自绘底栏会失去这些系统能力。
2. 问「先做组件库——按钮、卡片、商品 Cell、价格标签、骨架屏、空状态——组件做到满意再拼页面，会不会更好」，并要求从全局把规范写成规则文件，提升**交互手感**与**页面质感**。

同日编排对三端代码做了只读审计（iOS `93c3662`、Android `c8eac4a`、鸿蒙 `a819d7a`），结论一致：

| 端 | 系统组件用在哪里 | 自绘了什么（系统本来就有） | 手感 |
| --- | --- | --- | --- |
| iOS | 输入框、开关、转圈、下拉刷新、2 个系统半屏、「我的」下 5 个二级页的导航栏 | 底栏、导航栏（20 个页面藏了系统返回键）、弹窗 19 处、半屏 9 处、轻提示 19 处、分段、列表行；List / Form / Menu / Picker / searchable / confirmationDialog 全为 0 | 触感 0；整卡点击按下无反馈；动画极少；正式包锁浅色 |
| Android | 对话框窗口、底部半屏、导航框架、下拉刷新、水波纹 | 底栏、按钮（Box 重画，页面调用 99 处）、输入框外框、圆形勾选、轻提示（非 Snackbar）、自写顶栏 6 处；Scaffold / Snackbar / NavigationBar / AlertDialog 使用 0 | 触感 0；`androidx.compose.animation` 导入 0；返回常开 BackHandler、无预测性返回 |
| 鸿蒙 | 根 Navigation、Tabs、Refresh、13 处 bindSheet、Toast | 标题栏（22 个 NavDestination 里 21 个隐藏系统标题栏）、弹窗 22 处、购买流程自画遮罩与假半屏、开关、分段、列表行 | 触感 0；animateTo / transition 0；按压态 stateStyles 0；多页关闭回弹（EdgeEffect.None） |

根因不是某个页面写得差，而是**规则把方向定反了**：私有运行目录的组件清单（component-inventory §2）把按钮、输入框外框、勾选、筛选胶囊、顶部标签、列表行列为「必须三端一致」；Android 的 G1 守卫要求页面不得直接用系统控件、只能用组件库；视觉验收按设计稿像素比对。组件规范 v1.0（COMP-SPEC）至今「待排」，组件库与页面是同时写出来的。D37 把这几处一起改正，本文是改正后的统一依据。

## 1. 原则

| # | 要 | 不要 |
| --- | --- | --- |
| P1 | 同一功能三端提供**相同的信息、操作、业务规则、文案键与金额口径**（08 管取值，契约管形状） | 为了三端长得一样，把系统控件换成自绘 |
| P2 | 系统已有的控件**一律用平台原生组件**：iOS 按 Apple 人机界面指南（HIG）与 SwiftUI / UIKit 系统控件，Android 按 Material 3，鸿蒙按 ArkUI 系统组件与 HarmonyOS 设计规范 | 在系统控件外面再包一层自己的外观（重画边框、背景、按压、动画） |
| P3 | 品牌**只经主题接入**：iOS `tint` / AccentColor，Android `MaterialTheme`（色彩、字体、形状），鸿蒙 `CustomTheme` / `WithTheme`；数值取自令牌唯一源 `design/tokens/design-tokens.json` | 页面里写色值、字号、圆角、阴影常量；为了品牌色覆盖系统栏的材质与层级 |
| P4 | **业务组件只建系统没有的**（商品卡、价格与返利标签、金额格、钱包主卡、平台标识、商品图、骨架、空态 / 错误态等），建在组件库里、进组件目录页 | 在页面里私写同类件；同一种东西两套外观 |
| P5 | 验收看**功能与信息一致、遵循本平台规范**；截图快照是各端**自己的回归基线** | 跨端比截图；把设计稿当像素标准（D37） |

## 2. 三层结构

页面只许由下面三层组成。新页面、翻新页面都照此检查。

### L1 系统控件（只配主题，不改外观）

底栏、顶栏 / 导航栏、返回、半屏、弹窗、操作菜单、轻提示、列表行与分组、开关、勾选、单选、分段、搜索、菜单、下拉刷新、侧滑操作、长按菜单、输入框、日期与选择器、转圈。各端用哪个系统组件见细则的对照表。

- 要：直接用系统组件，经主题给品牌色；需要统一参数（例如半屏的高度档位）时写一个**只传参数**的薄封装。
- 不要：薄封装里重画外观、改按压反馈、关掉系统动画或读屏行为。

### L2 业务组件（负责人点名先做的，加上同类）

| 组件 | 要点（详细规格进组件规范 COMP-SPEC，规则见 §3–§4） |
| --- | --- |
| 按钮样式 | 基于系统 Button 的品牌样式（主 / 次 / 文字 / 图标；尺寸档位；内含加载态）。按压、禁用、焦点用系统按钮的状态机制。不用 Box / Row / Column 加点击重画 |
| 卡片 | 平台卡片 / 分组列表样式加令牌圆角与层级；整卡可点时用系统按钮或可点击行承载，按下有反馈 |
| 商品 Cell（商品卡） | 横向 / 网格 / 大卡三种布局（03 §10.2 `ProductCard`）；整卡按压反馈；商品图走「商品图」组件；价格与返利走标签组件 |
| 价格 / 返利标签 | 03 §10.2 `PriceTag`、`RebateTag`；金额格式化按 08 BR-TEXT-10、BR-PRICE；金额变化用数字过渡（§3.3） |
| 骨架屏 | 形状贴近真实内容；**带微光**；加载超过约 300 ms 才出现，出现后至少显示约 300 ms 防闪；减弱动态时不播微光 |
| 空状态 / 错误状态 | 文案取 08 BR-TEXT-14 表 C 通用状态键（`state.*`、`net.*`）；错误态有【重试】；系统有现成空态组件的端优先用系统的（细则说明） |
| 金额格、钱包主卡、平台标识、商品图 | 03 §10.2 `AmountGrid`、`WalletHeroCard`、`PlatformBadge`；商品图 = 占位 + 渐显 + 缓存 + 失败态（§3.6） |

### L3 页面模板

列表页、详情页、表单页、设置页四类模板，各端用**系统脚手架**搭（iOS NavigationStack + List / Form；Android Scaffold + TopAppBar + LazyColumn；鸿蒙 Navigation / NavDestination + List）。模板定下顶栏、滚动、加载 / 空 / 错误态、底部操作区、键盘处理的统一写法，页面只填内容。

## 3. 交互手感规则

### 3.1 按压反馈

- 要：**所有可点区域按下都有反馈**，用平台默认的高亮、涟漪或轻微缩放（按钮用系统按钮自带的按压态；整卡、列表行用系统可点击行或按钮样式承载）。
- 不要：iOS 用 `onTapGesture` 做整卡点击；Android 写 `indication = null` 或用 `clickable` 却无可见反馈；鸿蒙在 Row / Column 上挂 `onClick` 却没有 `stateStyles` 或按压效果。
- 验收：录屏里每个可点元素按住时可见变化；守卫拦「无反馈的可点」写法（细则列规则）。

### 3.2 触感反馈

只在用户需要确认「发生了」的时刻给触感，频率克制；系统控件自带触感的（如系统开关、系统长按菜单、系统选择器）不另加。

| 时刻 | 触感类型 | 例子 |
| --- | --- | --- |
| 选择变化 | 选择（最轻） | 分段切换、筛选胶囊、选择器滚到新值 |
| 操作成功 | 成功 | 复制成功、收藏、提现提交成功、绑定成功 |
| 被拦或失败 | 警告 / 失败 | 校验失败阻断提交、提现被拒、需要先登录的拦截 |
| 达到阈值 | 轻撞击 | 下拉刷新越过触发点（系统刷新控件自带时不加）、长按出菜单（系统菜单自带时不加） |

- 要：经组件库里**一个统一入口**调用（细则给各端 API），尊重系统的触感开关。
- 不要：滚动、列表加载、每次点击都震；购买外跳时加触感。

### 3.3 动效

- 要：**状态切换不硬切**——内容出现 / 消失、加载到内容、展开收起、选中态变化、Tab 内容切换都用平台默认曲线做过渡；时长：微交互约 100–200 ms，元素进出约 200–300 ms，页面转场用系统默认；金额与数字变化用数字过渡；**尊重「减弱动态效果」**：开启时位移、缩放改为淡入淡出，微光停播。
- 不要：自定义超过约 400 ms 的装饰动效；关掉系统转场（如 Tab 切换时长设 0、内容靠可见性硬切）。
- Web（H5 与管理后台）的具体时长与曲线取令牌 `motion.*`（v0.5.2，CSS 变量 `--motion-*`），用法见 `规划/03_前端架构.md` §10.6；原生三端用平台默认、不读这些数（D37）。

### 3.4 导航与返回

- 要：**系统返回手势永远可用**——iOS 边缘右滑返回、Android 系统返回与预测性返回、鸿蒙系统返回手势。登录、购买确认、协议这类「中途流程」用模态呈现（左上关闭）；层级下钻用压栈（左上返回）。
- 不要：iOS 隐藏系统返回键而不保留侧滑（隐藏返回键会连侧滑一起关）；Android 常开 BackHandler 抢走系统返回预览；用压栈呈现的页面放「关闭 ×」。
- 底栏在二级页是否保留按平台规范：iOS 按 HIG 在 Tab 内的层级导航中保留标签栏（细则：每个 Tab 自己的导航栈，迁移时评估）；Android、鸿蒙按各自规范，细则写明。

### 3.5 滚动

- 要：保留平台的**回弹 / 越界效果**；**再点当前 Tab 回到顶部**（已在顶部则回到该 Tab 根页面）；返回上一页、切回 Tab 时**保留滚动位置**；顶栏随滚动的平台行为（iOS 大标题收起与系统栏材质、Android TopAppBar 滚动行为、鸿蒙标题栏随滚动）用系统能力实现。
- 不要：关闭回弹（鸿蒙 `EdgeEffect.None`）；大面积关滚动条；把长列表写成「滚动容器 + 普通列」而不用系统列表的复用。

### 3.6 加载、刷新、图片

- 要：首屏用**骨架**而不是整页转圈；下拉刷新**等数据回来再收起**；提交类按钮用**按钮内加载态并防连点**；图片有**占位 + 渐显 + 缓存 + 失败态**；结果未知的写操作按 08 与契约的重试规则给轻提示。
- 不要：转圈立即收回；图片从占位硬切；没有缓存的图片列表。

### 3.7 键盘与输入

- 要：滚动时收起键盘；数字键盘有「完成」；回车切到下一个输入框；输入框不被键盘遮住；验证码与手机号用系统的自动填充 / 输入类型。
- 不要：自画输入框外框却丢掉系统的光标、选择、粘贴菜单与读屏行为。

### 3.8 深色、大字、读屏

- 要：深色**跟随系统**（00 D35；iOS 去掉浅色锁，DSX-127）；大字按 03 §10.4；读屏按 03 §10.5。系统控件的大字、长按放大、读屏行为交给系统。
- 不要：为自绘件补一套读屏 / 大字逻辑去模仿系统控件——先换成系统控件。

## 4. 页面质感规则

| 方面 | 要 | 不要 |
| --- | --- | --- |
| 层级 | 每屏**一个主操作**；文字角色（标题 / 正文 / 辅助）按令牌字阶，Android 映射全部 M3 字体角色；信息按「主信息 → 次信息 → 操作」排列 | 同屏多个同等强度的主按钮；同一级标题在不同页字重不同 |
| 间距与留白 | 4 的倍数栅格；页面左右边距、卡片内边距、组件间距只取令牌 | 页面里写死宽高与边距常量 |
| 材质 | 系统栏（标签栏、导航栏、标题栏）**保持系统材质**，iOS 26 起是 Liquid Glass；浮层用系统材质 | 给系统栏设不透明背景色、垫实色条；自绘毛玻璃 |
| 阴影与圆角 | 只取令牌（`radius.*`、`shadow.*`）；Android 优先用 M3 色调层级表达层次 | 多套阴影、手写圆角 |
| 图标 | 通用控件图标用**系统符号库**（SF Symbols、Material Symbols、HarmonyOS Symbol），选中态用实心变体；凑狸自有图标走统一 SVG 源（DSX-06） | 用 Path 手画通用图标；同一含义两套图标 |
| 颜色 | 语义令牌；状态不只靠颜色表达 | 用透明度代替状态色 |

## 5. 组件先行：回答负责人的提议

**结论：是，先组件、后页面。** 现在的问题是组件规范没定稿就开始拼页面，页面里各写各的；先把组件做到满意、再拼页面，返工最少。做法分四步，业务开发（接口、数据、业务规则）不停，只是**界面层**按这个顺序走。

### 第 0 步：先解锁（把方向反了的规则改过来）

| 现有规则 | 改为 | 承接 |
| --- | --- | --- |
| 组件清单 §2「必须三端一致」（按钮、输入框外框、勾选、筛选胶囊、顶部标签、列表行外观） | 作废，按 D37：系统已有的用系统的，外观随平台 | 本文 |
| Android G1 守卫（feature 不得直接用 M3 系统控件） | 改为「**禁止自绘系统已有控件**」，系统控件可直接用；组件库冻结范围收窄到业务组件 | D10-827 ③⑤，FU-AND-G1-SYSTEM-CONTROLS |
| DSX 计划里 LINT-STYLE 的「系统控件直用」反例失败（含把 M3 Button 列入禁用）、DSX-60「G1 转为失败」 | 「禁写死样式」保留；「禁系统控件直用」改为「禁自绘系统控件」 | LINT-STYLE-ios / -android / -harmony、DSX-60 |
| 截图按设计稿比、跨端一致 | 快照只作各端自己的回归基线；DS-02 对系统组件只比功能、信息与平台规范 | D37、D10-827 ④ |
| 锁住现状的测试（iOS 视觉测试与测量探针、Android 源码契约测试与快照等） | 随组件迁移按批次改，系统控件不再测像素位置 | 各端细则 |

### 第 1 步：各端组件冲刺（L2）

- 每个 L2 组件在**组件目录页**做齐全部状态：默认 / 按下 / 禁用 / 加载 / 选中，浅色与深色，标准字号与最大字号；以及手感（按压、触感、动效）。
- 每批组件由开发线**录屏**（模拟器或真机，含按压与转场），编排发给负责人看；**负责人说满意才冻结**（进快照基线与组件规范）。不满意的按意见改，再录。
- 先做负责人点名的六类：按钮样式、卡片、商品 Cell、价格 / 返利标签、骨架屏、空状态 / 错误状态；再做金额格、钱包主卡、平台标识、商品图。

### 第 2 步：页面模板（L3）

列表页、详情页、表单页、设置页各一个模板，也进组件目录、录屏、负责人看过再用。

### 第 3 步：按流程分批翻新页面

顺序：**首页 → 搜索 → 商品详情 → 购买 → 订单 → 钱包 → 我的**。每批翻新完录一段走完该流程的视频给负责人。**新页面只能用组件目录里的件**；目录里没有的，先补组件、再写页面。

## 6. 完成定义（每个 UI 改动）

- [ ] 功能与信息与另两端一致（同一接口字段、文案键、金额口径、状态与错误处理）。
- [ ] 遵循本平台规范：系统已有的控件用系统的；没有自绘系统控件；品牌经主题接入。
- [ ] 用到的业务组件都在组件目录里；新件先进目录。
- [ ] 按压、触感、动效、返回、滚动、加载、键盘按 §3 通过。
- [ ] 浅色 / 深色、最大字号、读屏走查通过（03 §10.4–§10.5）。
- [ ] 关键交互有录屏（证据进任务约定的证据位置）。
- [ ] 快照基线为本端自己的回归基线，更新理由写进 PR。
- [ ] 不追三端或设计稿像素一致（D37）。
