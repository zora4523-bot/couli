# 2026-10-19 身份线三项裁定回写

00 §8 第 ① 类（实现方案与 08 内部冲突的对齐），编排裁定，不改已确认决定、金额口径与订单归属。

## 1. 幂等请求摘要带密钥（B1-01zzf，身份线 10-18 13:16 UTC 请求）
- 内容：BR-WDR-07「请求体哈希」对含个人敏感信息（姓名、证件号、银行卡号、收款账号）的幂等操作改用 HMAC-SHA256（FieldCrypto 盲索引密钥，记密钥版本）；其余操作仍为 sha256。
- 理由：无密钥 sha256 在库泄露时可被穷举还原证件号等低熵信息。只收紧，已有冻结测试针对的不含敏感信息的操作不受影响。
- 受影响：代码仓库 platform 幂等模块（台账 B1-01zzf，身份线起草）。

## 2. 封禁用户调 GET /v1/invites/me（B1-11j，身份线 10-18 18:14 UTC 请求）
- 冲突：BR-INV-18 例子写封禁 → 200（can_invite=false），BR-ID-31 写封禁用户除白名单外一律 10006。
- 裁定：以 BR-ID-31 为准（备选 B）——封禁用户进账号受限页，看不到邀请入口，结果与原例「不显示邀请码」一致；不为邀请接口另开白名单。BR-INV-18 三个例子改写并注明原文。
- 受影响：B1-11j 规则测试的封禁 / 无申诉单 appealing 情形改为断言 10006。

## 3. B1-11g 发码计数口径（身份线 10-18 15:41 UTC 请求）
- 编排 10-18 23:3x 换模型裁定误写为「同一用户同一自然日」；B1-11g 的额度实际来自 BR-ID-05 / BR-ID-32 的同 IP 小时窗口、同 IP 新注册数与手机号额度，落地页请求无登录用户。
- 裁定：采纳身份线理解——PG attempt 行键 (app_id, 幂等键)，带 ip_hmac、phone_hmac、created_at、状态；计数 = created_at ∈ [now − 3600 − 发送超时上限, now] 的行数，在途与失败在结果确定前计入；Redis 只做缓存。BR-ID-05 `sms.ip_sends_per_hour` 行补实现口径说明（只会更早触限）。阈值不变。
- 受影响：B1-11g 第 7 轮实现（Opus 高推理，Fable 额度已尽），Codex 写穷举 / 性质测试。
