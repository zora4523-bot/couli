# 变更记录：剪贴板自动查返利改为默认开启（2026-10-30）

- 状态：已写回（负责人 2026-10-30 在对话中决定）
- 来源：负责人 2026-10-30 问「为什么还有开启自动查返利的提示，应该默认监听」，编排说明 2026-10-17 改版的口径（默认关闭、首次用途说明弹层点【开启】）与合规考虑后，负责人在三个选项中选「改为默认开启」。
- 类别：改变用户授权边界与已确认决定（规划/00 §8 第 ② 类）；负责人已在对话中明确决定，按 00 §8 直接回写并注明日期。
- 取值归属：门槛、默认值、三端方式与降级以 08 BR-ID-16 为准；本记录只登记决定、差异、涉及编号与修法。

## 1. 负责人决定

剪贴板商品识别（自动查返利）**三端默认开启**：同意当前版本隐私政策后即按 BR-ID-16 的自动任务门槛在回前台时自动读取、本机提取候选、识别并弹商品卡，不再弹首次用途说明弹层，不再要求单独的功能用途同意。用户可在设置关闭，已关闭的保持关闭。

## 2. 与 2026-10-17 写法的差异

| # | 2026-10-17 写法（作废） | 2026-10-30 写法 |
| --- | --- | --- |
| 1 | 三端默认关闭；首次用途说明弹层，用户点【开启】才记功能同意版本并开启 | 三端默认开启；无用途说明弹层 |
| 2 | 自动任务门槛 ②：功能用途同意版本有效（`config.clipboard.consent_version`） | 作废，不再作为门槛 |
| 3 | 手动粘贴任务门槛 ②：已看过用途说明弹层 | 作废 |
| 4 | consent type `clipboard_auto_import` 记设备级功能同意 | 客户端不再写入；枚举与已有记录保留，不迁移 |
| 5 | 文案键 `clipboard.consent.*` 与设计稿 HomeClipboardConsent、SettingsClipboardConsent | 停用，不实现；已实现的移除 |

保持不变：隐私政策同意仍是前提（基本模式不读）；自动任务的其余门槛（开关、服务端按端停用、前台与焦点、敏感页面与互斥模态、每轮 1 次、系统拒绝节流）；iOS 系统「允许粘贴」照常由系统决定、拒绝时 UIPasteControl 降级；鸿蒙具备资格且已授权才自动读取、否则 PasteButton；Android 焦点读取；只上传最小候选、服务端不存原文、原文不进日志；自写排除与同 hash 去重；邀请口令仍须用户点击确认才绑定（BR-INV-04）。

## 3. 代理补全的默认（规划/11 §7.1 可由 Jev 推翻）

1. 2026-10-30 前在旧弹层选【暂不开启】或在设置关闭过的设备，按「用户已关闭」保持关闭；从未作出选择的设备随新版本按开启处理。
2. 撤回隐私同意进入基本模式后不读；重新同意隐私政策后开关回到默认开启，除非用户此前已在设置关闭（关闭态本机保留）。

## 4. 风险与负责人接受的代价

- 读取只建立在隐私政策同意上。国内监管与应用商店对「未经单独同意读取剪贴板」检查较严，可能被通报或审核驳回；负责人接受此风险。缓解：隐私政策个人信息收集清单写明剪贴板读取的用途、默认开启与关闭方式（规划/06 Q-F1，法务）；设置页开关三端都显示、一步可关；服务端可按端停用自动读取（`features.clipboard.auto_read.<client>`）作应急。
- iOS、鸿蒙的系统限制不变：iOS 仍可能弹系统「允许粘贴」，鸿蒙无资格时只有粘贴入口。面向用户的文案仍写「系统支持并允许时自动识别，否则用粘贴入口」，不作承诺。

- 验收：全新安装同意隐私政策后，复制商品链接回前台，自动任务条件满足的设备直接弹商品卡、无用途说明弹层；设置关闭后零读取零上传、手动粘贴照常；升级安装且此前已关闭的设备保持关闭。
- 恢复：如需改回 2026-10-17 口径，按 00 §8 由负责人决定；本记录 §2 表列出被作废的写法可原样恢复，三端的弹层设计稿与文案键保留未删。
