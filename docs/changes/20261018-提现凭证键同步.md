## 1. 判断

| 写法 | 位置 | 与账务模型的关系 |
| --- | --- | --- |
| 成功时「写一张凭证」，含 WITHDRAW_PAID、WITHDRAW_FEE、TAX_WITHHOLD，三者合计 = amount_fen | BR-WDR-09 正文；细则例 2（¥100、fee ¥1、tax ¥2 写一张凭证） | 与 BR-FUND-16「每个 uniq_key 对应 1 张凭证 + ≥2 条分录，(app_id, uniq_key) 唯一」、BR-FUND-19 ②「每张凭证 Σ amount_fen = 0」、04 §3.2 `ledger_vouchers.uniq_key`（唯一键在凭证表）一致 |
| 「每条分录的 uniq_key = wd:{withdrawal_id}:{FREEZE\|RETURN\|PAID\|FEE\|TAX}」 | BR-WDR-09 细则（2026-10-18 前） | 把键放到分录级：uniq_key 不是分录的属性；按 BR-FUND-16 三个键就是三张凭证，与正文「一张凭证」矛盾；也与 BR-FUND-05 的键形（一张凭证一个键，如 `{order_key}:{user_id}:{role}:CREDIT`）不一致 |

结论：细则一处写错，正文是对的。凭证键在凭证级：`wd:{withdrawal_id}:FREEZE`（W1）、`wd:{withdrawal_id}:RETURN`（W3、W6、W10 判 FAILED）、`wd:{withdrawal_id}:PAID`（W5、W8、W10 判 PAID_API、W11 的成功凭证，一张一键）。成功凭证内的 WITHDRAW_PAID、WITHDRAW_FEE、TAX_WITHHOLD 以 ledger_type 与分录序号（line）区分；金额为 0 的分录不写（正文已有）；更正按 BR-FUND-16 写 `{原 uniq_key}:REVERSE` 整张红冲。不新造取值：三个键名沿用原细则已有的 FREEZE / RETURN / PAID，只去掉分录级的 FEE / TAX。
