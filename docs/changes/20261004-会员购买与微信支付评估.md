# 影响评估：App 内购买订阅会员（微信支付）

- 日期：2026-10-04
- 类型：00 §8 第 ② 类。新增「向用户收款」的业务范围，并且与已确认的 BR-INV-12、BR-INV-20 的现有写法冲突（§1）。**本文只是影响评估，不改任何规划正文**；负责人按 §7 选定后再写回。
- 状态：待负责人决定。
- 起因：2026-10-04 负责人在对话中提出：App 内订阅会员的购买要支持微信支付。
- 范围：只评估会员购买的收款。提现打到微信零钱见 `docs/changes/20261004-微信零钱提现通道评估.md`（已批准）。
- 依据：08 BR-INV-12、BR-INV-20、BR-FUND-13；00 §3、§4；09 5_X CAP-X-12（商店审核）；微信支付、苹果、华为的官方文档（§2）。

## 0. 结论

1. 技术上不难：微信「APP 支付」是成熟产品，三端共用已经要接的微信 OpenSDK。
2. 真正要先定的是三件事，都不是技术问题：
   - **会员卖什么**。现有规则写明不得收会员费、不得付费获得或提高分佣资格（§1.1）。会员权益如果碰到返利比例或等级，就要改已确认的规则，并且需要法务意见。
   - **iOS 怎么卖**。苹果要求 App 内解锁功能必须用苹果内购，不能用微信支付（§2.2）。
   - **要不要自动续费**。微信的自动扣款是另一个产品，没有全面开放，要单独找微信申请（§2.1）。
3. 建议：第一版只在安卓用微信支付卖「按期一次性购买」的会员，权益限定为与返利无关的工具类权益；收款和打款用两个商户号；排期放在内测之后（P1），不挤占当前里程碑。

## 1. 和现有决定的冲突

### 1.1 不得收会员费（BR-INV-12、BR-INV-20，已确认）

两条规则的原文都有「不得收取任何入门费、会员费或购买门槛」，BR-INV-20 另写「不得实现：付费升级或付费获得分佣资格」。这两条的本意是邀请分佣不能以交钱为条件。按字面，「会员费」三个字已经把付费会员整体排除了。

要卖会员，就得把这句话改得更精确，有两种改法，后果不同：

| 改法 | 会员能给什么 | 风险 |
| --- | --- | --- |
| A 会员与分佣无关 | 只给工具类权益（§3.1），不影响任何人的返利比例、等级、邀请奖励 | 低。规则改为「不得以付费作为取得计酬资格或提高计酬比例的条件」，原意不变 |
| B 会员提高本人返利 | 买了会员，自己下单的返利比例更高 | 高。等于付费换更高的计酬比例，叠加两级邀请奖励后的合规性必须有法务书面意见；分佣规则、报价口径、月结都要跟着改 |

### 1.2 余额不能用来付款（BR-FUND-13，已确认）

用户余额是平台应付的佣金，不是储值，规则禁止任何余额消费接口。所以会员不能用返利余额抵扣或购买，只能走第三方支付。本文不建议改这一条。

### 1.3 规划里没有任何收费功能

00 的范围表、04 的数据模型和接口、05 的任务都没有订单支付、退款、收入科目。这是一个新模块，不是在现有模块上加字段。

## 2. 官方文档事实

证据等级：官方文档写法，2026-10-04 读取，没有实测；读取经过摘要工具，原文未留存私有库。写进 09 并实测之前不得当作事实或对用户的承诺。

### 2.1 微信支付

| 项 | 文档写法 | 出处 |
| --- | --- | --- |
| 准入 | 开放平台账号已认证、有移动应用 AppID；商户号申请「APP 支付」权限并与 AppID 绑定 | [产品介绍](https://pay.weixin.qq.com/doc/v3/merchant/4013070158)、[接入准备](https://pay.weixin.qq.com/doc/v3/merchant/4015478291) |
| 下单 | 服务端 `POST /v3/pay/transactions/app`，必填 appid、mchid、description、out_trade_no（6–32 位）、notify_url、amount.total（分）；返回 prepay_id，2 小时有效 | [APP 下单](https://pay.weixin.qq.com/doc/v3/merchant/4013070347) |
| 调起 | 客户端用 OpenSDK 发 PayReq（appId、partnerId、prepayId、package 固定值、nonceStr、timeStamp、sign）；sign 用商户证书私钥在服务端生成；三端都支持 | [APP 调起支付](https://pay.weixin.qq.com/doc/v3/merchant/4013070351) |
| 结果 | 客户端回调 errCode 0 / -1 / -2 只作提示，结果以服务端收到的支付通知和查单为准 | 同上、[开发指引](https://pay.weixin.qq.com/doc/v3/merchant/4013070176) |
| 关单 | 未支付订单要调关单接口；订单默认 7 天内可支付，可用 time_expire 缩短 | 开发指引 |
| 退款 | 有退款与退款查询接口，支持支付成功后 1 年内的订单 | 开发指引 |
| 对账 | 有交易账单与资金账单下载 | 开发指引 |
| 自动续费 | 属于「委托代扣」产品，分纯签约与支付中签约；文档写明接口未全面开放，需联系微信运营单独申请，App 拉起签约页还要另申请权限 | [委托扣款模式](https://pay.weixin.qq.com/doc/v2/merchant/4012205799) |

费率、单笔限额、支付通知的重试间隔在读到的页面里没有写明。

### 2.2 苹果

[App Store 审核指南](https://developer.apple.com/cn/app-store/review/guidelines/) 3.1.1：在 App 内解锁特性或功能必须使用 App 内购买项目，不得用自有机制解锁。3.1.3(b)：跨平台 App 可以让用户使用在其他平台或网站上买到的订阅。所以 iOS 版要么用苹果内购卖会员，要么不在 iOS 里卖、只承认安卓端买的会员，后一种做法下 iOS 内不能有购买入口或引导。苹果内购的分成比例、退款由苹果处理等细节本次没有核对。

### 2.3 华为（鸿蒙）

华为应用市场审核指南的搜索摘要里，对应用内付费写的是「推荐选择华为应用内支付」，没有查到「虚拟商品必须用华为支付」的明确条款，也没有读到原文全文。**这一项没查清**，鸿蒙版能否用微信支付卖会员要读原文并在提审时确认。

### 2.4 没有查的

支付宝 App 支付（如果安卓也要支持支付宝付款）；安卓各应用商店对虚拟商品支付方式的要求；电子发票。

## 3. 建议方案（第一版）

### 3.1 卖什么

会员只包含与返利计算无关的工具类权益。可选的方向（具体权益和价格由负责人定，本文不预设）：

- Agent 找货的每日可用次数或更强的模型档位；
- 订阅提醒（降价、补货）的可订阅数量与提醒频次；
- 历史价格、比价等查询类功能的使用上限。

不能包含：更高的返利比例、更高的等级、邀请奖励的资格或比例、提现的优先或额度。这些都属于 §1.1 的 B。

### 3.2 怎么计费

按期一次性购买（如月卡、季卡、年卡），到期不自动扣款，续费由用户再买一次、有效期顺延。不做自动续费。

### 3.3 哪些端能买

| 端 | 第一版 | 说明 |
| --- | --- | --- |
| 安卓 | 微信支付 | 支付宝 App 支付留接口，以后加 |
| iOS | 不卖，但承认账号上已有的会员 | iOS 内不放购买入口和引导；以后要在 iOS 卖就接苹果内购 |
| 鸿蒙 | 先不卖 | 等 §2.3 查清 |

### 3.4 系统上怎么放

- **新模块**：会员与支付单独成模块，不放进钱包和提现。支付订单、会员有效期、退款各有自己的表和状态。
- **账务隔离**：会员收入记平台自己的收入科目，不进用户余额，不与佣金、分佣、月结发生任何关系。
- **结果判定**：只认服务端收到并验签的支付通知与主动查单；金额、商户单号、AppID 都要与我方订单核对；同一通知重复到达只生效一次；开通会员与订单置为已支付在同一事务。
- **未支付与关单**：订单有较短的支付时限，过期由服务端关单；用户重新购买生成新订单。
- **退款**：退款后收回对应的会员有效期；退款规则（是否支持、几天内、已使用权益怎么算）由负责人和法务定。
- **入口**：只有原生 App 能发起下单和支付；H5、JSBridge、Agent 不能发起（与提现同一原则）。Agent 不主动推销会员。
- **回调入口**：支付通知需要公网可达的地址，放在 API 服务上；payout 进程仍然没有公网入口。
- **商户号分开**：下单签名要用商户私钥，而同一个商户号的私钥也能调转账接口。建议收款和打款各用一个商户号，这样能下单的服务碰不到能转账的密钥。
- **双品牌**：每个 App 有自己的 AppID，会员归属跟账号还是跟 App 走，立项时定。

### 3.5 排期

当前里程碑的资金线已经很满（月结、提现、三个打款通道），会员没有产品定义，建议放 P1：内测后立项，届时再把本节展开成需求、规则、契约和任务。现在不写进 08，也不占契约线。

## 5. 没查清的

1. 鸿蒙和各安卓应用商店是否允许用微信支付卖 App 内的虚拟会员。
2. 微信 APP 支付的费率、结算周期、支付通知的重试规则。
3. 微信自动续费能否申请下来、条件是什么。
4. 苹果内购的分成、订阅组、退款通知的处理方式。
5. 会员是否需要开发票、怎么开。
6. 未成年人购买的限制与退款要求。

## 6. 验收与恢复（立项后细化）

- 会员购买有独立的总开关，关闭后不显示入口、不接受下单；已买的会员照常有效。
- 资金不变量不受影响：会员收款不产生任何用户余额分录。
- 至少覆盖：支付成功开通；通知重复到达只开通一次；通知丢失靠查单补上；金额被篡改的通知被拒；未支付过期关单；退款收回有效期；iOS 上看得到会员状态但没有购买入口。
