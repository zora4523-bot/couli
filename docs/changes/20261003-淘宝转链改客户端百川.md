# 变更：淘宝转链改为客户端百川 SDK 完成

- 日期：2026-10-03
- 类型：实现方案变更（00 §8 第 ① 类）。订单归属判定、资金口径、用户授权边界、对外承诺都不改；会碰到这些的问题单列在 §6，等负责人决定，本次不改。
- 起因：2026-10-03 核实，淘宝联盟的链接 API（链接转换，含万能转链按链接 / 口令转换）和三方 API 都是邀请制，要求月日均点击 ≥5 万且月日均成交 ≥10 万元，或 App 下载量 ≥100 万、DAU ≥30 万，新 App 首版达不到；只有基础 API（商品搜索、详情、店铺、推荐、选品库）可自助申请（09 2_TB §2.5，文档已确认、高）。原规划假设每次点击都在服务端转链（05 B1-06、02 §5.1、08 BR-ATTR-05 / 27、09 CAP-TB-06），淘宝这条路走不通。
- 依据：09 2_TB §2.5（权限路径与门槛、对设计的影响）、5_X §5.5（百川 openByUrl 打开 s.click / uland 时不得再传 pid；百川 5.x 取消 adzoneId + appkey 方式）；私有库淘宝客 API 手册（`taobao.tbk.dg.material.optional.upgrade` 与 `item.info.upgrade.get` 都有入参 `relation_id`；`item.click.extract` 在「链接类接口下线权限保留包」scopeId 31576；`tpwd.parse` 权限包 scopeId 15969；`tpwd.create` 权限包 scopeId 11655）。

## 1. 变更内容

| 项 | 原方案 | 新方案（淘宝） |
| --- | --- | --- |
| 谁来转链 | 服务端 `links/{id}/open` 调万能转链，返回 s.click / 口令，客户端打开 | 服务端不调链接 API；open 下发**百川打开指令**，客户端百川 SDK 完成淘客转链 |
| 归因身份 | linking 按快照构造 UnionIdentity（pid + relation_id），写进转链请求 | 同样由 linking 构造，写进打开指令；客户端原样传给百川，不得替换或补填（BR-ATTR-05） |
| 打开方式 | openByUrl(服务端转出的 s.click) | ① link 带有本用户可用的**我方推广链接**时：openByUrl(该链接)，**不传 pid**（SDK 不支持二次转链）；② 否则 openByCode(商品详情, item_id) + AlibcTaokeParams(pid, relationId)，由 SDK 转链 |
| 我方推广链接 | —— | 只取基础 API（物料搜索升级版等）在「带本次快照 user 的 relation_id、并以该 pid_scene 推广位」调用时返回的 `coupon_share_url`（优先）或 `click_url`，随 link 登记；不跨用户、不跨推广位复用；有效期未核实前按 BR-ATTR-13 ② W_link 判定，过期只走 ② |
| 粘贴的淘宝链接 / 口令 | 万能转链 `material_list` 按链接转换 | 逐级解析出 item_id：链接本身带商品 ID（`item.taobao.com?id=…` 等）→ 口令用 `taobao.tbk.tpwd.parse` 取原链接（权限是否自助**待核**）→ s.click / uland 原链接用 `taobao.tbk.item.click.extract` 取 item_id（在下线权限保留包，大概率拿不到，**待核**）→ 都不行返回 30132 + 标题搜索（原降级）。取到 item_id 后用基础 API `item.info.upgrade.get` 出卡，点击时按 ② 打开。用户原链接、口令不交给百川、不当返利链接（BR-PRICE-21） |
| 价格复核 | 实时调转链或详情取 new | 淘宝取详情接口；报价快照、比较基准、阈值、弹窗、new_link_id、50303 分支全部不变（BR-PRICE-12、13） |
| 「转链缓存」 | 缓存转链结果 ≤900 秒、按 user_id 隔离 | 对淘宝指已下发的打开指令，规则相同 |
| link_logs | open 记一条，result_code=0 表示转链成功 | 照记；result_code=0 表示指令已下发。点击证据口径不变；SDK 拉起结果看 link_jump |
| 降级 | BR-ATTR-27 淘宝行 | 降级阶梯不变：taobao:// → Universal / App Link → H5 → 未安装提示 → 全部丢归因隐藏按钮。scheme / UL / H5 三步只在有我方推广链接时下发；口令只能由我方推广链接经 `tpwd.create` 生成（是否自助**待核**），拿不到就只显示安装提示、不复制口令 |
| 京东、拼多多 | 服务端转链 | **不变** |

- BR-ATTR-27：淘宝行改写、加「淘宝行说明」，原写法记入「取代」。
- BR-PRICE-13：补一句说明淘宝的「转链 / 转链缓存 / 转链失败」所指，判定与分支不变。
- 08 主题文件 04_ATTR 开头加本次调整说明；15_待验证汇总 BR-ATTR-27 行同步淘宝矩阵与验证要点。

## 3. 受影响的页面、接口与契约

规划文档已改：02 §5.1（时序图分平台 + 淘宝说明）、§6.1 淘宝单点风险；03 §4.5（淘宝 sdk 步骤）；05 B1-04、B1-05、B1-06、B1-07；09 2_TB CAP-TB-06「不支持时怎么办」列。

**契约变更（代码仓库 `rebate-platform/contracts/openapi.yaml`，CT-02a 产物；本次未改代码仓库，须由负责契约的任务按下面改）**：

1. `components.schemas.JumpStep`：现为 `{type, value}`、`additionalProperties: false`，`value` 只能放一个字符串，装不下 openByCode 的 item_id + pid + relationId。新增可选属性 `sdk`（仅 `type=sdk` 时出现，`type=sdk` 时必填；用两个 oneOf 分支各自声明必填属性，沿用 ADR-0001 §4.2 #15 的写法）：

   ```yaml
   BaichuanOpen:
     type: object
     additionalProperties: false
     required: [provider, open_by]
     properties:
       provider: { type: string, enum: [baichuan] }
       open_by:  { type: string, enum: [url, code] }
       url:      { type: string, format: uri, maxLength: 2048 }   # open_by=url 必填；只能是我方推广链接
       page:     { type: string, enum: [detail] }                 # open_by=code 必填
       item_id:  { type: string, maxLength: 64 }                  # open_by=code 必填；联盟新版字符串 ID
       sku_id:   { type: string, maxLength: 64 }                  # 可选
       taoke:                                                     # open_by=code 必填；open_by=url 时禁止出现
         type: object
         additionalProperties: false
         required: [pid]
         properties:
           pid:         { type: string, pattern: '^mm_\d+_\d+_\d+$' }
           relation_id: { type: string, maxLength: 32 }           # 快照用户 active 绑定；分享场景为分享者
   ```

   `type=sdk` 时 `value` 填 `url`（open_by=url）或 `item_id`（open_by=code），只作日志与兼容，客户端以 `sdk` 为准。描述里写明：客户端不得改写、补填 `taoke`；open_by=url 时不得传任何分佣参数（BR-ATTR-27 淘宝行）。
2. `contracts/enums/trade.yaml` `jump_type.sdk` 的说明补「淘宝：百川打开指令，参数见 JumpStep.sdk」。
3. 示例：`OpenLinkUnchanged` 现为淘宝风格的 `type: sdk, value: https://s.click…` + `copy_tpwd`，改为两条淘宝示例（open_by=code 带 taoke；open_by=url 不带 taoke），`copy_tpwd` 只在有我方推广链接时出现；京东、拼多多示例不变。
4. `ConvertLinkRequest` 的 `url` 分支（H5 `trade.convertAndOpen`）：淘宝 url 先按 §1 解析出 item_id 再出指令，描述补一句，形状不变。
5. 事件 `link_jump`（`specs/events.yaml`）：步骤结果补 `sdk_open_by`（url / code）与百川回调错误码字段，便于区分 SDK 失败与拉起失败。
6. 数据形状（04 管，代码仓库建好后以 `db/schema.sql` 为准）：`links` 增加可空的我方推广链接列（如 `promo_url`、`promo_url_fetched_at`，只存带本用户 relation_id 与该场景推广位取得的链接）。04 §3.2 links 行待契约任务落地时同步，本次不先写字段名进 04，避免与契约不一致。

## 4. 验收

- Adapter 回放测试：淘宝 Adapter 在任何入口都不调用链接 API（万能转链、privilege.get 等）。
- open 用例（淘宝）：自购、Agent、他人 link、游客 link、分享者打开自己分享 link（BR-ATTR-05 ①–⑤、BR-ATTR-11）下，指令里的 pid 与 relation_id 分别等于预期身份；未绑定返回 30101，绑定停用返回 30153，与原来一致。
- 我方推广链接：跨用户缓存的检索结果不产生 promo_url；有 promo_url 时 open_by=url 且无 taoke；过期后改为 open_by=code。
- 价格复核：淘宝 open 用详情接口取 new，BR-PRICE-13 边界用例全部照旧通过。
- 真机（CAP-TB-11 / HM-04，生产放量前必过）：openByCode 带 pid + relationId 下单后订单 adzone_id、relation_id 正确；联盟券能否领取；字符串 item_id 与数字 ID 是否都能打开；鸿蒙百川同样验证。未通过的路径按 BR-ATTR-27 ③ 不对生产对外用户下发。

## 5. 恢复方式

- 若联盟后续批准链接 API（或 CAP-TB-11 证实百川路径丢归因而服务端转链可用）：Adapter 恢复服务端转链，jump 改回 `type=sdk, value=s.click`（open_by=url），客户端无须改动，因为 open_by=url 本来就支持；本记录中的 BR 说明按日期追加「恢复」即可，规则正文其余部分未动。
- 百川路径全部丢归因且无替代：按 BR-ATTR-27 该端隐藏淘宝购买按钮，或 `convert.enabled.taobao=off`（09 CAP-TB-12 降级），京东、拼多多不受影响。
- 尚无生产数据，无迁移。

## 6. 待负责人确认的问题（涉及归属或对外行为，本次未改规则）

1. **淘宝分享链接在 App 外打开时怎么带上分享者的 relation_id。** 原方案由服务端用分享者身份转出短链 / 口令（BR-ATTR-05 ①、BR-ATTR-10、`POST /v1/shares`、分享中间页）。没有链接 API 后：分享链接在**本 App 内**被打开，仍可按分享者的 pid + relation_id 下发百川指令，归属不变；在**微信等 App 外**打开，中间页没有百川，只能打开预先带分享者 relation_id 的推广链接或口令，而这类链接只能碰运气从基础 API 检索结果里取到（按标题检索同一商品、且检索结果唯一时还需要消费者比价场景权限），口令还要 `tpwd.create` 权限。若取不到，App 外打开的淘宝分享单会进未归因池，分享者拿不到收益——这等于改变分享单归属的实际效果。可选做法：(a) 首版淘宝分享只给「在本 App 打开」的入口与海报，App 外打开时提示下载 App；(b) 生成分享物料时尝试用分享者 relation_id 检索取推广链接，取到才允许分享，取不到则淘宝不提供分享；(c) 首版淘宝不开放分享，京东、拼多多照常。建议 (b)，失败时退到 (a)。**确认前不改 BR-ATTR-10 与分享规则。**
   - **负责人决定（2026-10-03）**：沿用现有 App 的做法——分享时在 App 内用分享者身份把商品转成我方推广链接，并生成淘口令；分享内容带淘口令或商品推广链接；App 外打开的 H5 分享中间页提供「复制淘口令」。归属仍按 BR-ATTR-10（转链者 = 分享者）。实现：分享时调联盟基础 API 取带分享者 relation_id、share 场景推广位的我方推广链接，并调 `taobao.tbk.tpwd.create` 生成口令（权限包「淘宝客【公用】淘口令生成」，联盟应用建好后第一批申请并核实）。
   - 取不到我方推广链接或口令时的默认处理（负责人未另行指定，按推荐）：不生成淘宝分享，提示「暂时无法分享该商品」；不得退回为无归因的原链接分享。
2. **按 item_id 打开时券是否还在。** 卡片「领券购买」按券后价报价（BR-PRICE-01、21），若 openByCode 打开的详情页领不到联盟券，用户实付会高于报价。CAP-TB-11 验证前，生产对外用户本来就只下发已验证路径（BR-ATTR-27 ③），不会对外出现；若验证结论是领不到券，需要负责人决定淘宝有券商品在没有我方推广链接时是按无券价报价，还是不出该路径。
3. **百川应用与联盟应用分属两个淘宝账号。** 百川 SDK 分佣按 pid 归属联盟账号，跨账号是否影响跟单待真机核对（09 2_TB §2.5）。若影响，可能需要把百川应用迁到联盟账号名下或另建，属账号与供应商安排，由负责人处理。
4. **pid 与 relation_id 下发到客户端。** 原来它们只出现在服务端转出的链接里，现在以明文出现在指令中。用户只能拿到自己的 relation_id，篡改只会让订单归到别人或进未归因池，不会多拿钱；推广位 pid 暴露后他人可用它推广，佣金仍归本 App 推广位，按白名单入未归因池（BR-ATTR-16）。判断不改变归属规则，列出供负责人知悉，无需决定时可忽略。
