## 1. 登记的通用状态键（08 BR-TEXT-14 表 C）

键名、措辞与用法是代理补全的默认；「加载失败」取定稿画板 StateLoadFailed。文案过 BR-TEXT-13 词表，没有命中。

| 键 | 文案 | 用在哪里 | 归类 |
| --- | --- | --- | --- |
| `state.loading` | 加载中 | 首次加载用 `Skeleton`（不显示文字），本键作骨架的读屏名称；按钮内与等待外部结果的转圈没有场景键时用；加载态到时长上限转加载失败，不无限转圈 | 普通 |
| `state.load_failed.title` / `.desc` | 加载失败｜内容没有加载出来，请重试 | 整页或整块 `ErrorState`；有错误码时说明句取 `error.<code>[.<reason>]`，没有错误码（无统一外壳、解码失败、加载态超时）才用 `.desc`，不借用 `error.50001` | 普通 |
| `state.timeout` | 网络不稳定，请重试 | 读请求超时：`ErrorState` 说明句；写请求结果未知又没有场景键：轻提示，重试沿用同一幂等键；场景键照旧（`buy.timeout`、`login.network_retry`、`pending_confirm.*`） | 普通 |
| `state.retry` | 重试 | `ErrorState` 与断网整页态的主按钮；场景重试键照旧 | 普通 |
| `state.empty.default` | 暂无内容 | 没有自己空态键的列表或模块；不配【重试】 | 普通 |
| `state.value_missing.a11y` | 暂时取不到 | 金额位显示「—」时的读屏说法 | 资金术语（BR-TEXT-12 认定规则 ③） |

断网不新建键：无缓存沿用 `net.unavailable` / `net.unavailable.desc`，有缓存沿用 `net.stale_data`，两行已注明是通用状态的「断网无缓存」「断网有缓存」。维护、强更沿用 `web_page.maintenance`、`error.50301`（含表 B 子键）、`error.10405`。

取代的三端草稿键（不在契约里，随 FU-DS 删去）：`wallet.load_failed`、`me.load_failed`、`withdraw.load_failed` → `state.load_failed.*`；`home.loading` 与各模块 `*.loading` → `state.loading`；`order_list.network_error`（iOS、安卓）、`order.network_error`（鸿蒙）→ `net.unavailable`；各模块 `*.retry` → `state.retry`。其中 `wallet.load_failed`、`withdraw.load_failed` 原在资金术语前缀内，新键只说「没加载出来」，归普通。

表 C 之后另补「通用状态键」一段，按状态列出该取哪几个键，供 `specs/ui-states.yaml` 逐行引用；`texts.default.json` 的 `state.*` 与表 C 须零差异（DSX-01 验收末项，UI-STATES 合并后比对）。

## 2. 金额缺失的显示（08 BR-TEXT-10 一览行与细则「金额缺失」）

**所选做法**：金额字段为 null 或响应里没有该字段（0 不算缺失）时不补 0、不推算。单独显示一个金额的位置显示「—」（U+2014），不带「¥」、正负号与「+」，同一块其他金额照常显示，读屏读 `state.value_missing.a11y`；同一块的金额全部缺失，或缺的是这一块操作的依据（如提现页的可提现余额与提现估算），整块进加载失败（`state.load_failed.*` + 【重试】），依赖它的操作置灰。管理后台空值同样显示「—」。

**不按本条、照原条的**：商品价格缺失（BR-PRICE-01）、返利金额未知或无返利（BR-PRICE-08）、预售单定金为 null（BR-TEXT-02 细则）、Agent 卡必需字段（BR-AI-04）；文案模板里的金额变量为 null 时按 BR-TEXT-12 回落或整条隐藏，不代入「—」。「金额隐藏」打开时仍显示「****」。

**Jev 判断**（请求 `model` 为 `jev-latest`，返回 `jev-1.14.0`，2026-11-06；背景给了审计发现、BR-TEXT-10 / 12、BR-AI-04、BR-PRICE-01 / 08 现文与提现页的校验需要；请求与原始回答存私有运行目录 couli-runs `DSX-01/jev/`）：

| 选项 | 内容 | Jev 概率 |
| --- | --- | --- |
| A（采用） | 单个金额位显示「—」；全块缺失或缺的是操作依据时整块进错误态、操作置灰 | 1.00 |
| B | 任一金额缺失，整块进错误态，其他数据也不显示 | 0.00 |
| C | 一律只显示「—」，不进错误态，操作照常可点，靠服务端提交时再校验 | 0.00 |
| D | 缺失的金额连同标签隐藏 | 0.00 |

选择置信 1.00。另问「A 是否与现有规则冲突」：0.30（低于一半）。能想到的冲突点是 BR-TEXT-12 对模板变量缺失时整条隐藏，回写时已把模板变量排除在本条之外、照 BR-TEXT-12 处理，与 BR-AI-04、BR-PRICE-01 / 08 的 null 规定也逐一列为「照原条」。
