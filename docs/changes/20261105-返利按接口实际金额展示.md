## 1. 内容

1. **下单前**：返利一律按联盟接口返回的佣金字段，用现有报价函数（BR-CALC-20 `quoteRebate`）算出单一金额（`rebate_min_fen = rebate_max_fen`），显示「预估返 ¥x」。不再按来源（粘贴、搜索、Agent、无来源详情）判为比价风险，不再用 `rebate.taobao.compare_rate_ratio_bp` 估下限，淘宝不再出「预估返 ¥a–¥b」区间；BR-PRICE-07 来源判定表的「→ rebate_basis」判定列与区间算法作废。entry_source 的取值与继承不作废，保留在 BR-PRICE-07 细则现行的「entry_source 取值」表里，2026-11-05 起只用于 link 复用与统计，不再参与比价判定。no_rebate、amount_unknown（拼多多直链）与 login_required（游客卡）照原规则，不按本条算金额。以后取得淘宝比价预判定权限、接口在点击时直接返回比价后的佣金的，按接口返回的那个佣金算出单一金额显示（不是我们估的，也不出区间）。拼多多比价预判（开关 `rebate.pdd.compare_precheck.enabled`，预判为比价按 BR-PRICE-08 无返利原因处理）是按接口结果、不是估算，保留不动。
2. **下单后**：订单同步按联盟订单接口返回的字段识别比价订单（`orders.is_price_compare`），每次同步都按报文更新，入库后才被判为比价时补上标识；识别到后，订单列表与订单详情给这笔订单加「比价订单」标识，返利金额按接口返回的实际佣金计算（BR-CALC-16「以联盟返回的已降佣 N 分账、订单列表 / 详情 / 入账流水三处一致、差额原因 PRICE_COMPARE」不变）。淘宝用哪个字段、什么取值标识比价单尚未验证（§3），08 与 04 只写「按接口字段识别，字段与取值以 09 CAP-TB-04 实测登记为准」；核实前 `is_price_compare` 不置位、不显示标识，订单金额照样按接口实际佣金显示。订单列表加标识取自负责人原话，订单详情取自编排口径 ②；标识的显示范围（自购、分享子 Tab 都显示，AI 订单卡、推送、站内信不显示）是代理补全的默认（§8），决策人可直接改。
3. **新文案**：订单标识 `order.tag.price_compare`「比价订单」，归资金术语键（BR-TEXT-12 细则「资金术语键」单列），BR-TEXT-13「比价」一词的 allow_keys 补这个键。订单页原「比价风险」那一行（display_status=PAID 且 rebate_basis=price_compare_risk 时显示区间 + hint「如被判定为比价订单，返利按较低金额计算」）作废，改为「比价订单」行：is_price_compare=true 时显示标识，金额与状态 hint 照常按实际佣金；「比价无返利」行与「查看说明」入口保留。键名、标识与其他提示行并列、「查看说明」的位置与去重是代理补全的默认（§8），决策人可直接改。
4. **下单前的口径小字**：区间作废后，商品卡与详情不再用 `rebate_compare`（「以结算为准」），有返利金额时统一用 `rebate_estimate`（BR-PRICE-17 相应改）；`rebate_compare` 键保留不删（BR 编号与键不复用、不重排）。
5. **待决与待补**：08 §14.3 C-22 标为被本决定取代；06 的 Q-D2、Q-G2 不再挡下单前展示，只服务订单侧比价识别与收入估算（条目保留，改说明）；BR-PRICE-07、BR-AI-04 的依赖里去掉 Q-G2，只留在 BR-CALC-16。

## 3. 事实提醒：淘宝比价单的订单字段尚未核实

官方文档 `taobao.tbk.order.details.get`（https://open.taobao.com/api.htm?docType=2&docId=43328；私有库 `rebate-private/docs-mirror/taobao/` 2026-10-02 取回，文档修改日 2026-05-08）对 `flow_source` 的说明是「产品类型」：订单属于特定产品类型时写明（举例联盟超级活动、品牌精选推广、自主推广），普通订单为「--」；没有写比价订单的取值。09 CAP-TB-04 里的「2020 旧规则：订单用 flow_source 标识」与「花卷云 flow_source 0=否、1=是」都不是现行官方说法。所以 08、04 只写「按接口字段识别，字段与取值以 CAP-TB-04 实测登记为准」，不把 flow_source 的任何取值写成事实。用真实订单核实的做法已在 CAP-TB-04 步骤 2（同一商品一笔从 App 搜索进入、一笔先在淘宝搜到再粘贴进 App，对照订单字段与 pub_share_pre_fee）。降佣发生在付款时还是结算时同样待这一步记录（10 AC-S1-29-TB 暂按两种情形断言）。拼多多比价单的订单表现同样待 CAP-PDD-04。
