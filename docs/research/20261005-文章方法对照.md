# 文章方法对照：Spec Coding 实战与凑狸现状

2026-10-05 · 参考记录（分析快照）。负责人给了一篇文章的总结，问三件事：文章里的方法项目已经在做哪些、哪些值得学、学了有什么收益。初稿把五条做法直接写成了规则；当天请 Codex 做了五路对抗评审并逐条核实（§6），结论是方向可取，但写成立即生效的规则不成立，于是收缩成试行。试行做法在 [11 §2.6、§5.6](../../规划/11_开发协作与自主推进.md)，以那里为准；§5 的代码仓库待办由编排会话认领后以台账为准。本文留对照、结论、依据和评审过程。

文章：《AI 编程能力边界探索：基于 Claude Code 的 Spec Coding 项目实战》，得物技术，2026-03-11，<https://mp.weixin.qq.com/s/1Oi7YhMgcPp9gQAWPndXWA>。一位前端工程师用 10 天做出一个中后台，方法是先写规格再写代码、用「约束 / 示范 / 视觉」三层规范、把文档直接接给 AI、按需求大小选协作方式。文中的提效数字是作者自述，没有对照组。

## 1. 逐项对照

| 文章的方法 | 凑狸现状 | 判断 |
| --- | --- | --- |
| 先写规格再写代码（为什么、要求、怎么做、任务、实施、归档） | `规划/` 00–12、变更记录、ADR、台账、任务书、证据文件一整套；规则测试先红、两家模型互审 | 已在做，比文章重。重构类任务的不变量没有专门要求，目前也没有重构任务 |
| 约束层（规则文件） | 根与模块 `AGENTS.md`、保护路径、守卫脚本、lint，机器强制 | 已在做，比文章强 |
| 示范层（标准页面的完整样板） | 后端有模块分层说明，没有指定的样板模块；前端还没有工程 | 没做 |
| 视觉层（HTML 设计稿给 AI 直接读） | 已有可读的 HTML 草稿，也有定稿后整理规格的安排；尚未定稿入库，任务书没有稳定带上路径与版本 | 做了一半 |
| 把文档直接接给 AI | 接口契约就在代码仓库，任务书按编号抽规则原文，平台文档有私有镜像 | 已在做（做法不同） |
| 后端没好先用模拟数据 | 契约每个接口至少有一个成功示例；mock 服务还是待办；对着未实现的接口开发还缺兼容保护（§5 第 2 项） | 做了一半 |
| AI 先当产品经理、再当设计师、再写研发文档 | 需求评审、01 的需求与验收编号、高保真稿、各批拍板都做了；设计稿还没定稿，也缺「按定稿写页面规格」这一步 | 差最后一步 |
| 按需求大小选协作方式 | 只按风险分级（RV0–RV2），不按大小 | 没做，暂不照搬（§3） |
| 输入说得清才动手 | 七类才问负责人、待补清单、变更先评估 | 已在做 |
| 踩坑就补规范，修一次全局生效 | 已有把教训改进规则和工具的例子，会话任务书也点名教训文件；缺的是跨会话认出同一个坑，有四处重复（§4） | 做了一半 |
| 提前锁定环境 | ADR-0001 锁技术栈，锁文件与 `.npmrc` 是保护路径，验证在断网容器里跑 | 已在做，比文章强 |
| 评审前移 | 规则测试先过审再派实现；规划文档有对抗评审 | 已在做 |
| 多代理并行（文章列为后续方向） | 一任务一工作树，在途 2–4 个，路径相交不派 | 已在做 |

## 2. 结论与试行

1. **「项目重、文章轻，所以学轻的部分」作为方向成立，但不足以支持一次立五条规则。** 相反的读法同样说得通：文章的作者是先用两天做出第一个列表页、打通前后端，再铺开。该学的是先把头一对页面做通，规则从重复里提。
2. **四条页面做法现在都用不上。** 前端还没有工程，页面没定稿，后台接口没进契约，mock 没有。它们对当前主线（05 §0.1 前三段，全是后端）没有收益，试行要等这些前提具备才开始。
3. **按已记录的 Codex 调用看，最大的一块成本不在文章覆盖的范围。** 211 次调用里 158 次是评审；5 个后端任务各超过 10 次，合计 67 次、约三分之一的输入量，原因是规则测试评审与代码评审轮次不收敛。五条做法没有一条针对它，只有教训回流沾边。

试行的范围、开始条件与「留不留」的判断条件写在 11 §2.6。试的只是三样新增的形式；「对应页面定稿后整理成规格再开发」是负责人已定的安排，不算新增成本。新增的成本如下：

| 做法 | 试行时做什么 | 新增的成本 | 试点能看出什么 |
| --- | --- | --- | --- |
| 页面规格的格式、规格与稿件进任务书 | 两对试点页的规格按模板写，任务书补依据摘录 | 按模板整理比随手写多出的时间（待量）；重派时要手工补回摘录 | 第二张还会不会因与稿不符返工 |
| 参考已合并的同类页面 | 第二张的任务书给第一张的路径 | 指给后面的任务之前，编排会话要先看一遍 | 有没有引来返工或额外负担；次数只作观察 |
| 教训索引、再出现先核实 | 建索引；四处重复的坑逐个核实 | 写教训前查一次索引 | 索引启用之后有没有新的同类复发、处置有没有挡住 |

试点只能量出每页多花多少、有没有明显的坏处，证明不了提效：页面任务没有历史基线。

**能受益的页面范围。** 2026-10-05 中午按当时目录复核（评审时的一次性归类）：后台画板 148 张（已排除适配、无障碍、数值压力稿），按主界面归并约 103 组，九成左右能归入列表、表单、详情、带二次验证的操作、文件导入。但其中资金 46 组、仅涉及归属 10 组；排除它们与复杂流程后，可以照普通同类页面做的不超过三成（约 31 组，其中 4 组是初稿点名当示范的页面）。H5 的 14 组里约 4 到 6 组。页面数不等于工作量，目录仍在变动。

**评审后撤掉的做法。**

| 初稿的做法 | 为什么撤 |
| --- | --- |
| 页面任务分直改、照样板、完整三档 | 前端路径现在全按最高风险级走，分档不改合并条件；照样板档与完整档没有实质区别；直改档要等页面存在、风险表有前端条目才有意义 |
| 四样齐才就绪、未定稿的页面标 `ask` | 没接进就绪计算；`ask` 会占住路径，并在三天内全部报警；本地状态没有接口示例可填 |
| 示范页没合并不派同类型页面 | 一张页面的未决业务会卡住整类页面，三端会变成逐页串行 |
| 台账加 `lane`、`exemplar`、`ui_refs` | 现有解析器遇到未知字段直接报错，评审入口还会静默降级 |
| 照样板档的任务书只列规则编号与标题 | 评审方依赖任务书里的规则原文 |
| 后端没实现也对着契约提前开发 | 兼容检查把未实现的接口全部排除，改了不报警；mock 还没有 |
| 分线手册进任务书、第二次出现就加守卫 | 重复的坑都在编排一侧，Codex 碰不到；不受保护的文档不该成为规则通道；有的坑该改规则或删流程 |
| 「导入」以商品池为示范 | 商品池是选品与链接解析入库，不是文件导入；真正的文件导入都涉及资金、归属或黑名单 |

## 3. 不照搬的，与暂不立规则的

不照搬：

- OpenSpec 工具：项目已有台账、任务书、证据三件套，再加一套会多出一个来源。
- `.claude/rules/` 目录与独立的模板目录：规则要给两家模型共用，放 `AGENTS.md`；脱离工程的模板会过期，参考主干里带测试的真实页面。
- 用 MCP 直连接口文档平台：契约就在仓库里，Codex 沙箱也没有网络。
- 产品人设提示词：已有需求与设计流程，不必另设；未定稿页面与未决交互仍按现有澄清流程推进。
- 文章提到类型检查、冒烟验证与评审前移，没有讲缺陷率和测试覆盖；项目经手真钱，测试与评审不因文章而减。

暂不立规则，各写何时再看：

- 按需求大小分档：页面已存在、风险表有前端条目之后。
- 复杂排障的三个信号（只在远端复现且反馈慢、多个原因互相掩盖、依赖的隐性行为没有文档）出现时提前换打法：某个任务因只在容器或 CI 复现的失败用到第 3 次实现、或触发熔断时。本项目的容器验证在本机约一分钟一轮，沙箱外验证本来就由编排会话判读，眼下不是痛点。
- 重构任务先写为什么与不变量：台账里出现第一份重构类任务时。
- 由会话数据统计协作量：试点结束、时间戳不够说明 Claude 侧成本时。
- 文件头的 `@ai-context` 标记：模块 `AGENTS.md` 与任务书已承担。

## 5. 代码仓库侧的待办（给编排会话）

1. **风险表**：现在不加前端条目，`apps/h5`、`apps/admin` 建好后全部按默认 RV2 走，不加 `apps/admin/**` 这类宽条目。以后要降级，只把确认不含资金、归属、权限、二次验证、金额展示的页面目录逐个列出，没列到的仍是默认 RV2。改这份文件是保护路径第三类，又关系资金与归属页面的边界，先问负责人。脚手架新建 `packages/*` 目录时覆盖检查要求显式条目，先按 RV2 写。另记一件事实：带证据文件的 PR 在 evidence-check 里一律算 RV2，将来降级要有效果，得同时定低风险 PR 带不带证据文件。
2. **契约兼容**：oasdiff 的基线把标 `planned` 的接口全部剔除，理由是没有调用方，现在 51 个接口里 50 个在豁免内。启用「对着未实现的接口提前开发」之前，要让已被页面或原生端使用的接口留在基线里比较。`x-implementation` 只能取 `planned`、去掉它必须已有路由，所以要另加标识，不能改或删这个标记。原生端按 05 的关键路径本来就对着契约先行，这一条独立于试行。
3. **mock**：`contracts/README.md` 里 Prism 仍是 TODO；沙箱内用的示例夹具与沙箱外的 mock 都还没有。
4. **任务书的依据摘录**：派工脚本重派时会重新生成任务书并立即启动，冲掉编排会话补的段落；现在靠手工顺序补回（11 §2.6「任务书」一条）。试行第一张页面之前，要么让生成器保住这一段，要么接受这个手工顺序。
5. **教训**：索引已建在 `couli-runs/lessons/INDEX.md`（先登记了上面四处）；四处重复逐个核实后定处置。运行目录里的 `verify-locked.sh`、`review-locked.sh`、`refresh-pr.sh`、`regen-brief.py` 先补上教训里已记的缺口，再考虑并入 `tools/`。
6. **试点之后再定**：台账要不要加字段（顺序是解析器与任务书生成器先合入代码主干、本机运行工具的检出更新之后，再写回模板）；要不要分档；要不要登记示范页。
