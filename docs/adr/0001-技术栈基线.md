# ADR-0001 技术栈基线

- 状态：已采纳（负责人 2026-10-01 授权代理定版）
- 日期：2026-10-01
- 取代：`规划/00` D27 中「不冻结技术栈」的部分；`规划/02` §16.3 的「可调整」口径
- 被取代：无
- 相关：`规划/11_开发协作与自主推进.md`（协作规则）；`规划/02` §16、§18、§19；`规划/03` §3.3、§8、§9

## 1. 背景

规划里的技术栈一直标「当前方案，可调整」（00 D27、02 §16.3、03 §3.3），版本号、主键类型、迁移工具、测试库策略等第一天搭脚手架就要用的决定都没写。负责人 2026-10-01 指示：技术栈现在定下来，先把基础搭好，眼光放长远。

选型原则：一人运营，少一个要维护的组件就少一类故障；资金路径（锁账户、判幂等、写分录）要有编译期类型检查；凡是可能被替换的库，业务代码只依赖自有接口；版本用锁文件钉死，不追新。

版本核对与兼容性实测于 2026-10-01 在本机完成（PostgreSQL 16 容器）；标「待核」的项在 `规划/11` §9.3 验证日核实后补入本文。

## 2. 决定

「版本线」写允许的主版本范围，精确版本只在锁文件。禁止 `@latest`；新版本发布满 7 天才装。

| 层 | 选型 | 版本线 | 理由 |
| --- | --- | --- | --- |
| 运行时 | Node LTS | 24.x，≥24.18；写入 `.node-version` 与 `engines` | prism-cli 要求 ≥24.18；Node 26 成为 LTS 并稳定后再评估 |
| 语言 | TypeScript | 5.9.x | TS 7 实测让 openapi-typescript 崩溃；5.9 满足全部 peer 依赖 |
| 模块制式 | 全仓 ESM，`tsc -b` 构建 | — | NestJS 12 是纯 ESM |
| Monorepo | pnpm workspace + Turborepo | pnpm 10.x；turbo 2.x | 沿用；pnpm 配构建脚本允许名单与 7 天最短发布时长 |
| 后端框架 | NestJS 模块化单体 + Fastify 适配器 | NestJS 12.x；Fastify 跟随 `@nestjs/platform-fastify`，不单独声明 | 沿用 02 原则 1 |
| 进程入口 | api / stream / admin / worker / payout 五个 | — | 去掉 relay（见 §3） |
| 数据库 | PostgreSQL + pgvector（阿里云 RDS 高可用 + 1 个只读实例） | 18；云上高可用或 pgvector 核对不过退 17（待核） | 用到的能力（声明式分区、咨询锁、SKIP LOCKED）13 起都有，退版不改代码 |
| 数据访问 | Kysely + pg | kysely 0.29.x；pg 8.x | 行锁、SKIP LOCKED、CAS、冲突处理都有编译期类型检查 |
| 迁移 | node-pg-migrate（SQL 文件）+ kysely-codegen 生成类型 + `db/schema.sql` 快照入库 | node-pg-migrate 9.x；kysely-codegen 0.20.x | 分区 DDL 与普通迁移同一序列；表结构不绑定在库上 |
| 队列与事件 | pg-boss；业务代码只依赖自有 `JobQueue` 接口 | 12.x | 任务与业务写入同一事务入队；状态跟随 PG 备份 |

| 配置校验 | zod | 4.x | 启动时校验环境变量 |

| 边界与规范 | dependency-cruiser、ESLint + typescript-eslint、Prettier、squawk | dependency-cruiser 18.x；typescript-eslint 8.x | 单一写者与断言规则靠它们 |
| 日志与监控 | pino、@sentry/node、OpenTelemetry | pino 10.x；@sentry/node 11.x | 沿用 02 §13 |
| H5 | React、Vite、TanStack Query、Tailwind；组件库待定 | React 19.x；Vite 8.x；TanStack Query 5.x；Tailwind 4.x | react-vant 两年多未发版；脚手架阶段做真实浏览器冒烟后再锁（候选 antd-mobile 5.x） |

## 3. 与 `规划/02` §16.3 的差异

| 项 | 原方案 | 现方案 | 原因 | 代价 |
| --- | --- | --- | --- | --- |
| 数据访问 | Prisma | Kysely + pg | 资金核心路径在 Prisma 里几乎全是原生 SQL，还要靠两个预览特性；CHECK 约束在其 schema 里不可见；它的 CLI `latest` 标签已指向下一个大版本的候选版 | Kysely 仍是 0.x；普通增删改查更啰嗦；迁移全部手写 |
| 迁移 | `prisma migrate` + 分区表另写 SQL | 全部 SQL 文件，一个序列 | 消除「Prisma 不管分区表」与单一 schema 文件并存的矛盾 | 没有 schema 总览文件，靠 `db/schema.sql` 快照 |
| 队列与事件 | BullMQ + 独立 queue Redis + outbox 表 + relay 进程 | pg-boss：领域事件作为任务在业务事务内入队 | 少一个要持久化的 Redis 和一个进程；任务随 PG 备份与时间点恢复；排查用普通 SQL | 社区较小；任务写入压在主库；没有官方 Nest 模块，自写薄封装；海报出图要把轮询调到 0.5 秒或开通知 |
| HTTP 测试 | Supertest | Fastify `inject` | 已够用 | — |
| 版本 | 没写 | 见 §2 | 多个 `latest` 是几周内的新大版本，且互不兼容 | — |
| H5 组件库 | react-vant | 待定 | 维护停滞，对 React 19 的支持未核实 | 脚手架阶段多一次冒烟 |

- TECH-09 的实质不变：保留分区、手写 SQL 迁移、引用订单的外键指向 `order_keys`。
- 02 §18 写「代码不得自创其他模式」，其中领域事件一行由本 ADR 改为：业务写入与任务入队同一事务 → 至少一次投递 → 消费端 `processed_events(consumer, event_id)` 去重。「资金不依赖事件」不变。
- 02、05、08、10 里提到旧方案名词的地方由同步任务改为中立说法（`规划/11` §9.1）；同步完成前以本文为准。

## 4. 数据库设计规则

### 4.1 沿用不变

金额 `bigint` 分（`_fen`）、比例万分之一（`_bp`）、外部 ID 用 `text`、蛇形命名、业务表 `app_id NOT NULL`、保留外键禁级联、分录只插入加触发器（BR-FUND-16）、单一写者、CAS + `row_version`、记账按账户 ID 升序加锁、同一订单咨询锁串行、PII 信封加密加盲索引、迁移先扩展再回填再收缩、单条查询 join ≤3 张表。出处：02 §18、§19，04 §3.2。

### 4.2 本次补定

| # | 项 | 规则 |
| --- | --- | --- |
| 1 | 主键 | 实体表用 UUIDv7，由应用在 `packages/domain` 生成，列类型 `uuid`；只增不删的高频表（分录、事件日志）用 `bigint` 自增，不对外暴露 |
| 2 | `link_id`、`order_id` | UUIDv7；需要短码时另设 `short_code` 列 |
| 3 | 金额在 JSON 里 | 整数（`int64`），不用字符串；服务端用 BigInt，序列化时断言不超过 2^53−1；Swift 取 Int64，Kotlin 取 Long；pg 的 int8 统一解析为 BigInt（类型生成同步改映射） |
| 4 | 分区维护 | worker 里的定时任务用专用角色建和删分区：按月的表预建未来 3 个月，按日的表预建未来 14 天；每张分区表设 DEFAULT 分区兜底，其中有数据即告警 |
| 5 | 分区粒度 | `orders`、`ledger_entries`、`union_raw_payloads` 按月；`link_logs`、`events` 按日 |
| 6 | `ledger_entries` 分区键 | 新增不可变列 `booked_at`，主键 `(id, booked_at)` |
| 7 | `order_keys` | 加 `attr_at` 列：按 `order_id` 查订单时先取它，才能做分区裁剪 |
| 8 | 数据库角色 | `couli_migrator`（DDL，只在 CI）、`couli_app`、`couli_payout`、`couli_readonly`、`couli_maint`（只管分区）；建角色放 `db/bootstrap/roles.sql`，每个环境执行一次；授权写在迁移里 |
| 9 | 测试库 | 每次测试运行起一个 PG 容器，迁移只跑一次生成模板库，每个测试文件从模板建独立库；测试以 `couli_app` 身份连接，权限和触发器都被真实检验 |
| 10 | 时钟 | 统一为 `Clock` 接口加环境变量 `CLOCK_NOW`，只在 local 和 test 生效；prod 启动时发现设置了就拒绝启动；`X-Clock` 请求头作废 |
| 11 | 连接池 | 不用 PgBouncer（咨询锁和通知需要会话模式）；每进程池大小 api 10、stream 5、worker 10、payout 3、admin 主库 3 加只读 5，按 RDS 规格复核；只读实例用单独的 `dbRead`，只有后台报表模块能引用 |
| 12 | 本地栈 | `pnpm dev:stack` 依次启动 compose（PG + pgvector、Redis、MinIO、Prism、WireMock）、跑迁移、跑种子；种子统一放 `db/seeds/`，含首行 `app_id`、平台字典、开关默认值、本地超管 |
| 13 | 目录 | 迁移 `db/migrations/`；快照 `db/schema.sql`；不变量 SQL `db/invariants/`；guard 脚本统一 `tools/guard/` |

第 6、7 项改的是 04 的表形状，随用语同步任务回写 04 §3.2 与 BR-ATTR-22 的示例措辞（不改规则含义）。

### 4.3 对现有矛盾的裁定

| 矛盾 | 裁定 |
| --- | --- |
| 02 §19 要求每表 `id`、`updated_at`，04 有联合主键表和只插入表 | `id`、`updated_at` 只适用于可变实体表；联合主键表和只插入表按 04 的定义 |
| 02 §19 要求业务表都有 `deleted_at`，04 只有个别表有 | 只有 04 明确列出的表有 `deleted_at` |
| 02 §19「列表一律 keyset」，后台用页码分页 | 用户侧列表一律 keyset；后台允许页码分页，走只读实例 |
| 环境写四个又写「三个环境」 | 四个：local / test / staging / prod |
| guard 路径 `scripts/guard/` 与 `tools/guard/` | 统一 `tools/guard/` |

## 5. 影响

- **文档**：02 §16.3 已按本文改表；02 其余章节、05 的 B1-01 与 QA-02、08 中 13 条 BR 的实现措辞、10 §5.3 待同步任务处理。04 的表结构在 `db/schema.sql` 建立后改为指针（`规划/11` §5.4）。
- **替换成本可控**：Kysely 与 pg-boss 都隔在自有接口后面；SQL 迁移和表结构不绑定库。
- **要留意的风险**：NestJS 12、Vitest 5 都是近期的大版本；Refine 自 2026-04 后无新版，后台框架有停滞迹象；自建 Sentry 的规格未核实；向量模型与维度未定，`rule_chunks` 的迁移暂不写。
- **待核项**：RDS PG 18 的高可用系列与 pgvector；云上 Redis 可选版本；pg-boss 自管 schema 所需权限；带 pgvector 的 PG 18 镜像；OAS 3.1 转 Fastify 校验 schema 的工具链；`jose`、Xcode、Kotlin、AGP、DevEco 版本。核对结果补进 §2，不另开 ADR。

## 6. 以后怎么改基线

- **补丁与次版本升级**：在版本线内，走 `deps` 任务（`规划/11` §3.4），不改本文。
- **跨主版本、换库、改数据库设计规则**：新写一篇 ADR，文件头写「取代 ADR-0001 的 §x」，本文对应处标「被 ADR-NNNN 取代」，保留历史（00 §8）。新 ADR 要写清：为什么现方案不够、迁移步骤、回退方式、受影响的模块与测试。
- **涉及花钱、新供应商、生产数据或资金一致性的改动**：先问负责人（`规划/11` §7.1）。
- 把待核项的结果补进本文、修正错字或错引用，不算改基线。
