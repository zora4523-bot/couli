# 复用优先门禁

- 日期：2026-10-09
- 类型：00 §8 第 ① 类（协作流程与任务书、台账、评审做法；不改业务规则、契约形状与技术栈锁定项）。
- 状态：已写回（2026-10-09）。
- 起因：负责人 2026-10-09 看后台前端预览，发现登录页与外壳手写了 900 多行 CSS，只用了 antd 的 ConfigProvider 与 QRCode，而 03 §9.1 早写了「表单用 AntD Form」；两家评审三轮与编排都没拦。负责人问「如何避免下次犯同样的错误」，代理给出五处门禁，负责人回复「开始，确保符合规范没有遗漏」。同日前端调度会话已先行合并 03 §9.1 组件硬规则、11 §3.1 后台 S1 与 §2.6 参考页面核对（couli#102），并入账 F1-06p 改造任务；本文只补通用机制，不重复。
- 同类先例：B1-03e 三维限流自写 Redis 令牌桶，未按 2026-10-07 开源接入规划 §3 先对照 `@fastify/rate-limit`（followups F-46）。两例同一模式：代理优先通过检查，不优先复用；写在文档里的要求没有任何一道检查会因它不满足而变红。
- 依据：规划/11 §2.1、§2.3、§3.1、§3.3、§5.5；03 §9.1、§9.2、§10.5；`docs/changes/20261007-基础设施开源接入规划.md` §3；`docs/changes/20261009-基础设施开源接入决定回写.md`。

## 1. 原则

写在文档里的要求不会被执行，写进门禁里的才会。每一道「用现成的」要求都要落到一个会变红的检查（入账脚本、lint、评审清单项、抽查记录）上。

## 2. 五处门禁与落点

| 阶段 | 门禁 | 规划落点 | 代码落点 |
| --- | --- | --- | --- |
| 入账 | 台账 `reuse` 字段必填（impl / contract / migration），列出必须复用的库、组件、端口、原语；`task.ts check` 校验非空 | 11 §2.1；`docs/templates/task-ledger.md` | CT-06 复用门禁任务（草稿 couli-runs `planning/ledger-drafts/CT-06-reuse-gate.yaml`） |
| 任务书 | `brief.ts` 固定渲染「必须复用」小节，自写等价物视为缺陷 | 11 §2.3 第 2 步；`docs/templates/task-brief.md` §2 | 同上 |
| 机器检查 | `apps/admin` 页面与壳目录 eslint 禁止裸写 form / input / button / table 与布局元素，例外须行内注释理由 | 05 F1-06 行 | 前端线 guard-change 任务（草稿 `planning/ledger-drafts/F1-06-admin-eslint-guard.yaml`） |
| 评审 | `checklist[]` 加 `reuse` 项；自写现成已有功能记 S1（不限后台） | 11 §3.1、§3.3 | CT-06 复用门禁任务改 `tools/agent/prompts/review-*.md` 与 `review.schema.json` |
| 验收 | 后台设计稿比对改组件级，antd 默认样式差异不算差异，不为贴稿覆盖组件内部样式 | 03 §9.2 | — |
| 事后 | 每合并 5 个任务抽 1 个核复用；教训回流 | 11 §5.5；couli-runs `lessons/REUSE-FIRST.md` | — |

## 3. 不做的

- 不回头重写已合并的其他自写实现（B1-03e 限流按 F-46 评估后再定）；只对后台登录页与外壳按 F1-06p 改造，因为现在只有两块、业务页还没起。
- 不给代理加「态度」要求；只加检查。

## 4. 恢复方式

改回原文即可：台账 `reuse` 字段改为可选，`task.ts check` 去掉校验，评审 `checklist` 去掉 `reuse` 项；没有数据迁移。

## 5. 后续

- CT-06 复用门禁任务由基础设施开源接入线入账（guard-change，保护路径第三类，按 approvals 第 24 条两家评审过即可加标签）；落地前编排者在评审任务书里手工加复用检查项。
- 前端线 eslint 守卫任务与 F1-06p 一起排；守卫合并后 F1-06p 的改造结果必须过这条规则。
- 已入账但没有 `reuse` 字段的旧任务不回填；派工时编排者在任务书第 2 节手工补「必须复用」。
