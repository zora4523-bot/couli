## 1. 做法（取值见 08 BR-TEXT-20 细则「短信渠道登记与后台渠道开关」）

1. 短信是通知模板的一个渠道：按 `notify_templates` 的 code × variant 一行登记签名、阿里云模板 CODE、模板类型与预览正文；触发、变量与含义由代码定义，后台不能改。
2. 「加模板」是给已有的服务类编码登记短信渠道；前所未有的短信场景（例如营销短信）要新的通知编码，属开发任务，后台不能凭空造场景。
3. 签名与模板先在阿里云申请审核，后台只登记审核通过的值；后台直接提交审核、按回执查询送达结果为 P1。
4. 换签名或模板 CODE 先向操作人自己的验证手机号测试发送，阿里云受理成功才启用，失败保留原配置。
5. 后台只开关推送与短信，站内信不能由后台增删；只发站内信的编码（BR-TEXT-23 三个编码与 BALANCE_ADJUSTED）不能开推送或短信；各编码默认渠道沿用 BR-TEXT-09 模板表；`SMS_CODE` 与站长告警的短信渠道只能换模板、不能关。
6. 过渡：后台登记上线前，`SMS_CODE` 用部署配置的签名与模板 CODE（D10-315）；上线后以后台登记为准，部署配置只在没有登记时兜底；AccessKey 只走部署配置。

## 3. 验收

- 给一个服务类编码登记短信渠道：变量集合与代码不一致、`SMS_CODE` 写的有效期与 BR-ID-05 不一致都拒绝保存；测试发送受理成功后才能启用；启用后该编码按新签名与模板发出，`notify_logs` 记了回执编号。
- 订阅类编码与只发站内信的编码（BR-TEXT-23 三个编码与 BALANCE_ADJUSTED），后台没有登记短信或打开推送的入口；站内信在后台不能增删（`SMS_CODE` 不会写进站内信）。
- 后台关闭 WD_FAILED 的短信渠道后，新触发的 WD_FAILED 只发推送与站内信；`SMS_CODE` 与站长告警的短信渠道在后台没有关闭入口。
- 换验证码模板 CODE 时测试发送失败：原模板继续生效，登录取码不受影响。

## 4. 恢复方式

- 后台改错了模板：按审计日志里的原值改回；测试发送失败的新配置本来就不会替换原配置。
- 整个功能回退：停用后台登记的短信渠道后，`SMS_CODE` 回到部署配置兜底，其余编码按 BR-TEXT-09 模板表的默认渠道发送。
