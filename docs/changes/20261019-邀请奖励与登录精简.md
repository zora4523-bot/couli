## 3. 代理补全的默认（待确认）

负责人给了活动的形态与主要口径，下列细节由代理按保守口径补全，都在 BR-INV-24 细则「代理补全的默认」逐项标注，并登记在 06「2026-10-19 邀请奖励活动待确认」第 1～10 项。开关默认关，这些项在打开开关之前定下即可，不阻塞开发；涉及花钱的口径按 00 §9 由负责人定，不交 Jev。

1. 扣回细节：好友首单入账后、奖励发出前（含顺延期间）这一单被扣回或进入维权 → 这位好友的奖励作废，以后的订单也不再触发；已发出的不追回。
2. 「首单」= 好友本人自购（不含分享单）子订单里第一笔结算入账的，且基数 B > 0；最低实付 `growth.invite_reward.min_paid_fen` 默认 0。
3. 资格在绑定时锁定（含金额），只认 landing、register、backfill 三个自助渠道；关闭开关不撤销已有资格；紧急停发用「把总预算改为已发金额」。
4. 同 IP = 两人登录记录保留期内的 IP 集合有交集（共用网络会误伤）。
5. 单方问题（封禁、申诉、冻结、注销中、BR-ID-37 同设备多账号、已识别未满 18 周岁）只该方不发，另一方照发。
6. 当日预算不够顺延补发；总预算用尽不补发；活动有效 = 开关 on 且总预算剩余 ≥ 两方之和，展示随之消失。
7. 邀请落地页默认不显示奖励句（负责人只提了登录页与邀请页）。
8. 打开开关的前提加奖励所得的税务结论（06 Q-F6）。
9. 文案：选填说明「都可以」与 168 小时期限不完全一致、标题已有「选填」；奖励句金额按 BR-TEXT-10 显示「¥10」；流水名称「邀请奖励」是占位措辞。
10. 排期：M-公开，不计入内测出门。
11. 发放不另发推送，用户端不显示「不发」的原因；发放是独立凭证，在 CREDITED 迁移提交之后执行（资金线可改为同一事务，但不得因奖励失败阻塞结算）。
