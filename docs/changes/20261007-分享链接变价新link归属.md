# 变更记录：分享链接被他人打开且变价时，新 link 归分享者（2026-10-07）

- 状态：已写回（代理经 TypeSafe Jev 判定，负责人可随时推翻）
- 来源：代码仓库任务 B1-06k（open 价格复核）实现评审。实现把变价后新建的 link 一律登记在打开者名下；Claude 资金评审判 S0：分享链接被他人打开又赶上改价时，订单会从分享者翻到打开者，游客再点会得 10001。08 没有写这种情况下新 link 归谁。
- 类别：订单归属的取值（规划/00 §9 第 1 类）。按规划/11 §7.1（2026-10-06 起「在已列方案里选一个」的归属取值交 Jev 判断后回写）处理。
- 范围：BR-PRICE-12 补一句，不改已确认的口径；没有新增或作废 BR，BR、F、AC 编号不变。

## 1. 问题

BR-ATTR-05① 规定分享 link 任何人打开都用分享者身份；BR-PRICE-12 规定价格变化一律新建 link；BR-PRICE-13 规定变价后客户端无论确认还是取消都换成新卡。三条合在一起，没有说新 link 的 `user_id` 与 `identity_snapshot` 归谁。

## 2. 方案与 Jev 判定

| 方案 | 做法 | 后果 | Jev 置信度 |
| --- | --- | --- | --- |
| **A（采用）** | 新 link 沿用原 link 的 identity_snapshot，`user_id` 为分享者 | 换卡后再点订单仍归分享者；登记要支持按快照身份代登记 | 0.82 |
| B | 新 link 归打开者 | 订单从分享者翻到打开者，等于提供 BR-ATTR-10 禁止的「换成购买者本人链接」入口；游客再点得 10001 | 0.14 |
| C | 不新建 link，沿用原分享 link | 与 BR-PRICE-12「价格变化一律新建」字面冲突 | 0.07 |

Jev 问法：给出 BR-ATTR-05①、BR-PRICE-12、BR-PRICE-13、BR-ATTR-10 原意与三个方案，分别问「是否最符合规则本意且风险最低」（模型 jev-1.13.0）。

## 3. 写回

- `规划/08_业务规则/03_PRICE_价格口径与展示.md` BR-PRICE-12：在「为他人 link 新建 link 时比较基准沿用……」之后补一句，写明分享 link 变价时新 link 沿用原快照身份、`user_id` 为分享者、比较基准不变、打开者再点仍按分享者身份转链。
- 别人的非分享 link 不变：仍按 BR-ATTR-05③，以打开者身份、同一 scene 新建。

## 4. 受影响的接口与任务

- `POST /v1/links/{link_id}/open`：响应形状不变；只是分享 link 变价时 `new_link_id` 指向的 link 归属不同。
- 代码仓库 B1-06k：按 A 做第 2 次实现。

## 5. 验收与恢复

- 验收：B1-06k 的实现评审核对分享 link 变价时，新 link 的 `user_id` 与 `identity_snapshot` 等于原分享 link。
- 恢复：负责人要改成 B 或 C 时，回退 BR-PRICE-12 补的这句，并在 B1-06k 之后另开任务改登记逻辑。
