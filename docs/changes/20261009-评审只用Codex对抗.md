# 评审只用 Codex 对抗：取消 RV2 的 Claude 第二家评审

- 日期：2026-10-09
- 类型：00 §8 第 ② 类（改变协作分工；不改业务规则、契约形状与技术栈锁定项）。
- 状态：已写回（2026-10-09）。
- 起因：负责人 2026-10-09 在前端调度会话看 F1-06p 的流程说明（Codex 写测试 → Opus 实现 → Codex 与 Claude 两家评审），原话「对抗codex 使用 gpt6 astra 轻度 对抗review 就可以了 为什么还需要Claude 对抗 Claude 写的 就不要评审了 给chatgpt 对抗review 评审」。
- 依据：规划/11 §1.1、§2.3、§2.4、§3.2、§3.3、§6、§7.3 第 12 项；05 §2；代码仓库 `ops/approvals.yaml` 第 19 条（被本条修改）。

## 1. 决定

1. Claude Opus 5.5 子代理写的实现，只交 Codex 新只读会话做对抗评审；**不再派 Claude 新子代理做第二家评审**，RV2（资金、归属、迁移、破坏兼容的契约、提现与调账页面）也不派。
2. Codex 评审的模型 gpt-6-astra 不变，推理档位改为**轻度**（`model_reasoning_effort` 默认 `low`；代码仓库 `codex-run.sh` 用环境变量 `CODEX_REVIEW_EFFORT` 可按次调高，取值 minimal / low / medium / high / xhigh）。Codex 写测试（impl 模式）的档位不变。
3. **不变的部分**：Codex 先写规则测试、先红、`spec_commit`；Codex 写的规则测试仍由 Claude 新子代理过审（这是交叉审，不是自审）；完整验证看 CI 必过检查；证据文件、长跑属性测试、埋雷抽查、轮次熔断、合并条件里「无未关闭的 S0 / S1」改为只看 Codex 一家。
4. **换家后**（§2.5：RV0 / RV1 超限改由 Codex 实现一次）评审方仍对调为 Claude 新子代理——那时实现是 Codex 写的，Claude 审不是自审。

## 2. 代理的说明（不是负责人原话）

- 取消 Claude 第二家后，RV2 的「两家各试一次都复现不了」改为评审方与实现方各试一次；埋雷抽查仍只对 Codex 评审做。
- 轻度推理的 Codex 评审漏检率会高于 xhigh；资金与归属任务的编排者可用 `CODEX_REVIEW_EFFORT=high` 调高，不需要再问负责人。这一句是代理默认，负责人可改。
- 在途任务：当天起生效，已经派出的 Claude 第二家评审跑完就算，结论不作合并条件；证据文件里已有的 Claude 条目保留。
