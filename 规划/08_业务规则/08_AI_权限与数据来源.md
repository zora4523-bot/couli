## 8. AI 权限与数据来源（BR-AI）

#### BR-AI-08 细则 · 价格条件抽取口径

- 状态：默认假设
- 默认值：闭区间；“低于”取 N×100−1；“左右”取 ±10%（下限 floor、上限 ceil）；放宽顺序 规格 → 价格上限
- 决策人：负责人
- 依赖平台能力：无
- 取代：
  - 规划/01 §5 J3 步骤 1：「“50以内”→price_max_fen=5000（未说明比较对象与 &lt; / ≤）」
  - PRD v2.1 §10.3：「金额由模型换算成分，服务端校验 >0 且 ≤10,000,000（保留）」
  - 规划/01 F-AGENT-13：「无结果放宽重试 1 次」
- 来源：规划/01 §5 J3、F-AGENT-13；PRD v2.1 §10.3、§10.9
- 需同步修改的规划文档：3 处（计数仅作记录，落点见 README §0.6）

| 用户说法 | 抽取结果（N、M 元） |
|---|---|
| N 以内 / 以下 / 不超过 / 最多 N | `price_max_fen = N×100` |
| 低于 / 少于 / 不到 N | `price_max_fen = N×100 − 1` |
| N 以上 / 至少 N | `price_min_fen = N×100` |
| 高于 / 超过 N | `price_min_fen = N×100 + 1` |
| N 到 M / N-M / N 至 M 之间 | `price_min_fen = N×100`，`price_max_fen = M×100` |
| N 左右 | `[floor(N×90), ceil(N×110)]`（±10%） |

- 例：“50以内”→ 5000，final_price_fen=5000 入选、5001 不入选；“低于40”→ 3999；“9.9 左右”→ [891, 1089]；“30 到 50”→ [3000, 5000]。
- `search_products` 增加可选参数 `spec`（规格词，如 24盒、500ml），由模型从用户文本拆出，`q` 不含规格词。
- **无结果放宽**：最多 2 次追加调用，计入单轮 4 次工具调用上限，上限不够时停止放宽。第 1 次去掉 `spec`，notice `agent.notice.relaxed_spec`（“已放宽规格条件”）；仍无结果，第 2 次去掉 `price_max_fen`（`price_min_fen` 保留），notice `agent.notice.relaxed_price`（“已放宽价格条件”）。
- 两次放宽后仍无结果：不再检索，出 notice `agent.notice.no_result`（默认“没有找到符合条件的商品”），suggestions 取 `agent.suggest.no_result.1–3`（默认“去掉价格条件再找”“只搜{q_short}”“换个平台看看”），由 CardAssembler 下发（BR-AI-06），模型不生成。本条是 Agent 无结果处理的唯一维护处，BR-PROD-04 细则与 AC-S1-46 引用本条（G-19）。
- 以下情况不放宽，直接出 notice：① `refine=cheaper` → `agent.notice.no_cheaper`（“没有找到比当前结果更便宜的商品”，同 BR-PRICE-15）；② 查询词或全部结果命中禁售黑名单 → `agent.refuse.prohibited`（BR-AI-18）。
- 与 BR-PRICE-15 的分工：比较对象、闭区间、0 &lt; 值 ≤ 10,000,000、min ≤ max 的校验口径与 BR-PRICE-15 相同；差别只在失败处理——Agent 链路校验失败不返回 20001（SSE 照常，出 clarify），GET /v1/products/search 直接调用时按 BR-PRICE-15 返回 20001。上游只透传下限、上限由服务端过滤，按 BR-PRICE-15 执行。
- 评测：“关键词 + 条件”参数正确率 ≥95%。
