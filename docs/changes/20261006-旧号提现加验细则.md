# 旧手机号被二次放号时的提现加验：补齐细则

- 日期：2026-10-06
- 类别：00 §8 第 ② 类里「待决策」的方案选择，按 规划/11 §7.1（§7.3 第 13 项）由代理用 TypeSafe Jev 判断后回写、事后报告；负责人可随时推翻。
- 涉及：BR-WDR-01 细则「旧手机号被二次放号时的提现加验」、BR-WDR-03 正文（新增 ③b）、BR-WDR-07 细则「前置步骤的回流」、BR-ID-05 / BR-ID-06 / BR-ID-27 细则指针；规划/12 §9 A-11、§5.1。
- 受影响的页面与接口：Withdraw、PayoutAccount、RealName、注销页、绑定第三方身份；`POST /v1/withdrawals`、`GET /v1/withdrawals/rules`、`PUT /v1/me/payout-account`、实名、注销与绑定第三方身份接口、各登录与并号接口（建立会话时判定）、后台客服代办换号；新增加验页与加验流程（契约线定义）。

## 1. 背景

2026-10-06 整批确认已定原则：高风险的旧账号在提现前加验原实名或既有的可信身份，首版不接付费的号码检测（`docs/changes/20261006-待确认事项整批确认与交由Jev判断.md` §6.3、§10）。还缺四项，补齐前该项不启用：判定条件与阈值、校验位置与返回码、通过后的有效期、第三方身份加验的流程与适用条件。

## 2. 候选方案与 Jev 结果

代理为每项拟了三个候选（选项 A 是代理的建议），连同背景、校验顺序与原则（「不要限制得太死；能做成配置就做；但不能让用户亏钱、不能把钱算错、不能让别人冒充本人拿到个人信息或资金」）交 Jev（`jev-1.13.0`，choice 题）。

| 项 | A（选中） | B | C | Jev 选择（置信度；三项概率 A / B / C） |
| --- | --- | --- | --- | --- |
| 判定 | 建立会话时：本次之前最近一次登录或令牌刷新距今 ≥ 180 天（可配置，0 关闭）且本次设备从未在该账号登录过 → 打「待加验」标记，保留到加验通过；不看余额 | 阈值 90 天，不看是否新设备 | 同 A，另要求可提现余额 ≥ ¥10 | A（0.93；0.95 / 0.04 / 0.01） |
| 位置与返回码 | ③a 黑名单之后、④ 未实名之前（③b），新错误码 + `data.method`；rules 接口不跳过；收款账号变更同样拦截 | 放在 ② step-up 之前 | 复用 10003 + `data.reason` | A（0.97；0.98 / 0.01 / 0.01） |
| 有效期 | 通过即清除标记，长期有效，再满足判定条件才重新打标 | 本设备 30 天内有效 | 每次提现都加验 | A（**0.34**；0.55 / 0.10 / 0.35） |
| 加验依据与第三方流程 | 只认打标前的实名与第三方身份；标记期间不许新绑第三方身份；复用 `POST /v1/auth/oauth-attempts` 加 `purpose=reverify`；连续失败 5 次当天转人工 | 不做第三方加验，没实名的一律人工 | 同 A，但打标后完成的实名也可用 | A（0.98；0.99 / 0.00 / 0.01） |

有效期一项置信度低（C「每次都加验」占 0.35）；Codex 评审指出整账号清除挡不住冒名者重新登录，已复判改为按设备（§6）。

- BR-WDR-03 正文：③a 之后加 ③b。BR-WDR-07 细则「前置步骤的回流」：Withdraw 页按该码打开加验页，该码列入「需要用户补办」。

## 5. 验收与恢复

- 验收：契约线实现后补 AC（沉睡账号换设备登录 → 提现返回新码；同一设备回来不打标；加验通过后本设备可提现、另一台设备仍要加验；并号迁入的身份不能加验；打标后补的实名不能加验；未加验设备上注销、首次实名、绑第三方返回新码；连续失败 5 次只剩人工；客服代办换号后会话全部作废、可信身份以外的第三方身份解绑、标记清除）。
- 恢复：按 git 记录把 BR-WDR-01 细则改回「未定……补齐之前本项不启用」，删去 BR-WDR-03 ③b、BR-WDR-07 回流里的该码、BR-ID-06 / BR-ID-27 / BR-ID-28 新加的条目与 12 §5.1 的 ③b，A-11 余下部分改回四项未定。
