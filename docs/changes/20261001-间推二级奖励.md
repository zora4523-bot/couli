# 变更：开发间推（二级奖励），后台开关控制

- 日期：2026-10-01
- 类型：改变已确认决定（D8）与资金计算口径（00 §8 第 ② 类）
- 批准：负责人（2026-10-01，对话中确认：「需要开发二级奖励的方案，保留在后台开启关闭设置的功能」）
- 财务确认：间推比例默认值随 06 Q-B1 / `ledger-rules.md` 签字一并确认

## 1. 变更内容

原 D8：只做直推一层，间推比例固定为 0，数据库 CHECK (= 0)，后台不出现间推配置项，解锁需法律意见 + 迁移。

新 D8：**计酬最多两级（直推 + 间推），间推能力随 MVP 开发，由后台开关控制，默认关闭。**

| 项 | 规定 |
| --- | --- |
| 层级上限 | 最多两级：直推（上级）+ 间推（上级的上级）。depth ≥ 3 的祖先永远不进入受益人，DB 与纯函数双重约束；再增加层级须新的负责人决策 |
| 开关形态 | 开关是**规则版本**的一部分，不是独立的即时配置：`commission_rule_versions.indirect_enabled`（默认 false）+ `commission_rules.r_indirect_bp`（CHECK 0–8000）。开启、关闭、改比例都通过发布新规则版本完成，沿用 BR-CALC-11 的 effective_from、按 paid_at 选版本、不回溯已生成快照 |
| 关闭时 | `indirect_enabled=false` 的版本中 r_indirect_bp 必须全为 0（CHECK）；splitCommission() 不产生 indirect 受益人，行为与原 D8 一致 |
| 开启操作 | 后台分佣规则页的「间推」开关与比例列；发布含 `indirect_enabled=true` 的版本须 step-up + 第二人审批（财务角色）+ 审计，并展示近 7 天试算（BR-CALC-11 试算报告增加间推份额列） |
| 受益人 | 间推受益人 = 直推上级在 paid_at 时刻的上级（两层都按 relation_change_logs 在 paid_at 重放，BR-CALC-12、BR-INV-11）；任一层在 paid_at 不存在 → 该份额归平台，事后绑定不补 |
| 比例取值 | r_indirect_bp 取 (platform, 间推受益人在 paid_at 的等级, order_type) 行；分享单的间推受益人是分享者上级的上级（BR-CALC-24） |
| 份额 | 间推份额 = floor(B × r_indirect_bp / 10000)，尾差归平台；入 PROMO 账户；流水 REFERRAL_CREDIT，sub_type=INDIRECT（不新增流水类型）；所得类型 SERVICE_FEE |
| 上限 | BR-CALC-07 发布校验改为：max(r_own) + max(r_direct) + max(r_indirect) + 活动加成 ≤ 8000 |
| 失效 | 间推受益人的有效性判定与直推相同（BR-CALC-13：失效归平台、不顺延；未成年人按 BR-INV-19、BR-ID-26） |
| 防重 | 间推受益人与归属用户或直推受益人为同一人时（异常数据），间推份额归平台并告警 |
| 默认比例 | 占位 r_indirect_bp = 500（5%），待财务确认；开关默认关闭，占位值不影响上线 |
| 用户展示 | 开关开启后，余额流水与收益明细把间推份额显示为「好友推广奖励」（2026-10-01 负责人确认名称，话术走 BR-TEXT 字典，与 P1 邀请奖励区分）；仍不做团队业绩、下级人数、排行、层级称谓等（BR-INV-20 其余禁止项不变） |

法律意见（06 Q-F5）仍由负责人跟进；系统不以其为技术闸门，开关由负责人按上述审批流程开启。

## 2. 涉及的规则

BR-CALC-04、05、06、07、10、12、13、24；BR-INV-12、13、14、20；BR-FUND-15（REFERRAL_CREDIT sub_type）；BR-TEXT（流水与收益话术）；08 §13（role、sub_type、配置与表字段对照）；08 §14.1（待决策条目）。

## 3. 受影响的页面、接口与数据

- 后台：分佣规则页（开关、比例列、发布校验、试算、审批）；分佣快照查看页显示 indirect 受益人。
- 用户端：收益明细、余额流水（开关开启后出现间推收入）；邀请说明页文案。
- 接口与契约（04）：commission_rules / commission_rule_versions 字段；beneficiaries.role 增加 `indirect`；ledger sub_type 增加 INDIRECT；后台规则发布接口的校验与审批。
- 纯函数：packages/domain splitCommission() 增加 indirect 分支；属性测试覆盖「关闭时无 indirect」「份额和 ≤ B」「depth ≤ 2」。
- 历史数据与迁移：尚无生产数据，无迁移；上线后关闭→开启不回溯，按 paid_at 选版本。
- 新旧客户端：未知 role / sub_type 按枚举兜底（.unknown）显示为通用收入，不崩溃。

## 4. 验收

10 中新增用例：关闭时不产生间推；开启后间推受益人、比例、取整正确；两层任一缺失归平台；发布校验（上限、关闭时比例必须为 0、审批）；版本切换按 paid_at 生效且不回溯。

## 5. 恢复

出问题时发布 `indirect_enabled=false` 的新版本止损（对之后付款的订单生效）；已生成的快照不改，如需纠正走 SETTLE_ADJUST / ADMIN_ADJUST 按 BR-CALC-23 审批。
