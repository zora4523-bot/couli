# 凑狸关键交互草案

2026-10-01 · 第二版设计建议 · 依据 [参考 App 研究](README.md)、[官方画面证据索引](evidence-index.md) 与当前 `规划/01`。

本文用于后续线框与设计令牌的应用。表内「状态」是设计稿需要覆盖的界面场景，不是新增接口枚举或业务状态机。业务判断、金额和话术只引用对应 BR；具体超时、额度、归因和资金规则不在这里复制。

本轮观察的是官方发布的静态界面图片，未运行竞品的登录、交易、回跳和提现旅程。以下流程是凑狸现有需求的设计建议，不是对竞品实际行为的复述。粘贴入口、余额与提现按钮已有国内官方画面支持；剪贴板授权、外跳返回、跟单延迟、提现失败恢复仍须按 `规划/09` 和 `规划/10` 验证。预览页中的虚构反馈不代替这些验收。

## 1. 粘贴 / 搜索 → 详情 → 购买跳转

参考：返利网官方图中的显式粘贴入口 + Apple Store 的商品层级 + 一淘的返利步骤说明。Rakuten 官方说明只辅助理解购物记录与返利状态，国内外跳返回尚无竞品实测证据。

| 界面场景 | 建议呈现与操作反馈 | 项目依据 |
| --- | --- | --- |
| 初次进入 | 搜索入口突出；粘贴使用各平台允许的显式控件；不在用户无感知时读内容 | J2、BR-ID-16 |
| 输入识别中 | 输入保留，原入口显示处理中，防止用户因为没有反馈反复点击 | F-CLIP、F-PROD-01 |
| 识别失败 | 原文保留可修改；按现有能力提供重新输入或关键词搜索，不能把失败解释为权益已经失效 | J2、BR-TEXT-14/15 |
| 搜索结果 | 选中平台和条件持续可见；回到列表恢复阅读位置；空结果与网络错误分别呈现 | F-PROD-01、BR-PRICE-15 |
| 商品详情 | 首屏明确商品和金额信息；口径说明可找到；购买为主按钮，AI 为辅助入口 | F-PROD-05、BR-PRICE-03～11、17、21 |
| 点击购买 | 按钮即时给出处理中反馈；用同一位置反馈复核结果，防止误认为已成功下单 | F-LINK-01、BR-PRICE-12/13 |
| 需要登录 / 平台授权 | 使用现有说明页面并保留上下文；返回后由现有恢复逻辑继续，不让用户再次寻找商品 | BR-ID-10、17、18 |
| 授权不可用 | 显示与实际原因对应的错误；按钮集合按服务端原因决定，不能把常规取消授权的降级入口用于所有失败 | BR-ID-24、F-LINK-03 |
| 复核结果变化 | 对比区域突出变化信息；按规则需要用户确认时提供明确选择，不用短暂 Toast 代替必要确认 | BR-PRICE-13/14 |
| 准备外跳 | 按既有 `JumpTip` 规则展示说明；按钮明确将前往哪个平台 | BR-ATTR-21、BR-ATTR-27 |
| 外跳后返回 | 恢复原商品上下文；不要播放「返利已获得」动画；订单事实由订单接口更新 | BR-FUND-01、BR-TEXT-01/02、规划/09 |

**界面验看重点**：金额未知或商品下架时仍有明确反馈；长标题不推走主按钮；用户取消登录或授权后不丢商品；大字体下的主按钮与安全区域不重叠。实际业务验收引用 `规划/10` 中 J1、J2 对应的 AC。

## 2. AI 表达需求 → 看卡片 → 修改条件

参考：Perplexity 官方产品图中的来源标记 / 来源卡，以及官方购物功能说明中的商品卡方向。条件回显与商品数据分工采用凑狸既有 BR；本轮未观察到完整移动端 AI 购物旅程。

| 界面场景 | 建议呈现与操作反馈 | 项目依据 |
| --- | --- | --- |
| AI 尚未开放 / 已关闭 | 遵循现有导航替换和入口开关，不把不可用入口画成可点击服务 | 规划/01 §4.1、BR-AI-12 |
| 首次使用 | 展示 AI 单独同意界面，保留清楚的继续与退出路径 | BR-AI-13 |
| 空态 | 展示后台配置的示例问题；品牌图形作为轻量识别元素，避免占用主要输入区域 | 规划/01 §4.1、BR-TEXT-22 |
| 受理中 | 输入内容保留；发送入口按进行中的请求状态防止重复触发；显示中性加载反馈 | BR-AI-23 |
| 条件明确 | 用可读的短标签回显平台、预算、规格；不要将检索条件当成商品事实标签 | BR-AI-08、BR-AI-24 |
| 部分结果已返回 | 卡片逐步可读，保留原阅读位置；解释文字和金额信息分区；不伪造模型的内部思考过程 | BR-AI-04/06 |
| 结果完整 | 逐卡展示服务端生成的条件标记和数据；重要限制直接可见，说明入口辅助核对 | BR-AI-10/24、BR-PRICE-16/17 |
| 同轮追问 | 快捷操作采用现有多轮能力；显示用户追加的条件，让新旧结果的关系容易理解 | F-AGENT-05、BR-AI-05 |
| 条件被放宽 | 保留原始条件摘要，并根据服务端返回显示放宽反馈；不将新结果包装成全部满足原条件 | BR-AI-08/24 |
| 无结果 / 部分平台失败 | 区分没有匹配与请求失败；保留可用结果，提供现有修改条件与搜索入口 | BR-AI-08/14 |
| 模型降级 | 保留正常商品卡和固定说明；只有搜索也不可用时再走对应错误反馈 | BR-AI-14/16、BR-TEXT-22 |
| 身份、额度或会话条件不满足 | 使用对应引导和返回路径；不将所有情况统一显示为网络错误 | BR-AI-11/15/20/23 |

**界面验看重点**：卡片数目不同不会留下固定大块空白；软键盘与输入框不遮挡操作；说明、AI 标识、广告标识与业务金额有明确角色；读屏顺序符合消息先后。不要为参考 Perplexity 添加首版不存在的历史列表或跨会话记忆。实际业务验收引用 `规划/10` 中 J3 对应的 AC。

## 3. 订单 → 看原因 → 找回 / 钱包

参考：Rakuten 官方商店图中的已确认 / 待确认分组与购物记录入口 + 一淘的返利钱包步骤 + 返利网的余额与提现入口。竞品营销图中的到账速度、手续费和兑换方式不进入凑狸规则。

| 界面场景 | 建议呈现与操作反馈 | 项目依据 |
| --- | --- | --- |
| 订单列表 | 沿用自购与分享分组；每行突出商品、当前状态和相应金额标签，额外信息进入详情 | 规划/01 §4.1、F-ORD、BR-TEXT-01/02 |
| 列表空态 | 空态明确当前分组没有记录，保留找回与继续浏览的显式入口；加载失败单独显示重试 | J4、J5、BR-TEXT-14 |
| 订单详情 | 当前状态优先，历史时间线在后；预计结算信息按接口呈现，异常原因靠近相关金额 | BR-TEXT-02～05 |
| 用户查看异常 | 页内直接展示已知原因和建议；AI 是额外帮助入口，不作为阅读原因的门槛 | J5、F-AGENT-06 |
| 找回订单 | 表单保留用户已填信息；缺失项就近提示；提交后进入可查询的记录反馈 | BR-ATTR-17～20、J5 |
| 钱包 | 单一余额主卡体现可操作金额；其他状态信息分组解释，流水说明收益来源 | BR-FUND-18、BR-TEXT-01、J6 |
| 进入提现 | 提现作为明确动作；身份、收款账号与协议页面让用户逐项完成，表单不预先暗示成功 | BR-ID-25、BR-WDR-01/02/31 |
| 提现已提交 | 切到记录和实际状态反馈；处理中不展示到账庆祝，不添加自行撤销入口 | BR-TEXT-06～08、F-WDR |
| 提现不可用 / 失败 | 原因与下一步入口在金额附近可见，按字典和服务端状态决定可用动作 | BR-TEXT-01/08/23 |

**界面验看重点**：返利与提现状态不混用；异常不只依赖红色；列表金额用稳定对齐；敏感字段按现有规则脱敏；关键资金操作不依赖隐藏手势。实际业务验收引用 `规划/10` 中 J4～J6 对应的 AC。

状态配色应与文案一致：商品卡的预估返利、订单等待结算采用中性或等待状态表达；已结算再使用成功语义。已收货只说明订单阶段，不以整块绿色成功标签暗示返利已入账。界面样例须同时保留明确文字，金额与状态由接口决定。

## 4. 制作线框时的阶段检查

- **当前 MVP**：三条现有旅程的视觉组织、空态、加载、结果、失败与恢复反馈。
- **P1**：跨平台同款、截图找同款、降价提醒、美团、会员月账单等只保留未来方向；依赖、未知项与阶段以 `规划/00`、`规划/01` 为准，不画成当前可用按钮。
- **不新增**：收藏、历史会话列表、跨会话记忆、购物车、代下单、代支付与自动领券。
- **上线内容**：业务文案取字典，状态取接口；设计示例不是生产事实，不能用布局或动画建立额外承诺。
