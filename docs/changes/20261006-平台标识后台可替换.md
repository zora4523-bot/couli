- 来源：负责人提出平台 logo 素材会经常变更，问是否要先有存储再补、能否在后台上传。原做法（2026-10-05 [后台保守规则与适配范围](20261005-后台保守规则与适配范围.md) §5）是负责人把官方标识放进 `design/icons/platform/`，随安装包与 H5 产物发布，换图要发版。

## 1. 内容

1. **内置一套**：`design/icons/platform/` 的官方标识照旧打进三端安装包与 H5 产物，作为兜底。负责人提供之前，开发用占位图标，不阻塞页面开发。
2. **后台可替换**：后台「内容」新增「平台标识」页（F-ADM-14），按平台上传替换图、预览、发布、回滚，留版本历史与审计；新权限点 `content.platform_icon`。
3. **下发与兜底**：`/v1/config` 新增顶层键 `platform_icons`（形状在 04 §10.1）；客户端按内容摘要缓存，远程图缺失、下载失败或校验不通过时显示包内那套，不出现空白。
4. **上传校验与来源登记**：取值与含义只在 08 BR-TEXT-24 维护（文件格式、清洗、大小、必填的来源页地址与下载日期、只换用途不变的官方原图）。
5. **存储**：上传的图存阿里云 OSS `media` bucket，按内容摘要命名、经 CDN 公开读（02 §3 的现有 bucket，不新增供应商）。环境开通前后台上传功能只在本地与测试环境的替身存储上验收。

## 3. 验收

- 后台上传一张新图并发布后，三端与 H5 在下一次取配置后显示新图；回滚后显示上一版。
- 断网、远程图 404、摘要不符时显示包内图标，不留空白、不报错。
- 上传带脚本或外部引用的 SVG 被拒或清洗后才保存（BR-TEXT-24 细则）；缺来源页地址或下载日期不能发布。
- 没有 `content.platform_icon` 的后台账号看不到该页；发布与回滚写审计。

## 4. 恢复方式

后台回滚到任一历史版本，或清空某平台的替换图（下发中去掉该平台），客户端即回到包内图标。整体撤销本功能时把 `platform_icons` 下发为空，客户端全部用包内图标。
