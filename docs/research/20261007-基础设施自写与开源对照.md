# 基础设施自写与开源对照（2026-10-07）

- 状态：参考，属于分析记录，不是开发依据。技术选型以 `docs/adr/0001-技术栈基线.md`、`docs/adr/0002` 为准，业务取值以 `规划/08_业务规则/` 为准；本文与它们冲突时以 ADR / 08 为准。
- 用途：回答负责人 2026-10-07 的问题「当前项目需要搭建多少基础设施？哪些可以直接用开源项目？有必要全部从 0 开始搭建吗？」。
- 做法：13 个代理分四步——5 个盘点读者读 `规划/02`、`规划/03`、`规划/05` 与代码仓库（rebate-platform 本地 main c0cae7b / origin/main 3742c6b，三端原生仓库 2026-10-07 当日提交），列出 382 行组件；6 个领域评估员逐项裁定并联网核实候选开源项目的许可证、维护状态、国内适配与是否触碰 ADR-0001；1 个对抗核查员专挑评估员的错（两个方向：换开源不靠谱、自写其实有开源）；1 个综合员汇总。核查员的质疑原文见附录 A，评估员没覆盖的 6 项见附录 B。
- 置信度：表中「置信度」列由综合员按证据强弱给出；带「保留意见」的条目是核查员削弱过的，采用前要先做它写明的验证。GitHub 对一年内的发布只显示月日，年份按当日推断。
- 没有做的事：没有安装或运行任何候选项目，没有登录任何控制台；「官方 Node SDK 是否存在」这类要进控制台才能核的事按「未核实」处理。

## 一句话结论

「从 0 开始」不成立：数据库、队列、日志、监控、CI、测试、前端框架、三端工具链全是现成开源或平台能力，真正必须自写的是规则层（身份判定、账本、归因、联盟适配、Agent 护栏、JSBridge 协议、门禁），这些没有可替换的开源件；还能再省的只有 7 处小改（squawk、二维码库、staging 反代用 Pigsty 自带 nginx、链路追踪并入 VictoriaTraces、Dependabot、GlitchTip 待验证、Grafana 看板待拍板），不要再引任何重型自托管系统。

## 6. 延后或不做的

- **不引独立 IdP / 开关平台 / 通知平台 / 模型网关 / Agent 框架 / 追踪评测平台**：Logto、Keycloak、Kratos、Better Auth、SuperTokens、Casdoor；Unleash、Flagsmith、GrowthBook；Novu；LiteLLM、one-api、new-api；Vercel AI SDK、LangGraph.js、Mastra；Langfuse、Phoenix、Braintrust——共同原因：独立服务或自建表（违反 ADR-0001 迁移唯一来源），规则不匹配，无运维团队、单节点放不下。备忘：Casdoor 是唯一国内适配完整的 IdP，将来多系统 SSO 再看。
- **不换账本/迁移/分区工具**：TigerBeetle、Formance、Blnk、Medici；Atlas、Bytebase、Liquibase、pgroll、pg_partman；均与 ADR-0001 角色/镜像/同事务约束冲突。
- **不上 PaaS 层**：Dokploy、Coolify、Kamal 各带 Traefik+PG+Redis，与 Pigsty nginx 冲突。
- **SLS 暂不换 VictoriaLogs**（核查推翻）：BR-ID-30 ⑥ 要求应用日志 180 天，VictoriaLogs 开源版只有全局 retention，且 Pigsty Vector 无自定义源入口；若要换须按 180 天 + 独立盘/对象存储重算成本并同步 08，现阶段维持 SLS 规划。
- **P1/首版关闭**：payment、淘礼金、美团 Adapter、P1 前端入口、京东/拼多多客户端 SDK、产品分析平台（PostHog/Matomo/Superset；真要上只有 Umami 与基线相容）、Stryker（上游 Vitest 5 issue 未修）、规则引擎（02 §16.3 P2）。
- **内测期延后**：prod SLB/WAF/CDN、多地拨测、备用域名/HTTPDNS。
