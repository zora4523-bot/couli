## 2. 给资金线的 csv 改法（按本记录改起草稿）

- 平台行 sub_account：全部 available（⑦）。
- CLAWBACK、SETTLE_ADJUST 的平台差额 14 个模板：ledger_type / sub_type 取所在业务（CLAWBACK / FULL 等，SETTLE_ADJUST / SETTLE_DIFF 等），与起草稿一致。
- CREDIT:PLATFORM、FORFEIT、FORFEIT:REASSIGN、FORFEIT:DEFERRED、UNION_RECEIPT 两个：ledger_type REBATE_CREDIT、sub_type 空（①②③）。
- CREDIT:PLATFORM 金额 `platform_credit_fen`；FORFEIT:DEFERRED 键 `{order_key}:PLATFORM:FORFEIT:{uid}:{role}:DEFERRED:{beneficiary_credit_id}`、借 UNION_RECEIVABLE:{platform} / 贷 COMMISSION_REVENUE、金额 `pending_credit_fen`；WITHDRAW:SUCCESS 三个的 PAID 行 `net_fen`、TAX 行 `tax_fen`；UNION_RECEIPT 键 `RECEIPT:{platform}:{receipt_id}`、金额 `receipt_fen`（⑤②）。
- 新增延后补记模板，按义务上记下的开立类型（`origin_ledger_type`、`origin_sub_type`）选 4 个之一：`ADJ:DEFERRED:SETTLE_DIFF`、`ADJ:DEFERRED:PRICE_PROTECT`、`ADJ:DEFERRED:PRICE_COMPARE`（ledger_type SETTLE_ADJUST）、`ADJ:DEFERRED:RESTORE`（ADMIN_ADJUST / RESTORE）；键 `{order_key}:{user_id}:{role}:ADJ:DEFERRED:{beneficiary_credit_id}`，借 UNION_RECEIVABLE:{platform} / 贷 USER_BALANCE.available，金额 `pending_credit_fen`（③；template_id 叫法资金线可改）。
- 改派：REASSIGN_CREDIT 拆 5 个——用户按角色 4 个（self → REBATE_CREDIT，share → SHARE_CREDIT，direct / indirect → REFERRAL_CREDIT 的 DIRECT / INDIRECT；借 UNION_RECEIVABLE / 贷 USER_BALANCE.available，金额为新快照下的应得）与平台 1 个（REBATE_CREDIT 占位，借 UNION_RECEIVABLE / 贷 COMMISSION_REVENUE，金额 `platform_credit_fen`）。REASSIGN_REV 不拆成「每个角色一个固定类型」的模板：每个旧受益人 / 角色各一张、平台一张，按被更正分录的 (ledger_type, sub_type) 分组，每组一借一贷（用户组对 UNION_RECEIVABLE，平台组 COMMISSION_REVENUE ↔ UNION_RECEIVABLE），金额为该组在该账户上的代数和、为 0 的组不写，全部组为 0 才不写凭证；在 csv 里怎么表达（按组列行、金额名沿用 reassign_fen 或按组命名）由资金线定（⑧）。
- RECON_FIX、OTHER：按白名单科目拆模板（同 PAYOUT_RECOVERY 按通道拆的先例），COMMISSION_REVENUE、UNION_RECEIVABLE:{platform}、BAD_DEBT、MKT_EXPENSE × 调增 / 调减 × 正常 / 红冲，共 32 个替换原来 8 个；白名单仍注明待财务确认，财务改白名单时增删对应模板（Jev：拆模板 0.77，置信度 0.66；写参数的做法放不下含冒号的 UNION_RECEIVABLE:{platform}）。

## 3. 待负责人决定

**改派时旧受益人已进入注销处理或已注销**（06_FUND §6.3 第 23 项）：已入账订单改派（R14）要先红冲旧快照受益人在本单的分录。旧受益人已进入注销 processing 或已注销、且在本单键下还有不为 0 的类型组时，这部分记在哪里，规则没有写。

| 选项 | 做法 | 影响 |
| --- | --- | --- |
| A（推荐） | 比照扣回（BR-FUND-08）与负差（BR-CALC-09）的已注销规则：不写墓碑账户，按其净额改借 BAD_DEBT / 贷 UNION_RECEIVABLE，键不变，净额为 0 不写 | 这笔由平台承担（记坏账），金额 = 旧受益人在本单的净额；新受益人照常拿到应得；与注销后扣回的现行做法一致 |
| B | 照常红冲墓碑账户 | 墓碑账户余额变负，之后没有收入抵扣；BR-FUND-12 核销只适用于未注销用户，负数一直挂着；本质上同样是平台损失，但对不上账 |
| C | 这种订单不允许改派 | 不产生坏账，但新受益人拿不到这单返利，订单仍归已注销的旧受益人；客服纠错没有通道 |

决定前按 C 的效果处理：没有分录模板，事务整笔不提交，什么都不变。旧受益人在注销冷静期的不在此列，照常红冲（冷静期不算失效）。
