## 1. 问题

08 有五处写了转链缓存（BR-AI-04 细则「转链缓存」、BR-PRICE-13 细则「单飞与转链缓存按身份键隔离」、BR-ID-17 正文与影响面、BR-PROD-07 键表、BR-ATTR-05 细则「缓存键」），写法互不一致，其中三处的字面写法与代码的实际做法不同：

| | 原字面写法 | 实际做法（本次写进规则） |
| --- | --- | --- |
| ① 无返利购买的结果 | BR-AI-04（已确认）：不带用户归因参数的结果不得缓存，也不得返回给 links/open | 只在无返利身份下单独缓存；无返利与带归因两种身份互不命中；非无返利的 open 不得返回不带用户归因参数的结果，无返利购买按 BR-ID-18 |
| ② 用户授权或重新授权 | BR-AI-04：授权、重新授权、绑定释放时清除该用户全部转链缓存；BR-ID-17：不得复用授权前的缓存 | 归因参数或推广位有变化时旧条目不命中；后台重置绑定时尽力清除；缓存不替代授权校验（授权校验在读缓存之前） |
| ③ 单飞与缓存的身份 | BR-PRICE-13（已确认）：身份键由身份主人、推广位与是否无返利组成 | 身份由更多项共同确定（再加平台、商品、推广位所属联盟账号、归因参数等），更严 |

实际做法同样防住三件事：把甲的链接给乙（缓存按身份主人与归因参数隔离，授权校验在读缓存之前）；把不带归因的链接给要返利的人（非无返利的 open 拿不到无返利结果）；把带归因的链接给选了无返利购买的人（无返利请求拿不到带归因的结果）。

另：架构评估 RA-04 的建议写法「授权一变即失效」由本决定改为「归因参数或推广位变化即不命中」——重新授权后归因参数不变的，旧条目仍可命中；绑定停用、封禁、后台重置后，带归因的 open 在授权校验一步就返回错误，读不到缓存（无返利购买按 BR-ID-18 跳过授权门，只读无返利身份下的条目）。

## 4. 验收

代码现状已符合本写法（`rebate-platform` 主干 5b1dcb1，只读核对），不需要改代码：

- 先授权、后读缓存：open 的顺序是平台开关与路径准入 → 授权校验 → 价格复核 → 转链或打开指令；淘宝、拼多多的授权不通过（30101 / 30102 / 30111 / 30153）都在读缓存之前返回。
- 缓存键含 app_id、身份主人、平台、product_key、原始商品 ID、pid、pid_scene、是否无返利与外跳方案变体，京东、拼多多点击码开关打开时含点击码；与条目同存的标签：淘宝为绑定的联盟账号与 relation_id 加选中推广位的联盟账号与 pid，拼多多为绑定与其联盟账号加选中推广位，无返利为「无返利 + 推广位」。标签不同即不命中；单飞按键加标签区分。
- 无返利结果单独缓存，与带归因的结果互不命中。
- 后台重置淘宝绑定后清除该用户的缓存条目，清除失败只记日志、重置照常生效。
- 有效期 ≤900 秒。
- 京东适配器尚未实现，标签还没有京东分支；京东接入时按 BR-ATTR-05 细则「缓存键」补齐（subUnionId、私域推广位模式下的私域推广位）。

对应的已有冻结测试由 union 线与 W1 线对照本写法核对；核对中发现与本写法不符的，按代码仓库的测试变更流程处理，不反改本规则。代码注释里仍指向「BR-AI-04 细则『转链缓存』」的，随下次相关改动改为指向 BR-ATTR-05 细则「缓存键」。

## 5. 恢复方式

负责人改选「维持字面写法」时：回退本次 PR 的文档改动，并另开两个开发任务——用户每次授权或重新授权都让该用户的转链缓存失效；不再缓存无返利结果（拼多多、京东的无返利购买每次多一次联盟调用，淘宝不受影响）。同时 BR-AI-04「不带用户归因参数的结果……不得返回给 links/open」与已确认的 BR-ID-18 无返利购买冲突，这半句仍须改写。
