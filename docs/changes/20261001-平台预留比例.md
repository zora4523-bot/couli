# 变更：恢复平台预留比例，分佣基数先扣预留

- 日期：2026-10-01
- 类型：资金计算口径变更（00 §8 第 ② 类）
- 批准：负责人（2026-10-01，对话中确认）。原话要点：「淘宝返回的佣金要先减去预留的比例，剩下的再根据用户等级的比例区分佣」；「昨天预留 13%，设置 15% 时应按最新的生效」；生效范围选「改后付款的订单用新比例」；比例「只按等级，不设个人专属比例」
- 财务确认：各平台预留比例的初始值由负责人 / 财务在后台设置，随 `ledger-rules.md` 签字一并记录

## 1. 变更内容

原 BR-CALC-02：B = max(0, N_base − tlj_deduct_fen)，不扣任何平台预留（不设 reserve_bp）。

新口径：

| 项 | 规定 |
| --- | --- |
| 公式 | B = max(0, floor(N_base × (10000 − reserve_bp) / 10000) − tlj_deduct_fen)；预留部分归平台，尾差归平台 |
| 预留维度 | 按平台设置（taobao、jd、pdd，接入的平台各一个值），不按等级、不按订单类型、不设个人值 |
| 取值范围 | reserve_bp 整数，0–10000（万分之一）；如淘宝 15% = 1500 |
| 配置位置 | 属于分佣规则版本：每个规则版本对 commission.platforms 中每个平台必须有一个 reserve_bp，缺任一平台拒绝发布（与 BR-CALC-06 完整性校验同处） |
| 生效 | 改预留比例 = 发布新规则版本，按订单 paid_at 选版本（BR-CALC-11）：改之前付款的订单保持原预留，改之后付款的订单用新预留；已生成的快照不重算 |
| 初始值 | 种子版本 reserve_bp = 0；上线前由负责人在后台按平台填写（例：淘宝 1300） |
| 分账 | 本人、直推、间推份额都按 B 计算（BR-CALC-04、BR-CALC-05、BR-CALC-24），比例只按等级（BR-CALC-06，不变） |
| 报价 | 商品卡、Agent 报价与入账使用同一个计算函数，报价同样先扣预留（BR-PRICE-06） |
| 快照 | commission_splits 记 reserve_bp 与 reserve_fen（= floor 后扣除的预留金额），快照后不可改 |
| 四段金额 | BR-CALC-27 的「基数前扣除」包含预留金额 |
| 上限 | BR-CALC-07 的 ≤ 8000 仍以 B 为基数，不变 |

## 2. 涉及的规则

BR-CALC-02、04、06、10、22、24、27；BR-PRICE-06（报价口径）；08 §13（reserve_bp 字段对照）；08 §14（BR-CALC-02 待决策条目、B10 去向）；06 Q-B1 与 B10 行。

## 3. 受影响的页面、接口与数据

- 后台分佣规则页：每个平台一个「预留比例」输入；发布校验与试算差异报告增加预留列。
- 04：规则版本增加按平台的 reserve_bp（CHECK 0–10000）；commission_splits 增加 reserve_bp、reserve_fen。
- 纯函数 splitCommission() 与报价函数：先扣预留再分账；属性测试覆盖「份额和 + 预留 + 尾差 = N_base − tlj」。
- 历史数据：尚无生产数据，无迁移。

## 4. 验收

10 中新增用例：预留按平台扣除；改预留后按 paid_at 生效、不回溯；报价与入账一致；发布时缺平台预留被拒。

## 5. 恢复

发布新版本修正预留比例（对之后付款的订单生效）；已生成快照如需纠正按 BR-CALC-23 调整。
