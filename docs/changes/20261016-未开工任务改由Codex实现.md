# 变更记录：未开工的任务默认改由 Codex 实现（2026-10-16）

- 状态：已确认（负责人 2026-10-16 在对话中明确）
- 负责人原话：「现有的任务 保留claude。执行 就是还有没开始的 可以安排 codex 来执行 可以提高开发效率」。编排会话追问范围（原 2026-10-06 例外的安全边界是否放开），负责人选「边界外 + 三端原生」。
- 类别：分工与门禁（规划/11 §7.3），负责人决定。
- 背景：多条线同时推进，Claude 各账号周额度先后用尽（第二账号 10-16 撞限、10-20 恢复）；Codex 走另一份额度，把未开工任务的主实现交给 Codex 可提高并行度。

## 1. 内容

1. **已开工的任务保持原分工**：已认领、或已有 `spec_commit` / 实现提交的任务，照旧由 Claude Opus 实现、Codex 写测试与对抗评审。
2. **未开工的任务默认由 Codex 实现**：入账或开工前改为台账 `impl: codex`、`tester: claude`，任务号加进代码仓库 `tools/guard/codex-impl-tasks.json`；流程同 2026-10-06 例外：Claude 子代理先写规则测试（先红）→ Codex 新只读会话过审测试 → Codex 经 `codex-run.sh impl` 实现（gpt-6-astra，推理档位 high）→ Claude 新子代理代码评审（规划/11 §2.4：实现方之外的一家）。
3. **仍由 Claude 实现的范围（安全边界不变）**：资金、订单归属、打款、订单补拉、数据库恢复与主库切换、发布流水线接入、数据库迁移、接口契约；`codex-impl-tasks.json` 的 `forbidden_paths` 照旧。
4. **三端原生 App 的新任务也改由 Codex 实现**：构建与模拟器验证由编排者在沙箱外跑，失败信息交回 Codex 下一轮；Codex 轮次用满仍不过按 §2.5 换家给 Opus 一次；先在一端试行。

## 3. 验收与恢复

- 验收：之后新入账的非资金、非归属、非迁移、非契约任务，台账为 `impl: codex`、`tester: claude` 且在 `codex-impl-tasks.json` 里，证据文件的代码评审为 Claude 新子代理；三端原生新任务由 Codex 实现、编排者沙箱外复验。
- 恢复：负责人要收回时，删除 §1.1 新增条与 §7.3 第 15 项、撤销 approvals 对应条目；已改派但未开工的任务改回 `impl: claude`、`tester: codex`；已由 Codex 实现并合并的不回退。
