# 凑狸 UI / UX 参考

研究日期：2026-10-01。第二版保留 **5 个参考：Apple Store、返利网、Perplexity、Rakuten、一淘**。以两款国内导购 / 返利 App 补充粘贴素材、跟单和资金入口的观察，替换首版的 Airbnb 与 Things 3。

本轮实际打开官方商店及产品网页，查看开发者发布的界面图片，并保存浏览器截图供评审核对。下文区分**截图可见事实、官方文字说明、凑狸采用方法、尚未验证的行为**。宣传截图可能经过排版或使用旧版界面，不能证明当前安装版的全部行为；本轮未登录竞品、下单、外跳后返回或提现，也未测量竞品字号、命中区及无障碍表现。

本目录只保存分析与[证据索引](evidence-index.md)。临时浏览器截图保存在 `/tmp/couli-reference-evidence/`，未将第三方图片或商标打包为凑狸素材。官方来源链接是长期复核入口；临时文件失效时须重新查看官方页面，不能把索引当成截图本身。交互方案不改变 `规划/` 的 MVP 范围、业务规则或平台能力结论。

## 1. 五个参考各解决什么问题

| 参考 | 已看到的界面证据 | 凑狸采用方法 | 不从该证据推断 |
| --- | --- | --- | --- |
| Apple Store | 商品卡、产品分区、订单详情中的商品摘要与进度条 | 商品 / 金额 / 主操作分层；当前状态优先于历史信息 | 完整下单、取消或恢复行为 |
| 返利网 | 首页大输入区域及粘贴按钮；个人页余额与提现入口 | 显式粘贴；搜索与素材解析在同一入口；余额与提现操作相邻 | 自动读取剪贴板、资金到账速度、手续费口径 |
| Perplexity | 官方 Search 页示意图中的问题、回答、来源数量与来源卡 | 解释文字和可核对的数据分工；当前会话保留追问上下文 | 当前手机端布局、国内商品报价准确性、代下单能力 |
| Rakuten | 商店图中的 Confirmed / Pending、活动明细、购物记录及收款方式入口 | 预估与已结算分层，异常入口靠近订单与资金 | 美国确认 / 付款周期适用于国内、跳转等于跟单成功 |
| 一淘 | 返利钱包示意、三步说明、商品券与返利信息、购物车商品行 | 帮新用户理解购买、记录、结算 / 使用的不同阶段 | 支付宝卡包兑换等于凑狸现金提现、同步购物车属于 MVP |

具体流程见 [interaction-patterns.md](interaction-patterns.md)。采用信息组织方法，导航仍沿用凑狸现有信息架构。

## 2. Apple Store：商品与订单有清楚的层级

来源：[Apple 发布的中国区 App Store 页面](https://apps.apple.com/cn/app/apple-store/id375380948)。本次查看 iPhone 截图轮播的前后两组，证据为 `apple-store-01.png`、`apple-store-02.png`。

**截图可见**：产品页中，一件主商品占上方区域，下方配件使用独立卡片，名称与价格跟随商品；另一张订单详情图从上到下排列商品摘要、预计送达、进度条、地址等信息。产品、为你推荐、深入探索在底部导航中分工。没有依据静态图推断点击后的动画或恢复行为。

**凑狸采用**：`ProductDetail` 的商品、价格、预估返利和口径分组，购买操作保持明确主次；`OrderDetail` 先呈现当前状态、相应金额与原因，再给历史过程。具体购买文案和可用状态引用 F-PROD-05、BR-PRICE-21；恢复商品上下文依 BR-ID-10、BR-ID-17。

**边界**：不因参考 Apple 引入购物袋、支付、收藏、最近浏览或个性化设备推荐；本轮没有看到和测试凑狸所需的第三方购买外跳返回链路。

## 3. 返利网：显式粘贴，资金操作有入口

来源：[返利网官方 App Store 页面](https://apps.apple.com/cn/app/id591584458)。查看 iPhone 截图轮播前后两组，证据为 `fanli-app-store-01.png`、`fanli-app-store-02.png`。

**截图可见**：首页示意顶部有用于商品素材的大输入区域，右下方是独立的「粘贴」按钮，下方才是渠道与生活服务入口。个人页示意把可用余额、金额和「提现」放在同一块卡片内；旁边还出现该产品自己的其他资金入口。这证明控件在官方发布的图片中存在，不能证明是否请求剪贴板权限、粘贴失败如何恢复、提现提交后如何显示。

**凑狸采用**：粘贴是用户主动动作，保留素材原文、解析反馈与改为关键词搜索的入口（J2、BR-ID-16、BR-TEXT-14/15）。钱包把可操作金额与预估信息分开，提现进入现有身份 / 账号 / 协议及结果流程（J6、BR-FUND-18、BR-WDR-01/02/31）。

**边界**：宣传图的到账速度和手续费文字只是竞品营销表达，不作为凑狸承诺。还信用卡、生活服务渠道、活动与任务不因此加入 MVP；凑狸提现口径仅引用 BR-WDR 与 BR-TEXT。

## 4. Perplexity：解释之后有可核对的信息

来源：[官方 Search 产品页](https://www.perplexity.ai/hub/products/search)、[2024-11-18 官方购物功能介绍](https://www.perplexity.ai/en-GB/hub/blog/shop-like-a-pro)。有效画面证据为 `perplexity-search-citations.png`，来自 Search 页的来源引用模块。

**截图可见**：示意图上方有用户问题，回答上方标明来源数量，回答旁有引用标记，展开卡片包含来源域名、标题与数量。这是官方网页中展示的产品界面示意；本轮没有把它当作 iPhone 安装版截图。

**官方文字说明**：2024 年购物介绍描述了购物问题后呈现商品卡，并区分特定商品的站内结账与商家跳转。这是有日期的功能发布说明。本轮该页内嵌演示未形成可读商品卡截图，不能声称已观察其完整购物流程或当前移动版商品卡样式。

**凑狸采用**：每轮按照「用户条件 → 短说明 → 商品卡 → 后续问题」组织；金额、平台、取价时间、规则入口由卡片承载，解释文本负责说明条件和限制（BR-AI-04/06、BR-PRICE-16/17）。快捷条件先回显为用户消息，再更新结果；条件不是商品已满足条件的证据（BR-AI-08/24）。

**边界**：卡片价格继续来自现有联盟接口；不引入网页价格抓取、代下单、代支付、历史会话列表、跨会话记忆、语音或文件上传。AI 标识、推广披露与单独同意仍按 BR-AI-10/13、BR-TEXT-16 执行。

## 5. Rakuten：不同资金状态，分别解释

来源：[Rakuten Rewards 的 Google Play 页面](https://play.google.com/store/apps/details?hl=en&id=com.ebates)、[官方 Account FAQ](https://www.rakuten.com/help/category/account-questions-26578301675411)。本轮美国区 App Store 在浏览器中重定向至中国区，改看开发者官方 Google Play 图片；证据为 `rakuten-google-play-01.png`、`rakuten-google-play-02.png`、放大的 `rakuten-google-play-balance.png`。

**截图可见**：账户图把 Confirmed Cash Back 和 Pending 分成两组，旁边有 See Activity；下方可见 Shopping Trips 与收款方式入口。图中也有礼品卡兑换区。这些图片来自 Android 商店页面，其中手机样机外框不用于判断真实运行系统或验证原生组件。

**官方文字说明**：Account FAQ 区分未确认与已确认金额，并说明 App 中的 Shopping Trips 可查看激活记录及报告缺失返利。该证据说明信息和入口的用途，未验证入口的每一步操作。

**凑狸采用**：返利订单、收益和提现各有明确状态文案。预估金额不能使用已入账的成功样式；订单详情靠近当前状态展示原因和帮助，未跟单与已有订单异常分别提供现有入口（J4、J5、BR-ATTR-17、BR-TEXT-01～08）。用户从商品平台回来只恢复上下文，订单事实按接口更新。

**边界**：这是美国返利服务，不是日本乐天商城。不采用其礼品卡、收款方式、确认周期、税务或追踪机制；凑狸保持 BR-FUND-18 的单一余额口径，平台外跳与归因仍以 `规划/09` 实测为准。

## 6. 一淘：把购买、返利记录与资金使用讲清楚

来源：[浙江淘宝网络有限公司发布的一淘 App Store 页面](https://apps.apple.com/cn/app/id451400917)。查看 iPhone 截图轮播前后两组，证据为 `etao-app-store-01.png`、`etao-app-store-02.png`。

**截图可见**：第一组的钱包宣传图内，返利钱包画面与三个编号步骤组合，区分一淘内下单、返利钱包和兑换支付宝卡包；第二张商品页把商品价格、优惠、返利信息及底部动作集中组织。第二组购物车图按商品行展示图片、名称、金额和选择状态。

**凑狸采用**：新用户购买前解释下一步前往的平台、预估返利和状态查看位置；订单页以商品、状态和金额形成稳定行。钱包附近解释预估与可操作余额的区别。具体话术与显示条件引用 BR-ATTR-21、BR-TEXT-01～05、BR-FUND-18，不自行制定新的到账条件。

**边界**：截图的卡包兑换不是凑狸现金提现的证据；没有验证竞品是否需要外跳、回到 App 后如何更新跟单。同步淘宝购物车、比价、降价提醒、签到任务不因此加入 MVP。

## 7. 国内四个关键场景：证据与尚待验证处

| 场景 | 本轮证据实际覆盖 | 凑狸当前设计采用 | 仍待实测 |
| --- | --- | --- | --- |
| 粘贴链接 / 口令 | 返利网官方首页图可见输入区及粘贴按钮 | 显式粘贴、原文保留、处理中和失败恢复；J2、BR-ID-16 | 竞品及凑狸三端的授权提示、实际识别范围和口令异常 |
| 购买外跳 / 返回 | 商品主操作可见；Perplexity 官方旧版说明提及商家跳转；没有国内完整往返录像 | 外跳前说明平台，返回保留商品；不把返回显示为跟单成功；BR-ATTR-21、规划/09 | 三平台真实跳转、未安装、取消授权、回跳与上下文恢复 |
| 订单跟踪 / 异常 | 一淘宣传图有返利记录步骤；Rakuten 图有购物记录入口，FAQ 描述缺失返利处理 | 订单状态、预估金额、未跟单与异常入口分开；J4/J5 | 竞品实际延迟、异常处理全过程；凑狸联盟订单与归因 |
| 余额 / 提现 | 返利网图有余额与提现入口；一淘图是卡包兑换；Rakuten 图区分两种资金状态 | 余额与预估分列；提现进入现有条件检查和结果页；J6、BR-FUND-18、BR-WDR | 竞品提交与失败界面；凑狸真实提现、资金状态及恢复 |

AI 商品卡另由 Perplexity 的来源组织与官方购物说明提供方向：本轮已观察来源界面，商品卡的具体交互采用凑狸已有 BR-AI 设计，**不宣称已测评国内 AI 购物完整旅程**。

## 8. 一致性约束

| 设计对象 | 采用方向 | 项目依据 |
| --- | --- | --- |
| 导航 | 沿用首页、AI 助手、订单、我的；按开放状态执行既有替换 | 规划/01 §4.1、D16 |
| 商品与价格 | 以接口报价为主，返利与口径分层；无券、金额未知等状态分开 | BR-PRICE-03～05、08～11、17、21 |
| 购买按钮 | 明确主操作，加载、防重复点击、恢复与异常反馈 | F-PROD-05、F-LINK-01、BR-ID-10、BR-PRICE-13/14 |
| AI | 短说明、卡片事实、条件可见、异常可恢复 | BR-AI-04～10、13、14、20、23、24 |
| 订单与钱包 | 状态、预计结算信息与操作入口分工，保持单一余额 | BR-FUND-18、BR-TEXT-01～08 |
| 无障碍 | 状态同时用文字 / 图标表达；字号放大可读；关键操作有显式入口 | [颜色规范](../colors/colors.md)、[设计令牌](../tokens/README.md)、[图标规范](../app-icon/README.md) |

完整文案、金额、状态、授权和接口行为仍由 `规划/08_业务规则/` 唯一维护；本目录不建立第二套业务规则。
