# Codex 对抗评审档位由轻度改为中档

- 日期：2026-11-07
- 类型：00 §8 第 ② 类（改变已确认的协作取值；不改业务规则、契约形状与技术栈锁定项）。负责人在对话中明确确认，直接回写。
- 状态：已写回（2026-11-07）。
- 起因：负责人问「当前项目有没有使用 gpt6 astra 模型、默认推理强度来对抗 review opus 5.5 编写的代码」。编排会话答复：模型是 gpt-6-astra，但评审档位按 2026-10-09 的决定是 `low`，不是 Codex 的默认（本机默认 `medium`）；当天几次资金评审每次约 1 分钟，对抗强度偏弱。推荐至少资金单用 `medium`，额度与时长约多几倍。负责人回复「评审强度改成 medium」。
- 依据：规划/11 §1.1「评审」条、§2.4 评审命令示例；代码仓库 `ops/approvals.yaml` 第 27 条（被本条修改其「默认 low」一句）、第 53 条（本条）。

## 1. 决定

1. Codex 对抗评审（代码仓库 `tools/agent/codex-run.sh` 的 review 模式）的 `model_reasoning_effort` 由 `low` 改为 `medium`，所有评审类型（资金、契约、通用、规则测试评审）一样。
2. 不变的部分：模型 gpt-6-astra；Codex 写代码的 impl 模式仍是 `high`；所有风险级的代码评审仍只由实现方之外的一家做（Opus 写的由 Codex 审）；`CODEX_REVIEW_EFFORT` 仍是负责人的开关，只在负责人另有决定时改。

## 2. 代理的说明（不是负责人原话）

- 即日生效的做法：编排会话在各开发线的启动脚本里设 `CODEX_REVIEW_EFFORT=medium`，各线下次拉起即用中档；仓库里 `codex-run.sh` 的默认值、它的单测与 `tools/agent/README.md` 由 ops 的 guard-change 单改成 `medium`，落地后启动脚本里的设置可以保留也可以去掉，结果相同。
- 评审超时不变（硬上限 15 分钟、闲置 720 秒）；中档下单次评审预计几分钟。
- 埋雷抽查（规划/11 §3.3）此前没有落实，已另交 ops 补做（编排裁定 D10-880），中档评审的漏检率届时由它记录。
