文章：《AI 编程能力边界探索：基于 Claude Code 的 Spec Coding 项目实战》，得物技术，2026-03-11，<https://mp.weixin.qq.com/s/1Oi7YhMgcPp9gQAWPndXWA>。一位前端工程师用 10 天做出一个中后台，方法是先写规格再写代码、用「约束 / 示范 / 视觉」三层规范、把文档直接接给 AI、按需求大小选协作方式。文中的提效数字是作者自述，没有对照组。

## 1. 逐项对照

| 文章的方法 | 凑狸现状 | 判断 |
| --- | --- | --- |
| 先写规格再写代码（为什么、要求、怎么做、任务、实施、归档） | `规划/` 00–12、变更记录、ADR、台账、任务书、证据文件一整套；规则测试先红、两家模型互审 | 已在做，比文章重 |
| 约束层（规则文件） | 根与模块 `AGENTS.md`、保护路径、守卫脚本、lint，机器强制 | 已在做，比文章强 |
| 示范层（标准页面的完整样板） | 后端有模块分层说明，没有指定的样板模块；前端还没有工程，也没有样板 | **没做** |
| 视觉层（HTML 设计稿给 AI 直接读） | 高保真稿 382 个画板已出，但在 claude.ai 画布和本机运行目录，未定稿、未入库，任务书里带不上 | **做了一半** |
| 把文档直接接给 AI | 接口契约就在代码仓库，任务书按编号抽规则原文，平台文档有私有镜像 | 已在做（做法不同，效果相同） |
| 后端没好先用模拟数据 | 契约 51 个接口都有示例，但 mock 服务还是待办 | 做了一半 |
| AI 先当产品经理、再当设计师、再写研发文档 | 需求评审、01 的需求与验收编号、高保真稿、各批拍板都做了；缺最后一步「按定稿写出实现者照做的页面规格」 | 差最后一步 |
| 按需求大小选协作方式 | 只按风险分级（RV0–RV2），不按大小；改个间距也要一份台账加整套流程 | **没做** |
| 输入说得清才动手 | 七类才问负责人、待补清单、变更先评估 | 已在做；页面任务缺明确的就绪条件 |
| 踩坑就补规范，修一次全局生效 | 每段会话写教训文件，但放在运行目录、不进任务书；同一个坑重复踩 | **做了一半** |
| 提前锁定环境 | ADR-0001 锁技术栈，锁文件与 `.npmrc` 是保护路径，验证在断网容器里跑 | 已在做，比文章强 |
| 评审前移 | 规则测试先过审再派实现；规划文档有对抗评审 | 已在做 |
| 多代理并行 | 一任务一工作树，在途 2–4 个，路径相交不派 | 已在做 |

## 2. 采纳的五条与预期收益

| 做法 | 解决什么 | 预期收益（待验证） | 怎么验证 |
| --- | --- | --- | --- |
| 示范页：每种页面类型先做一张真实页面，其余照做 | 后台 115 张画板基本是列表、详情、表单、带二次验证的操作、导入五种类型的重复；没有样板时每页都要重新约定写法 | 同类型第二张起，任务书变短、评审只看差异；写法一次定好，不用逐页纠正 | 记录照样板档任务的一次通过率、每任务 Codex 调用次数，和示范页自己比 |
| 定稿设计稿与页面规格进任务书 | 实现者看不到图，只能按文字猜布局与状态 | 少一类返工：「做出来和稿不一样」 | 截图对比的差异、因与稿不符被打回的次数 |
| 页面任务分三档（直改 / 照样板 / 完整） | 小改动走全流程，流程成本高于改动本身 | 样式小改按页面组一批处理；复杂与资金页面照旧 | 直改档从提出到合并的时长 |
| 页面任务的就绪条件（稿、规格、契约示例、示范页四样齐） | 输入不全就派工，实现者自己填空 | 少派半截任务；后端没实现不再卡前端 | 受阻任务里「输入不全」的占比 |
| 教训回流（标类型、进手册、第二次出现就改成脚本） | 教训只写不用，同一个坑再踩 | 重复踩坑降到零；任务书自带该线的手册 | 周报里重复出现的条数 |

不改的：风险级判定、合并条件、资金与归属的全部流程。收益都是预期，不是实测；第一批照样板档任务做完后在周报里对比，没有变省就回头改规则。

## 3. 不照搬的

- OpenSpec 工具：项目已有台账、任务书、证据三件套，再加一套会多出一个来源。
- `.claude/rules/` 目录与独立的模板目录：规则要给两家模型共用，放 `AGENTS.md`；脱离工程的模板会过期，改用主干里带测试的真实页面作示范。
- 用 MCP 直连接口文档平台：契约就在仓库里，Codex 沙箱也没有网络。
- 产品人设提示词：需求与设计阶段已经做完。
- 文章没有写测试与评审；项目经手真钱，这部分不因文章而减。
