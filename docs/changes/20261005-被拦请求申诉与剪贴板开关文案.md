## 1. 申诉对象由「注册请求」推广为「被拦截的请求」

**原写法**（同日 `docs/changes/20261005-游客剪贴板开关与注册拦截申诉.md` §2）：08 BR-ID-36 第 ③ 类申诉对象只收「注册请求」——用手机号注册被 44001 拦下、没有建号的那一次请求。已登录、账号正常的人在提现、换手机号、绑收款账号时被 44001 拦下，弹窗同样写「客服核实后会帮你登记」，但后台没有对象可登记（账户申诉只收 banned、frozen），定为「客服在会话里受理并说明，后台暂不登记」，并列入规划/06「2026-10-05 设计审查待确认」第 22 项 ②。

**改为**：

1. 第 ③ 类改称「被拦截的请求」：凡被风控拦下、返回 44001 的写操作都归这一类。请求类型（取值与含义只在 08 BR-ID-36 细则「被拦截请求申诉」维护）：注册、提现提交、绑定或更换手机号、绑定或更换收款账号。以后新增会返回 44001 的写操作，上线前在 08 加一个类型。
2. 登记：仍统一经企业微信找客服，由客服在后台风控申诉页代为登记；用户侧申诉接口不接受这一类。客服按本人提供的**完整手机号**（规范化后）或**用户 UID** 查出被拦的那次请求，列表显示脱敏手机号、请求类型、拦截请求编号、拦截时间、拦截原因类别，提现类另显示申请金额（后台金额格式）。
3. 处理：
   - 撤销 → 处理人把造成拦截的名单条目移出黑名单（BR-ID-31，写审计），客服告知本人可以重新操作。系统不代为重提：注册不代为建号；被拦的提现当时没有建单，不自动恢复，本人重新提交时按当时的余额与校验处理；换手机号、收款账号也由本人重新提交。
   - 维持 → 拦截照旧，客服告知原因类别（不说命中了什么规则）。
   - 结果都由客服在企业微信会话里告知，不发站内信、不发短信。
4. 账号正常（risk_state=normal）的人也可以有这类申诉；这类申诉不改任何账号的 risk_state，不构成提现阻断，不延后入账。
5. 唯一性：同一次被拦截的请求同时最多 1 条处理中的申诉；注册类另按同一手机号最多 1 条处理中（代理补全的默认，仍待负责人确认）。

**仍没定（规划/06「2026-10-05 设计审查待确认」第 22 项，本次只改 ②）**：① 非黑名单原因的拦截（同设备注册数、落地页同 IP 注册数或其他 block 规则）撤销后怎样放行，定之前只能维持；③ 第三方首次登录被拦下、没有手机号也没有账号的人怎么登记；④ 同号只留一条处理中的注册类申诉（代理补全的默认）；⑤ 字段名、`request_type` 的编码与拦截请求编号的编码（契约线定）。BR-ID-31 列出的联盟备案拦截在授权流程（BR-ID-17）里还没写返回 44001 的位置，本次不单列类型，写明时按第 1 点加一个类型。

**涉及 BR**：BR-ID-36（正文第 ③ 类、入口与代为登记、同一对象的唯一性、结案与通知、影响列；细则状态、默认值、取代，「注册请求申诉」一段改为「被拦截请求申诉」并加请求类型与提现例，删去原「已登录、风控状态正常的人……后台暂不登记」一句）。只作引用：BR-ID-05、BR-ID-06、BR-ID-17、BR-ID-31、BR-ID-32、BR-ID-33、BR-WDR-02、BR-WDR-03、BR-WDR-33、BR-TEXT-10、BR-TEXT-14 `cs.appeal_entry`。

**受影响的页面与接口**：后台风控申诉页【代登记申诉】（稿面 `AdmRiskAppealRegister`、`AdmRiskAppealRegisterNoAccount`）要支持按 UID 查找、显示请求类型与提现金额；提现、注册、换手机号三处 44001 弹窗的【联系客服申诉】不变。04 只改形状：§3.2 `appeals.target_type` 的 `register_request` 改名为 `blocked_request`（还没有落地、没有历史数据，直接改名、不保留旧值），加 `request_type`（仅 blocked_request），user_id 只在注册类为空，唯一键按被拦请求、注册类另按手机号 HMAC；`risk_hits` 被拦请求行另记请求类型与提现申请金额；§6.1 用户侧申诉接口不接受 `blocked_request`；§11.2 `risk.appeal` 写明按完整手机号或 UID 查找。用户侧接口与错误码不变。

**验收**：没有单列用例；后台风控申诉页验收时按 BR-ID-36 细则「被拦截请求申诉」的两个例子核对（注册：按完整号码查到、只显示脱敏号、撤销后可重新注册；提现：账号正常的人按 UID 查到、显示金额、登记后账号状态不变、撤销后重新提交而不是自动恢复，均不发站内信）。

**恢复方式**：BR-ID-36 正文第 ③ 类改回「注册请求申诉」、细则改回「注册请求申诉」一段并恢复「已登录、风控状态正常的人……后台暂不登记」一句（细则「取代」已登记原写法）；04 `blocked_request` 改回 `register_request`、删去 `request_type` 与提现金额；06 第 22 项 ② 改回待负责人确认；01 F-ADM-18、05 B1-27 改回本次之前的半句。
