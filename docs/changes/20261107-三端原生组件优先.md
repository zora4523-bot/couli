# 2026-11-07 三端功能一致、界面优先用各平台原生组件

- 类别：改变已确认的设计做法（03 §10「三端各实现一份、命名一致」与 DS-02 逐屏比对口径），00 §8 第 ② 类；负责人在编排会话中明确确认，按 00 §8 直接回写并注明日期。
- 负责人原话（2026-11-07）：「三端会长得不一样 UI 不需要一样 功能一样就好了 你可能误会了」「为什么 IOS 要自绘底栏 请问 现在IOS 还有人自绘吗 这是最佳实践指南吗？」
- 编排裁定：D10-824（代码仓库各线派工）。

## 1. 现状（编排核实，代码仓库各原生仓主干）

| 端 | 底部标签栏 | 判断 |
| --- | --- | --- |
| iOS | 系统 `TabView` 承载各 Tab 根页面，但用 `.toolbar(.hidden, for: .tabBar)` 隐藏系统标签栏，另画设计系统的 `TabBar` | 自绘 |
| Android | Compose 自绘 `TabBar`（一行按钮），没用 Material 3 `NavigationBar` | 自绘 |
| 鸿蒙 | 系统 `Tabs(barPosition End)`，每项 tabBar 用自定义构建（系统样式只接图片资源，凑狸图标是矢量路径） | 基本原生 |

起因是规划把「三端组件清单一份、命名一致、逐屏对设计稿」理解成了三端界面一致，于是把系统已有的控件也换成了自绘。这不是平台最佳实践：Apple 人机界面指南建议用系统标签栏、只改主题色；Material 3 推荐 `NavigationBar`。自绘会丢掉系统随版本带来的外观与行为（如 iOS 26 的新材质与滚动收起、iPad 自适应侧边栏）、系统自带的读屏与大字适配，以后还要自己跟进。

## 2. 新口径

1. **三端功能一致、界面不求一致。** 同一功能在三端提供相同的信息、操作与业务规则（文案键、金额口径、状态、错误处理照旧一致）；布局与控件外观按各平台规范。
2. **优先用平台原生组件。** iOS 按 Apple 人机界面指南与 SwiftUI / UIKit 系统控件；Android 按 Material 3；鸿蒙按 ArkUI 系统组件。系统已有的控件（标签栏、导航栏、弹窗、底部弹层、开关、单选 / 复选、分段选择、输入框、菜单等）不再自绘。
3. **品牌色经系统主题接入。** 设计令牌（03 §10.1）继续是品牌色、字号层级、间距、圆角的唯一源，各端通过系统主题 / tint / colorScheme / MaterialTheme / ArkUI 主题接入；深色模式照 D35 跟随系统。
4. **业务组件照旧自建。** 系统没有对应物的业务组件（商品卡、价格与返利标签、金额格、钱包主卡等，03 §10.2 表）照旧由设计系统各端实现，组件名三端一致便于对照，外观可按平台细节不同。
5. **iOS 底栏（负责人 2026-11-07「iOS 底栏用系统 TabBar，Liquid Glass 悬浮样式，自绘底栏会自动失去这些能力」）。** 用 SwiftUI `TabView` 的系统标签栏：iOS 26 起自动呈现 Liquid Glass 悬浮样式（内容延伸到标签栏下方、滚动时可收起，`tabBarMinimizeBehavior`，仅 iOS 26+ 调用），iOS 16–25 为系统经典样式；不加 `UIDesignRequiresCompatibility`、不给标签栏设不透明背景或 `UITabBarAppearance` 覆盖、不在标签栏外再叠一层自绘栏；图标用 SF Symbols 或模板渲染的图片资源，选中色用品牌色 tint。
6. **验收口径。** 视觉验收从「三端与设计稿像素一致」改为「功能与信息一致、遵循本平台规范」；截图快照仍做（防回归），基准按各端自身实现出，不跨端比对；设计稿作为信息结构与品牌的参照，不作像素标准。

## 3. 影响与执行

- 03 §10.2、§11 按上文改写；design/README 加一句口径说明。
- 代码仓库：iOS 底栏改系统标签栏（选中仍跟随 Router、点 Tab 经守卫），Android 改 Material 3 `NavigationBar`，鸿蒙保持系统 `Tabs`；三端各自只读摸底「系统有、我们自绘」的组件清单，按影响排序报编排后逐项改；截图基准随改动重出；DS-02 逐屏比对按新口径判定（D10-824）。
- 不涉及金额、订单归属、用户授权与对外承诺。

## 4. 验收与恢复

- 验收：三端底栏为系统控件；摸底清单列出的系统控件改为原生实现；各端快照基准更新并通过；功能冒烟（03 §11 UI 冒烟流程）三端一致通过。
- 恢复：若某个系统控件满足不了业务（如需要系统不提供的交互），在该端保留自建并在清单里写明原因，由编排登记，不回到全面自绘。
