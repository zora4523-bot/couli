## 0. 结论

1. 底座已是开源件（Pigsty 整套、NestJS、Kysely、pg-boss、jose、OpenAPI 工具链、Vitest、React、Refine 等，研究记录 §2），必须自写的是规则层（身份判定、账本、归因、联盟适配、Agent 护栏、JSBridge、设计系统，§3）。
2. 还能再省的是 7 处小改：本文把其中 2 处直接接入代码仓库（§1），其余 5 处与十几处「用库减负」的要点规划成任务或任务书要点（§2、§3），4 处要负责人决定（§4）。
3. 不做的与延后的见 §5；核查发现的遗漏见 §6。

## 5. 不做或延后（维持研究记录 §6 的裁定）

- 不引：Logto / Keycloak / Ory Kratos / Better Auth / SuperTokens / Casdoor；Unleash / Flagsmith / GrowthBook；Novu；LiteLLM / one-api / new-api；Vercel AI SDK / LangGraph.js / Mastra；Langfuse / Phoenix / Braintrust；TigerBeetle / Formance / Blnk / Medici；Atlas / Bytebase / Liquibase / pgroll / pg_partman；Dokploy / Coolify / Kamal。共同原因：独立服务或自建表（违反 ADR-0001 迁移唯一来源）、规则不匹配、无运维团队、单节点放不下。
- 延后到 P1 或首版关闭：产品分析平台（PostHog / Matomo / Superset；真要上只有 Umami 与基线相容）、Stryker（上游 Vitest 5 问题未修）、规则引擎（02 §16.3 P2）、备用域名与 HTTPDNS、prod SLB / WAF / CDN（内测期）。
- 数据库侧 JWT 扩展（pgjwt、pg_session_jwt）不装（2026-10-07 已核查）。
