## 1. 新增读屏与无障碍测试任务（05 QA-12）

**内容**：

1. **标准**：WCAG 2.2 AA，逐项检查下列成功标准（只列条款号与一句话，取值与原文以 W3C 官方文本为准）：
   - 1.3.1 信息与关系：标题、列表、表格、表单分组等结构能被读屏读出来；
   - 1.4.3 / 1.4.11 对比度：文字与非文字元素（图标、输入框边框、焦点框）的对比度达标；
   - 2.1.1 键盘：功能都能用键盘完成（主要针对后台与 H5）；
   - 2.4.3 焦点顺序：焦点顺序与阅读和操作顺序一致；
   - 2.4.7 焦点可见：键盘焦点始终看得见；
   - 2.5.8 目标尺寸：可点区域不小于最低尺寸（App 另按 01 §7.5 的命中区下限）；
   - 4.1.2 名称、角色、值：控件有可读的名称、角色和当前状态；
   - 4.1.3 状态消息：不移动焦点的结果提示也能被读屏播报。
2. **App 三端**：用系统读屏（iOS VoiceOver、Android TalkBack、鸿蒙系统读屏）走 QA-11 同一组页面（7 个关键页与钱包、提现、订单页），另加登录页与分享页。
3. **App 内 H5、站外 H5 与管理后台**：用浏览器读屏，并接自动检测（如 axe）；工具选型由实现任务定，不写成承诺。
4. **逐项检查**：
   - 控件名称：图标按钮有名称；表格行操作读出「动作 + 该行主标识」（如「审核 提现单 W123」），不只读「审核」；
   - 表格：表头与单元格的关系能被读出；
   - 对话框 / 抽屉：打开时焦点进入、焦点圈在其中、Esc 关闭、关闭后焦点回到触发控件；叠层时只暴露最上层；
   - 表单：标签与输入框关联，校验错误被播报并能定位到出错字段；
   - 异步结果与轻提示（toast）被播报；
   - 验证码用单个输入框，读屏读作一个字段，不拆成逐位的多个框。
5. **依据**：以设计稿的适配与无障碍约定为准（设计稿规范不在本仓库，规划只写指针）。
6. **执行端与排期**：IOS / AND / HM / F1（F1 含 H5 与后台），W4–W5，与 QA-11 同一窗口（W5 内测发包前跑一轮）。

**验收**（05 QA-12 验收列）：每项有读屏录屏或自动检测报告；设计稿审查转入的读屏问题逐条关闭；发现的问题在内测前修完，修不完的登记原因与计划。10 新增 AC-S1-157（后台与 H5）、AC-S1-158（App 三端），属条件项，不计入 S1 出门（05 §0 的出门范围没有改）。
