## 1. 负责人决定

2026-10-17：剪贴板商品识别**全按新规格改**。新口径（取值只在 08 BR-ID-16）：

1. **iOS**：用户开启功能后可程序化读取剪贴板；系统「允许粘贴」弹窗照常由系统决定，App 不承诺不弹、不把一次成功当作永久允许。系统拒绝或不可用时降级为 UIPasteControl「粘贴查返利」入口，本轮不再自动尝试。变化计数、内容类型等非内容元数据只用来减少重复尝试，不作授权依据。
2. **鸿蒙**：本应用具备申请 READ_PASTEBOARD 的资格、且用户已授予时自动读取。资格与商用设备授权**09 未验证**（CAP-X-02、06 Q-G11），规划只写「具备资格时」；不够资格、未授权或撤销时用 PasteButton 降级，安全控件的临时授权不持久化。
3. **Android**：开启后回前台自动读取，本机提取候选后直接调 `POST /v1/inputs/parse` 并弹商品卡一次，不再先出提示条等用户点击（原 10 §6.1 G-20 作废）；Android 12+ 的系统 Toast 是通知不是同意。
4. **三端统一**：功能**默认关闭**；首次以专门弹层说明用途（读取剪贴板、在设备上提取链接 / 口令、提交服务查询商品优惠；可随时关闭；系统可能另要求粘贴授权），用户选【开启】才写功能同意版本 + enabled=true；笼统隐私同意不自动开启；现有用户也要完成该用途同意；设置项三端都显示（原「iOS、鸿蒙不显示」作废），设备级、游客可见、不随登录变。

保留不变：敏感页面不识别；不清空、不改写剪贴板；原文不落日志 / 埋点 / 崩溃；只上传提取出的最小候选；本 App 自写内容按 hash 排除；同 hash TTL 去重；服务端不存原文；邀请口令商品优先且用户点击才绑定（BR-INV-04 不随本次改为自动）；`/v1/inputs/parse` 识别不到返回 30132；H5 不得写 enabled=true；配置不能覆盖用户关闭态。

## 2. 与 2026-10-05 决定的差异

| # | 2026-10-05 写法（作废） | 2026-10-17 写法 |
| --- | --- | --- |
| 1 | Android「打开 App 自动识别剪贴板」默认开启；iOS、鸿蒙不显示这一项 | 三端功能默认关闭，设置项三端都显示（设备级、游客可见、不随登录变） |
| 2 | 读取只以隐私政策同意为前提 | 另加功能用途同意：首次专门弹层说明用途，用户点【开启】才记功能同意版本（`config.clipboard.consent_version`，与隐私政策版本分开）；笼统隐私同意不自动开启 |
| 3 | Android 命中后先出提示条、用户点击才上传（G-20）；iOS 只用 detectPatterns 探测、提示条内 UIPasteControl 点击后读取；鸿蒙只有 PasteButton | 三端开启后符合门槛的前台轮次自动读取 1 次、本机提取候选、直接识别并弹商品卡 1 次；iOS 程序化读取 + 系统弹窗照常 + UIPasteControl 降级；鸿蒙「具备资格且已授权」时读取 + PasteButton 降级 |
| 4 | F-CLIP-01 验收「iOS 不出现系统允许粘贴弹窗」 | 「系统弹窗照常；拒绝后有粘贴降级入口且本轮不循环请求」；加「未开启：零自动读取零上传，手动粘贴按 BR-ID-16」 |

细则另补：功能同意版本与隐私政策版本分开记录；ImportTask 门控（requestId / 前台轮次 epoch / 页面实例 / 同意版本，过期任务不上传不弹卡）；系统拒绝的终态与降级入口；撤回同意或关闭时立即取消待执行读取。

## 2.1 Codex 对抗评审（第 1 轮，不通过）后的补充

评审原文：couli-runs `approvals/docs-clipboard-auto-import/codex-review.md`（S0 4 条、S1 5 条、S2 0；D19 检查 PASS）。逐条修法（都是实现方案或口径收紧，不改负责人决定）：

1. 面向用户的文案与验收不把有条件的自动读取写成确定行为：`settings.clipboard_auto.desc` 与 `clipboard.consent.body` 改为「系统支持并允许时自动识别，否则用粘贴入口」；AC-S1-03 的 Given 按端分「自动读取条件满足 / 不满足」两组，② 只在满足组断言自动读取，⑦ 不断言系统是否弹窗、只验收 App 的处理。
2. 本地过滤与去重的取值（长度 10–500、≤20 位纯数字 / 字母、最近 10 次自写、同 hash 24 小时）由 01 F-CLIP-02 移入 BR-ID-16 细则「本地过滤与去重默认值」，01 只留引用；03 §4.6 删去对同意与失效迁移的复述，只留实现结构与指针。
3. 门控分两种任务：自动任务受全部门槛与轮次限制；手动粘贴任务只要求隐私同意、看过用途弹层、有效点击、系统允许、页面有效，不受开关、功能同意版本、轮次与节流限制，自动失败后同轮手动照常。
4. 服务端开关拆成两个键：`features.clipboard.enabled.<platform>` 只管按电商平台的识别过滤、不停读取；新增 `features.clipboard.auto_read.<client>`（ios / android / harmony）按端停用自动读取、手动入口不受影响（形状 04 §10.1，取值 BR-ID-16 细则「服务端开关」，09 CAP-X-02 降级列引用）。
5. BR-INV-04 细则「只出商品提示条」改为「只弹商品卡」；F-CLIP-04 的 AgentChat 一句改为自动识别。
6. iOS 无法区分拒绝与空内容时按不可用保守处理（展示粘贴入口、不记拒绝、不上报 denied）；能确认拒绝时记时刻，节流期沿用 BR-ID-13 细则的时长，节流期内不自动尝试、用户在设置页主动开关不受限；鸿蒙权限申请经权限组件，BR-ID-13 节流直接适用。
7. 任务生命周期：系统弹窗造成的暂时失焦不撤销任务，只有真正退后台、页面销毁、关闭开关、撤回同意才撤销；成功、无候选、去重命中、不可用、取消、过期六种终态都释放，释放只清同 requestId 的任务，轮次「已消费」不回退。
8. `clipboard_auto_import` 不论是否带令牌都记设备级（BR-ID-12 细则、04 §6.1 例外）。
9. 用途说明弹层补好友邀请码用途与「确认后才绑定」，与 06 Q-F1 一致。
