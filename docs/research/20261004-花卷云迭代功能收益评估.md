# 花卷云迭代功能整理与凑狸收益优先级

2026-10-04。结论：先把识别、真实报价、跟单解释、资金核对和分享链路做可靠；新增投入优先考虑搜索洞察、官方选品清单、活动内容中心和后台订单分析。分群触达等有了实际运营数据再做。高收益指改善成交、减少返利争议、降低运营成本的预期价值，目前没有新 App 的收入、流量或人力基线，不能据此承诺收入增长。

## 2. 如何判断收益

优先处理直接影响“查得到、跳得通、跟得上、算得对”的能力，其次利用既有商品池、CMS、埋点与后台减少重复操作。需要新平台、新供应商、新奖励预算或大规模用户数据的能力后置。判断中的高、中、低是相对定性判断，不是 ROI 测算。

| 工作包 | 收益来源与预期 | 追加成本与依赖 | 证据置信度 | 当前处理 |
| --- | --- | --- | --- | --- |
| A 识别与真实报价 | 避免用户输入有效商品却查不到；减少自购与分享金额混淆，直接影响购买信任，优先级高 | 现有 parsing、报价与转链任务内补样本；新格式权限可能增加工作量 | 对问题与已有规则的判断高；新增格式支持度待实测 | MVP 已有链路优先验收；额外格式逐项进入 P1 候选 |
| B 订单解释与后台分析 | 用户知道失效原因，客服能定位归属与处理记录，减少查单往返，优先级高 | 原因、找回与审计已规划；完整标签组合、店铺查询与订单导出增加中等工作量 | 需求判断高；节省时长待基线 | MVP 完成已有部分；查询增强归 F-ADM-25，P1 |
| C 资产快照与对账 | 及时发现余额、待打款与账务差异，保护已产生的收益，优先级高 | 已有账务任务，主要是串起快照、核对和后台查阅 | 规则覆盖高；必须回放及真实月结验证 | 保留 M-内测，不新建一套报表账本 |
| D 搜索洞察与关键词直达 | 找出高频无结果需求，改热词、商品池与直达入口，提高找货效率，预期高 | 直达已有；聚合洞察需新增隐私方案、统计口径与后台，成本中 | 价值推断中；没有搜索样本或改善幅度数据 | 直达保持 MVP；搜索洞察 F-PROD-10 为 P1 优先候选 |
| E 官方选品清单与素材 | 运营一次整理，多人手动选用和分享，缩短内容准备时间，预期中高 | 复用商品池与分享模板；依赖分享归因、价格刷新和素材审核，成本中 | 复用判断高；分享带来的增量成交待验证 | F-SHARE-09，P1 优先候选 |
| F 活动内容中心与日历 | 集中展示有效活动、规则和历史说明，减少找入口及改页面的成本，预期中高 | 复用 CMS / H5；联盟活动购买与分享依赖单独转链验证，成本中 | 内容价值判断中；活动转链能力未证实 | F-H5-08，P1 优先候选；内容与交易依赖分开 |
| G 分享链路可靠性 | 减少打不开、过期素材和无归因链接造成的流失，优先级高 | 已有分享页、域名检测与分享面板，额外工作小 | 已有覆盖高；真机归因待验证 | 按 M-公开完成，不新造通用短链平台 |
| H 分群触达 | 在用户同意范围内召回有需求的人，预期中等 | 依赖人群口径、退订、频控和对照组，持续运营成本中 | 增量效果置信度较低 | F-MSG-06 保持 P1，排在洞察与内容之后 |

这些收益不可相加：同一笔成交可能同时经过搜索、活动与分享。优先级随上线后的漏斗、工单与成本数据调整；“已有规划可复用”不等于当前已经有可调用服务。

### 3.2 P1 增量目标

**搜索洞察 F-PROD-10。** 运营能识别热门需求、无结果与识别失败集中在哪里，用于调整 F-PROD-03 热词和关键词直达、商品池及 Agent 离线评测。依赖 F-OBS-03、F-ADM-20 和可追溯的搜索结果事件。未知项是哪些查询可采集、如何清洗和聚合、匿名基本模式如何排除、最小样本门槛及留存方案。关键词本身也可能含个人信息，聚合不自动等于匿名；不照搬“触发用户列表”，不把搜索词自动用于训练。涉及新采集的部分先完成 BR-ID-11、BR-ID-30、BR-ID-33 与隐私清单对齐。

**官方选品清单与素材 F-SHARE-09。** 运营从已允许的商品源制作主题清单，用户主动选择商品、复制文案、保存图或分享；素材中心复用同一套清单与审核流程。依赖商品池、价格复核、各平台分享能力及 BR-ATTR-10。未知项为多商品分享的承载方式、部分商品失效时的交互、淘宝口令权限和分享者未授权时的处理；后两项继续沿用功能对照 Q-08 / Q-09 的待确认记录。群消息采集、自动发群和自动发圈仍不做。

**活动内容中心 F-H5-08。** 聚合活动说明、时间、状态、素材和结束后的说明归档，复用 F-H5-07，不另建同类页面系统。运营内容展示与联盟活动交易分开：前者依赖 CMS，后者仍受 BR-ATTR-29 和各平台活动转链实测约束；归档目标是查规则，不能保留过期购买或领奖承诺。未知项是有效物料来源与维护责任、各平台活动能力、归档范围。它不自动创建 BR-WATCH-22 大促提醒，也不自动申请日历或推送权限；本轮不新增现金奖励引擎。

**后台订单查询增强 F-ADM-25。** 在现有查询上补齐平台标签组合、原因、店铺、标题与付款时间筛选、按相同条件导出，以及按操作人查看相关审计记录。依赖订单同步、权限、异步导出与 CAP-*-07/08 的真实字段。未知项是字段可得性、缺失标签呈现、导出容量和权限点是否需要细分。保留平台原始含义，不凭运营标签改变归属、分佣或账务状态；不向推广者开放下级或团队订单。

**补充格式 F-PROD-11 和分群触达 F-MSG-06。** 前者根据实际失败输入补最常见的商品格式，活动、淘金币等特殊场景另验，唯品会等跟随平台接入阶段。后者在前面内容与测量基础具备后评估；只用获准的本 App 数据，不能把“在凑狸无订单”称为“在拼多多从未或近期未下单”。新增平台、新供应商、资金奖励、数据用途或用户授权变化仍走 00 §8。

## 4. 实施顺序与收益复盘

1. **先完成 S0/S1/S2 和 M-公开既有主线。** 用 §3.1 消除重复排期、补齐样本和验证关注点；工作状态仍在正式工程的任务台账中记录。
2. **P1 既定主线仍为 S3 降价提醒。** 本轮新增的是运营增强候选，不能作为 S3 新门槛，也不占用其关键人力。需要共享资源时先保 S3；有独立余量才并行。
3. **运营增强候选按收益证据选择一包试点。** 默认先搜索洞察，再官方清单，活动内容中心随后；若真实客服工单显示查单成本更高，订单查询增强可前移。格式扩展按失败样本频次插入；分群推送后置。这里是立项顺序，不是额外承诺的周计划。
4. **每包立项时补规格。** 在 08 明确新增业务规则，在 04 定契约形状，在 09 登记适用平台证据，在 10 补验收，再拆成 05 / 正式工程台账的任务。P1 现在只固定目标、依赖、未知项。

| 观察对象 | 如何判断值不值得继续 | 测量限制 |
| --- | --- | --- |
| 输入识别与搜索 | 按平台和输入类型记录识别成功、无结果与商品卡点击；结合既有成交漏斗 | 成功须能定位具体商品；活动识别单列，不计作商品识别成功；避免把接口报错当无商品 |
| 真实报价与订单解释 | 记录报价差异原因、返利金额争议、每单客服处理耗时 | 用户问题减少需看同类订单与订单量；不能只看工单总数下降 |
| 搜索洞察 | 运营修复过的无结果需求是否改善，是否减少用户改词与重复搜索 | 新事件口径、采集与留存先获准；没有原始词也可先做失败类别统计 |
| 清单和活动 | 内容制作耗时、有效商品点击、可归因成交，以及素材失效比例 | 同一订单去重；价格刷新与联盟同步延迟分别观测；未能归因的点击不补造订单 |
| 后台分析 | 同类查单任务的耗时、重复导出与二次问询是否减少 | 权限不足与数据缺失单列；导出量增加不等于收益增加 |
| 分群触达 | 同期对照组的增量有效订单、退订和投诉、触达成本 | 发送量和点击率只作过程指标；先有基线再定扩大或停止阈值 |

以上是观测建议，不改变 01 §8 已有指标。基线、样本量和阈值在试点前定；没有实验时只报告相关变化。平台收益沿用现有结算与账务口径，再观察实际新增运营成本，不把联盟总佣金或预估返利等同平台利润。
