## 2. 写回的内容

### 2.1 三个价格字段怎么取（BR-PRICE-01、BR-PRICE-02）

**问题**：BR-PRICE-01 要求「券后价 = 券前价 − 券」恒成立，界面上把 `price_fen` 叫「券前价」、`coupon_fen` 叫「券」（BR-PRICE-04、05）。如果只把 `final_price_fen` 换成接口到手价，恒等式就不成立；如果把百亿补贴等并进 `coupon_fen`，副行「券 ¥y」就会把立减写成券，「有券」筛选、券失效判断（BR-PRICE-14）、领券按钮（BR-TEXT-12）也都会被立减带偏。

**做法**（规则只在 BR-PRICE-02 细则「淘宝优惠明细的分类」，这里只写思路）：不加字段。以接口到手价为基准加回会员专享项得到券后价，券单列，券前价由券后价加券得到（核对通过时它就是折扣价扣除平台立减），所以界面上「券前价 / 券 / 券后价」仍名实相符。明细与到手价对不上、金额或券 ID 缺失、明细里有已过期的项等情况，一律按价格异常不出价，不用部分明细拼价格。淘宝的券不再另选最大一张，接口给出的券全部计入。券变了而券后价没变时也换新报价快照（细则写明）。

**会员项怎么识别**：实测没有能判断「会员专享」的结构化字段，只能按优惠名称归类；名称清单做成服务端配置，默认值取自 2026-10-06 实测出现过的名称（清单与判定顺序只在 BR-PRICE-02）。

**未识别名称（代理默认，待负责人确认）**：负责人的 B 只说加回会员项、其他照单全收，没有说清单外的新名称怎么办。做成开关 `price.taobao.unknown_promo`，三个取值：加回（不计入）、计入（B 的字面）、该商品不出价。代理按「不扩大对用户的承诺、不改变返利口径」把默认设为不出价，并记告警由运营补清单：默认计入可能把只有部分用户才有的优惠算成人人可得；默认加回会抬高显示价，也会抬高预估返利（第 3 轮评审指出）；不出价两头都不扩大，代价是这类商品暂时不显示。2026-10-06 实测样本的名称都在清单里。负责人改默认只改配置。

### 2.2 不计入什么（BR-PRICE-03）与口径说明文案

- 正文改为：不含运费；不含会员专享优惠（88VIP、京东 PLUS、店铺会员价，含淘宝明细里的会员项）；不含联盟接口没有计入的下单页优惠（淘金币、跨店满减、平台红包、第三方淘礼金等）。淘宝明细里全员可享的券与平台立减计入。京东、拼多多不变，实测后另定。
- 原文把「平台红包和补贴满减」整体列为不计入，与 B 冲突，已改；旧写法按 08 README §0.2 记在 BR-PRICE-03 细则「取代」里。
- `price_basis` 与 `price_basis.general`（BR-TEXT-14 表 C）都去掉「跨店满减」四字，其余不变。理由：淘宝明细里的「满元减」可能就是跨店满减，计入之后还写「不含跨店满减」会说错；只点名会员价，其余用「等」带过，不新增对用户的说法。设计预览 `design/brand/preview.js` 的同一句一并改。

### 2.3 术语（BR-PRICE-05）

保持「券后价」，不改叫「到手价」，理由写在 BR-PRICE-05 细则末条：

1. 立减已经放进券前价，「券后 = 券前 − 券」字面上仍然成立；
2. `final_price_fen` 仍不含运费、会员价和接口没算的下单页优惠，叫「到手价」会让用户以为就是实付，属于扩大承诺；
3. 不改名就不用改界面标签、排序文案「券后价从低到高」、价格走势（D30）、分享海报、禁用词和三端字典，影响最小。

### 2.4 新增配置与日志

- 配置：会员专享、券、平台立减三份名称清单；开关 `price.taobao.unknown_promo`（未识别项怎么计价，默认不出价，待负责人确认）；开关 `price.taobao.basis`（默认按明细；`coupon_only` 是只扣券的降级口径，与旧的「选最大一张券」不完全相同，切换会改变对外价格口径，须负责人同意）。键名与默认值只在 BR-PRICE-02。
- 日志 / 告警：`PRICE_PROMO_UNKNOWN`（新）；`PRICE_CALC_DIFF`（已有，淘宝改为按明细核对）。

## 4. 对报价、返利与其他口径的影响

- **返利金额口径不变**：入账、补差、扣回都按联盟订单佣金（BR-CALC-02），与显示价无关。订单归属不变。
- **报价会变**：BR-CALC-20 用 `final_price_fen × 佣金率` 估算 N_quote。淘宝有平台立减的商品，`final_price_fen` 变低，「预估返」随之变低（例：折扣价 39.9 元、百亿补贴 10 元、券 5 元，报价基数由 34.9 元变为 24.9 元）。新报价更接近联盟按实付计佣的结果，是收紧而不是放大承诺。用户用了会员价等未计入的优惠时，实付更低，实际返利可能低于报价，这一点与改前相同，由 `rebate_estimate` 口径说明覆盖。
- **预估返后价**（BR-PRICE-09）随 `final_price_fen` 变低。
- **点击复核**（BR-PRICE-13）：秒杀、限时类立减会到期，点击时复核出「价格变动」的次数可能增多；机制不变。
- **价格走势与价格变更历史**（D30、BR-WATCH-19）：凑狸还没开始记录，没有历史数据需要迁移；淘宝的记录从上线起就是新口径。
- **降价提醒**（P1）：立减到期会让券后价短时上涨再回落，留到 P1 提醒开工时定是否过滤（BR-WATCH-03 已注明）。
- **价格区间筛选**：接口区间按折扣价过滤，按券后价筛选的做法只按 BR-PRICE-15（上游只透传下限）。
- **数据不一致的商品不出价**：明细与到手价对不上时按价格异常处理（检索不出卡），2026-10-06 实测样本里没有出现这种情况。
